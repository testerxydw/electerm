## 1. 本版要解决的问题（一句话）

V2 把"两端实现"统一了，但**没有把"信号"统一**。当前同一件事（一个 IPv4 地址、一段时长、一个 `error` 词）
在多个预设组里各有一份规则、各染各的颜色，谁赢由"跨度长短 + 让位 lookahead"临时决定。
用户可感知的后果就是：**同一个 IP 在不同行里是两种颜色**。

本版把唯一性判据从"一条正则只出现一次"提升到**语义级全局唯一**：

> 一个信号家族（family）→ 一种颜色 → 一个归属组 → 一条裁决优先级。
> 任何别的组不得再声明同一信号，也不得把该信号吞进自己的更大模式里。

### 2.1 用户点名的 IPv4 —— 确实有两种颜色

| 行内容 | 实际染色 | 出处 |
|---|---|---|
| `connect to host 10.1.2.3 port 22` | `10.1.2.3` → `#FF9ECB` | 通用 · 地址与路径 `ipv4` |
| `inet 10.1.2.3/24 scope global` | `10.1.2.3/24` → `#FF9ECB` | 同上 |
| `tcp ESTAB ... 10.1.2.3:443` | `10.1.2.3:443` → `magenta` | HTTP & web logs `host:port` |
| `upstream=10.1.2.3:8080` | `10.1.2.3:8080` → `magenta` | 同上 |
| `0.0.0.0:8080->80/tcp 10.1.2.3:53` | 整段 → `magenta` | Docker `listen` + HTTP `host:port` |
| `127.0.0.1:631` | → `magenta` | HTTP `host:port` |

同一个地址的颜色取决于**后面跟的是 `/24` 还是 `:443`**，因为 `ipv4` 规则里写了一句让位护栏 `(?!:\d)`，
把 `ip:port` 整个让给了另一组的 magenta。这不是调色板问题，是**归属不唯一**。

IPv4 形状目前存在于 **3 个配置**：`通用 · 地址与路径`(ipv4 本体)、`HTTP & web logs`(内嵌 `\d{1,3}(\.\d{1,3}){3}` 分支)、
`Docker & Kubernetes`(内嵌 `0\.0\.0\.0` 分支)。

## 3. 契约：信号全局唯一（KU）

### KU-1 一色（family → 单一颜色）

每条规则必须声明 `family: '<家族 id>'`。**同一 family 的全部规则，颜色必须一致**。

例外：`分级族`（graded family）——家族的语义本身就是按级别分色的，此时家族 id 必须写到级别粒度，
使每个色档成为**独立家族**，从而仍然满足一色：

```
http-status.5xx / http-status.4xx / http-status.3xx / http-status.1xx2xx   （4 个家族，各 1 色）
syslog-sev.crit / syslog-sev.warn / syslog-sev.info                        （3 个家族，各 1 色）
bracket-level.err / bracket-level.warn / bracket-level.info                （nginx [error] 形制，3 个家族）
```

判定：**只有当"级别"是该信号自身的语义维度时才允许分级**。`word-error` 不是分级族——它就是"报错词"这一个信号，
11 份词表全是同一族同一色，属于纯重复。

### KU-2 一归属（family → 单一归属组）

同一 family 的所有规则必须落在**同一个预设组**里。业务组不得声明通用家族。

归属裁决顺序（就近原则 → 专属原则）：

1. 通用家族（时间/数值/地址/路径/级别）→ 一律归 `通用 · *` 三档，业务组**只允许引用、不允许重述**。
2. 领域专属家族（`interface-name`、`unit-name`、`sql-keyword`、`git-ref`…）→ 归该领域组。
3. 一个家族只能有一个归属组，归属组写进 `FAMILY_HOME` 常量表，供 CI 断言。

### KU-3 不吞并（家族边界）

**禁止**在别的家族的规则里内联该家族的形状片段。这条是"IP 只有一种颜色"的真正保证，
比 KU-1/KU-2 更强：即使 `host:port` 规则换了归属，只要它内部还写着 `\d{1,3}(\.\d{1,3}){3}`，
它就会把 IPv4 一起吞掉、改色。

改法（本版核心动作）：**一条染色 span 只承载一个家族**。把复合模式拆成相邻的、各归各族的段：

```js
// 拆前（HTTP 组，magenta 吞掉 IP）
'\\b(?:[a-z][a-z0-9.-]*|\\d{1,3}(?:\\.\\d{1,3}){3}):\\d{2,5}(?:->\\d{1,5}/(?:tcp|udp))?\\b'
// 拆后：端口成为独立家族，IP 段交回 ipv4
{ keyword: '\\b\\d{1,3}(?:\\.\\d{1,3}){3}\\b(?:/\\d{1,2})?', family: 'ipv4', rank: 10 }  // 归通用地址档，删 (?!:\d)
{ keyword: ':\\d{2,5}\\b(?:->\\d{1,5}/(?:tcp|udp))?',      family: 'port', rank: 40 }   // 归通用地址档，单一色
```

扫描器按"最左起点 + rank"裁决：`ipv4` 先吃掉 `10.1.2.3`，游标前进到 `:`，`port` 再吃 `:443`。
**不需要变长后视，也不需要任何让位 lookahead**——两段相邻、各色各色、各有归属。

原型实测（`/tmp/kw-audit2/split3.mjs`，7~9 条玩具族 + rank 裁决，验证机制而非最终表）：

```
tcp ESTAB 10.1.2.3⟨ipv4⟩:443⟨port⟩ 93.184.216.34⟨ipv4⟩:80⟨port⟩
inet 10.1.2.3/24⟨ipv4⟩ dev eth0
upstream=10.1.2.3⟨ipv4⟩:8080⟨port⟩ 0.0.0.0⟨ipv4⟩:8080->80/tcp⟨port⟩
docker: 5m⟨duration⟩ 12m30s⟨duration⟩ 45%⟨percent⟩ 233G⟨size⟩ 4096 bytes⟨size⟩ 5MB⟨size⟩ 0x1f⟨hex⟩
host registry.example.com⟨host⟩:5000⟨port⟩      elapsed 1.2s⟨duration⟩ latency 300ms⟨duration⟩
```

同一 IPv4 在 4 种上下文里颜色恒定，问题在此机制下自动消失。原型同时暴露 **4 条必须一起满足的约束**
（缺一条即退化成抢色，实施时逐条验证）：

| # | 约束 | 不满足的后果（原型复现） |
|---|---|---|
| a | `ipv4` 本体必须含 CIDR 段 `(/\d{1,2})?` | `10.1.2.3/24` 的前缀 `24` 漏给 `number` |
| b | `duration` 必须含**复合** AGE 形式 `\b\d+[dhms](\d+[dhms])*\b` 与 `\(\d+(\.\d+)? ?(sec\|ms\|min)\)` | `12m30s` 被拆成 `12`/`m`/`30`/`s` 裸字符，`(0.01 sec)` 逃逸 |
| c | `size` 单位表**去掉 `i` 标志**，只认 `B`/`iB`/`bytes` 或**大写**单字母 | 带 `i` 时 `5m` 同时是"5 分钟"与"5MB"（§2.4 实测）；完全去掉裸单字母则 `233G`（`df -h`）漏染 |
| d | `percent` 从 `number` 拆出并 rank 高于 `number` | `45%` 双色竞争（§2.4 实测） |

同理必须拆/让位的吞并点：

| 吞并方 | 被吞信号 | 处置 |
|---|---|---|
| Docker `image-ref` 的 `[a-z0-9-]+(\.[a-z0-9-]+)+(/\S+)?` | `ipv4`（`10.1.2.3/24`） | 主机段首字符限定为字母：`[a-z][a-z0-9-]*(\.[a-z0-9-]+)+` |
| AppLog `package-name` 的 `([A-Za-z_]\w*\.){2,}\w+` | `ipv6-mac`（`aabb.ccdd.eeff`）、`host`（`registry.example.com`） | 排除全十六进制段与含 `.` 的域名结尾：加 `(?!.*\.[a-z]{2,6}\b)` 与"段不能全为 hex 且长度 4"约束 |
| 通用 `size` 的 `[KMGTPE]` + `i` 标志 | `duration`（`5m`、`3s`、`12m`） | 体积单位表**去掉 `i` 语义**：只认带 `B` 的形式（`5MB`/`5MiB`/`4096 bytes`）或大写单位；裸 `5m/3s/1h` 唯一属于 `duration` |
| 通用 `number` 的 `\d+(\.\d+)?%?` | `percent`（`45%`） | `%` 后缀从 number 分支移除，`percent` 独立成族（归通用时间数值档，单一颜色） |
| 通用 `ts` 的 `(?!\.\d)` 等 5 处让位 lookahead | —— | 批次 3 用家族优先级裁决取代，逐条删除（见 §5） |

### KU-4 一词一族（词表家族）

任意一个英文字面词（含多词短语）**只能整词命中一条规则**。跨组重叠的词必须：

- 同色 → **删除副本**，只保留归属组那一份（归属组吸收该词）。
- 异色 → **人工裁决一个颜色**，另一处的副本删除。本批唯一实例：`listening` 裁决为 **yellow**
  （它描述的是"正在监听"的过渡态，不是成功终态；Syslog 绿档里的 `listening` 删除）。

裁决原则（写进代码注释，供后续同类冲突复用）：**终态 > 过渡态**；
同一词在两个组里语义不同 → 归更通用的那一档，业务组若确需另一种语义，必须换一个词形
（如 Netmorking 的 `down` 保留 red，Syslog 不能再用 `down` 表示别的含义）。

### KU-5 裁决改为家族优先级（取代长短裁决）

现行 `arbitrateAt` 是"同起点取最短、等长按原序"。这是**没有家族概念时的权宜**，
它把"谁赢"交给跨度长度，于是产生两个后果：① 必须靠 lookahead 让位；② 短的错误模式会切碎长的正确模式。

本版改为：

```
1. 最左起点优先（combined 大正则天然给出）
2. 同起点 → family rank 小者胜（FAMILY_RANK 显式表，非隐式数组顺序）
3. rank 相同 → 跨度长者胜（同族内合并优先，不再跨族抢色）
4. 仍相同 → 原序（保证确定性）
```

`FAMILY_RANK` 是**发布契约的一部分**，不是实现细节：改优先级必须改表并被 spec 锁定。
初始 rank 分层（数字小者优先）：

| 层 | rank | 家族 |
|---|---|---|
| 0 边界 | 0 | `conflict-marker`、`diff-hunk`、`redis-type` |
| 10 精确地址 | 10 | `ipv4`、`ipv6-mac`、`url`、`uuid`、`fingerprint`、`pci-address` |
| 20 精确路径 | 20 | `file-line`、`src-file`、`abs-path` |
| 30 领域标识 | 30 | `interface-name`、`unit-name`、`device-name`、`resource-ref`、`pod-name`、`image-ref`、`git-ref`、`commit-sha`、`sql-keyword`、`quoted-ident` |
| 40 时间数值 | 40 | `timestamp`、`duration`、`size`、`percent`、`hex-literal`、`cli-flag`、`port` |
| 50 状态词 | 50 | `word-error/warn/info/debug/ok`、分级族各档 |
| 60 兜底形状 | 60 | `number`、`package-name`、`host` |

要点：`number`/`package-name` 这类"宽口径形状"垫底，就再也不会把 `aabb.ccdd.eeff` 或 `registry.example.com:5000`
抢走——不是因为它们短，而是因为它们 rank 低。

### KU-6 一色一语义（色板收紧，回答"颜色是不是太多了"）

**实测（`npm` 复跑口径：全量 14 组 100 条规则展开后按 `color` 去重）**：颜色 **17 种**，不是 24 种
——7 个 ANSI 语义名 + 10 个真彩色。问题不在**数量**，在**一名多义**：ANSI 语义名被结构档大量占用。

| 颜色 | 承载规则 | 承载家族 | 其中结构档家族 |
|---|---|---|---|
| magenta | 19 | 18 | 12（pid / pci-address / host-port / user-agent / trace-id / pod-name / restart-count / image-ref / port-map / commit-sha / fingerprint / uuid …） |
| blue | 17 | 17 | 15（interface-name / unit-name / daemon-tag / device-name / http-method / package-name / thread-name / stack-frame / resource-ref / git-ref / auth-daemon / username / sql-keyword / quoted-ident / diff-header） |
| cyan | 10 | 10 | 4（kernel-version / percent / diff-hunk / tls-word） |
| red | 17 | 8 | 0（全是错误语义，正确） |
| yellow | 13 | 6 | 0（正确） |
| green | 11 | 3 | 0（正确） |
| 其余 11 个真彩色 | 各 1 族 | —— | 唯一一色（正确） |

也就是说：**结构档里 46 个家族有 35 个（76%）挤在 blue/magenta/cyan 三个"语义名"上**——
`magenta` 同时表示"空值/布尔"和"端口/镜像/UUID"，`blue` 同时表示"调试"和"一切标识符"。
用户看到的"颜色乱"就来自这里，而不是来自 17 这个数。

规则（与 KU-1 的关系：KU-1 管"一族不拆成多色"，KU-6 管"一色不混多种语义"）：

1. **七个 ANSI 名只属于 signal 档**：`red`=错、`yellow`=警、`green`=成、`cyan`=信息、`blue`=调试、
   `magenta`=空值/杂项、`white`=预留。signal 家族跨主题走主题映射，观感随主题保持一致。
   （分级族 `http-status.*`/`syslog-sev.*`/`bracket-level.*` 的每一档本身就是语义级别，天然落在这六个名内。）
2. **结构档一律真彩色**，不得占用任何 ANSI 名。这条把 35 个越界家族迁出，颜色数会上升，
   但每一色从此只表示一件事。
3. **色的语义粒度 = 色组（color group），不是家族**。家族管**裁决**（rank、谁吞谁），色组管**观感**（这是什么类别的东西）。
   一个色组可以覆盖同层内的多个近邻家族（它们视觉上本就该同类），但**一个色组只允许一个颜色**，
   且**一个颜色不得跨两个色组**。目标色组表（16 组，结构组 10）：

   | 色组 | 归属家族（举例） | 色 |
   |---|---|---|
   | 错 / 警 / 成 / 信 / 调 / 空（六个独立色组，一组一名） | word-* 与三套分级族、signal-name、conflict-marker、traceback-head | ANSI red / yellow / green / cyan / blue / magenta |
   | 时间 | timestamp | `#56D4FF`（现有） |
   | 时长 | duration | `#2DD4BF`（现有） |
   | 体积 | size | `#A5D6FF`（现有） |
   | 数值 | number、percent | `#79C0FF`（现有，percent 并进来：`45%` 与 `42` 同类） |
   | 十六进制 | hex-literal | `#D2A8FF`（现有） |
   | 命令行选项 | cli-flag | `#E3B341`（现有） |
   | 地址 | ipv4 / ipv6-mac / url | `#FF9ECB` / `#FF7BAC` / `#F78C6C`（现有） |
   | 端口 | host-port / port-map / port-word / restart-count | 新真彩色（粉→紫带内的空档） |
   | 路径与位置 | path / file-line / stack-frame / src-file | `#9CDCFE` / `#7EE787`（现有二色） |
   | 标识符 | interface-name / unit-name / daemon-tag / device-name / pid / thread-name / auth-daemon / username / kernel-version / tls-word / http-method / sql-keyword / quoted-ident / field-name | 新真彩色 1~2 色（"这是个名词"） |
   | 制品引用 | image-ref / pod-name / resource-ref / git-ref / commit-sha / uuid / fingerprint / trace-id / user-agent / package-name | 新真彩色 1~2 色（"这是个可复制的引用"） |
   | diff / 冲突边界 | diff-header / diff-hunk / diff-index | 新真彩色 1 色（marker 层，与语义名脱钩） |

4. **色位数由可辨性决定，不由家族数决定**。新增的每个 hex 必须过两道机检：
   ① 与已有色在深色底上的 CIE ΔE(1976) ≥ 25；② 不落在 ANSI 六名的观感邻域内（避免"像红又不是红"）。
   达不到就**并组**，不许硬造一个近似色——近似色正是"一个颜色两种语义"的另一种形态。
5. **批次 A 已顺带修掉的一处 KU-1 违规**：`duration` 族原有 3 条规则 2 种色
   （通用档 `#2DD4BF`、Docker AGE `cyan`、Database `(0.01 sec)` `cyan`）——
   后两条的 `cyan` 同时又是 `word-info` 的语义色。现已全族统一 `#2DD4BF`。

> KU-6 之后，颜色数预计从 17 升到 20~22，**但"一名多义"降到 0**：每个颜色恰好对应一个色组，
> 每个色组恰好一个颜色。这比"颜色少"更值钱——用户凭颜色就能反推类别。

## 7. 验收标准（全部可机检）

1. **一色**：`FAMILY_HOME` 中每个 family 的 color 集合大小 = 1。
2. **一归属**：每个 family 的 group 集合大小 = 1。
3. **不吞并**：`ipv4` 家族样本矩阵在全量配置下 100% 染成 `ipv4` 色；`duration` 样本不被 `size` 抢；
   `percent` 样本不被 `number` 抢。
4. **一词一族**：整词探测 402 个候选词，跨配置重复 = 0、异色 = 0。
5. **护栏归零**：§5 表中 1/2/5 三处 lookahead 在批次 C/D 后删除，`highlight-equivalence.spec.js`
   的"参考引擎"随之升级为家族裁决 oracle（原参考实现是取短口径，批次 A 后即失效，需替换为 §3 KU-5 口径）。
   —— **批次 A 已完成替换**：参考实现的排序键改为「起点 → rank → 跨度降序」，与 `selectByRank` 同口径。
6. **数量**：生效规则 ≤ 60，structure ≤ 28，signal ≤ 32。
7. **性能**：全量配置的 `collectMatches` 在 4096 字符行上单次 < 8ms（现有 LRU 编译缓存不失效）。
8. **两端一致**：终端与网格对同一字符串输出相同 span（已同源，本批次不得再分叉）。
9. **一色一语义（KU-6）**：结构档占用 ANSI 语义名的家族数 = 0；每个颜色恰好属于一个色组

## 8. 风险与取舍

| 风险 | 说明 | 处置 |
|---|---|---|
| 已固化用例翻色 | `highlight-equivalence.spec.js`、`keyword-presets.spec.js`、`keyword-groups.spec.js`(152/105 硬编码) 会大批断言失效 | 这些 oracle 的**前提**（取短裁决 + 组内自治词表）正是本版要废除的。逐条按 §7.3 判定新色是否更正确，再重定基线；禁止为过测试回滚家族化 |

## 10. 落地顺序建议（一次一句话）

A 建机制（family + rank 裁决，不改表）✅ → B 治词表（KU-4）→ C 治形状（KU-3，IP 在这一批解决）
→ D 收数量（≤60）→ E 收颜色（KU-6，一色一语义）→ F 实机与面板可见化。
每批独立提交、独立跑 `npm run test-unit-ci`；C 与 D 之间不设依赖，可并行但不得合并成一个提交，
否则"删了一条规则导致另一条抢色"无法归因。
E 排在 D 之后：先删掉不会再出现的形状，再给留下的家族定色，避免给一条批次 D 就要删除的规则配新色。
