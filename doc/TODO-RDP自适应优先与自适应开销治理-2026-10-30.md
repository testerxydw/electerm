## 5. 风险提醒（详情见分析 §6）

1. **resize 风暴**：每次成功改分辨率 = 重建 surface/framebuffer + 整屏重绘 + 服务端重编码（wasm strings 已证实）→ 批次 C 的防抖/迟滞/次数闸是**前置条件**，不是优化项。
2. **内存 ∝ 面积**：4K 单帧缓冲 31.6 MB（10.5×），实际驻留按 2~3× 估 → cap 必须显式（D1）。
3. **`canvasResizedCallback` 参数语义未知**：该 API 全仓库 0 引用，无法从现有代码推断 → 真机打印确认后才能接线（R5-2 的第一件事）。
4. **基线漂移**：本轮分析期间工作树被并行会话改写（`terminal-size.js`、`db-view.jsx`、`colWidthRevision` 等已不在当前 HEAD）。**开工前需重新 `git pull` 并对齐本文引用的文件与行号**。

## 6. 批次 A/B 实施记录（2026-10-30）

决策层抽到一个纯函数模块：`src/client/common/remote-adapt.js`（`MIN/MAX_DESKTOP`、`clampDesktopSize`、`clampManualSize`、`resolveInitialSize`、`shouldReLayout`、`resolveScaleViewport`、`RESIZE_MERGE_MS`、`VIEWPORT_EPSILON`），配套 `src/test/unit-ci/remote-adapt.spec.js`（15 条：纯函数 + 组件接线字符串契约）。

与计划不同的 5 处（都是实施时才发现的真问题，不是缩工）：

1. **R2 必须额外修一个时序 bug**：React 先跑子组件的 `componentDidMount`，`SessionShell` 的实测回调在父组件那一轮才发生 —— 旧写法下 `this.viewSize` 永远是 `null`，首连尺寸会退化成固定的 1024x768，"跟随窗口"名存实亡。现在把 `remoteInit` 挂到微任务（同一提交阶段跑完之后）发起。
2. **V2 ③ 的落地形式**：计划写的是"`scrollTo` 定时器只在选屏变化时挂"，但缩放比例变了也必须重滚（滚动量 = `screen.x * scale`），否则选屏会错位。改为按 `选屏@缩放比例` 作键：两者都没变就不重挂定时器。效果一致（稳态 0 次定时器 churn），但条件不同。
3. **R4 附带一个误报门控**：`handleReInit` 改成原地重连后，旧 `session.run()` 的迟到 reject 不再被组件卸载抹掉，会给用户弹一个"连不上"的错误窗。已在 `.catch` 里加 `this._unmounting || this.session !== session` 提前返回（与 `onSessionEnd` 既有守卫同一口径）。
4. **C1 只有一处是真 bug**：`/vnc/:pid` 的 `term.start(query)` 确实把整个对象当成了 `width`，已改为 `(width, height)`；`/spice/:pid` 的 `term.start(query, ws)` 与 `session-spice.js` 的签名本来就是匹配的，**不能改**，只加了注释防止后人"顺手改坏"。`session-vnc.js` 的 `this.width/height` 保留但注死口径：仅供诊断，VNC 帧缓冲尺寸由 server 端决定。
5. **R6 比预期小得多**：本文最初说 `clipViewport`、`qualityLevel`、`compressionLevel`、`domain` 都裸 key，那是在 npm 语言包里查的；本仓库的补词通道是 `src/app/common/locales-extra.js`（运行时合并，上面几个 key 早在里面）。实际只缺一个：新引入的 `resolutionAuto`（en `Auto (fit window)` / zh_cn `自动（跟随窗口）`），已按成对补齐。`patch-locales.js` 本轮未动。

验收方式与计划的差异：§4 写的 `self-test/vnc-resize-throttle-demo.js`（真实例 RO 回调计数）**本轮未做** —— 环境里没有可连的 VNC/RDP 服务（`ss -ltn` 无 5900/3389 监听），写一个跑不起来的脚本只会变成债。改用 `remote-adapt.spec.js` 里的拖窗手势重放（60fps、34 帧事件序列）断言"每手势 1 次而非每帧 1 次"，待有真机时再补运行时实测。
