### 2.2 引擎与连接

- 支持 5 种：MySQL(3306)、Redis(6379)、PostgreSQL(5432)、TiDB(4000)、OceanBase(2881)。
- TiDB / OceanBase 复用 MySQL 协议适配器（`DB_ADAPTER`，`index.js:13-19`）。
- 驱动全部在函数体内懒加载（`require('mysql2/promise')` / `ioredis` / `pg`），主包不背驱动体积。
- 可选 SSH 隧道：运行时通过 `sshTunnelBookmarkId` 查 ssh 书签，不在数据库书签里复制凭据。
- 数据库书签复用 bookmarks 表，`type = 'database'`，扩展字段：`dbType/dbHost/dbPort/dbUser/dbPassword/dbName/sshTunnelBookmarkId/readOnly`。

### 2.3 后端能力

**生命周期（`index.js`）**

- `instances[tabId]` 持有 `{ dbType, conn, tunnel, readOnly }`；`openDbTab` 先关闭同 id 旧实例，避免重连泄漏。
- 打开过程中用 `pending` 占位 + `aborted` 标记处理「慢连接时 tab 被秒关」竞态：`closeDbTab` 置中止位，`openDbTab` 在 build/acquire/metadata 三步后各自检查并释放已建资源（`:139-202`）。
- `dbClientOp` 在实例不存在或仍在 pending 时统一抛 `database tab not open`（`:204-224`）。
- 只读以主进程实例为权威：`safeArgs = { ...args, readOnly: inst.readOnly }`，渲染层传 `readOnly:false` 无法绕过（`:216-221`）；页内切换走 `setDbReadOnly`（`:226-235`）。
- 超时：默认 15s，`getPageData` 60s，`executeSql` 120s，元数据/建连 15s，错误消息带来源标签（`:66-81`）。
- 关闭：`closeDbTab` 按引用计数释放；`closeAllDbTabs` 逐个关闭后无参全清兜底（`:237-270`）。
- 6 个 IPC handler：`testDbConnection / openDbTab / dbClientOp / setDbReadOnly / closeDbTab / closeAllDbTabs`（`ipc.js:286-291`）。

**MySQL（`mysql.js`）**

- 连接：`pools: Map<sig, pool>` + `refs: Map<sig, count>`，签名 = host:port:user:db；`connectionLimit: 4`、`enableKeepAlive`、`multipleStatements: true`。
- 元数据：`SHOW DATABASES` 后按库 `SHOW TABLES FROM`，`mapLimit` 并发 4；单库失败降级为 `{ name, children: [], error }`（`:154-186`）。
- 系统库：`information_schema/mysql/performance_schema/sys` 默认照常显示，仅当调用方显式传 `hideSystemSchemas: true` 时过滤（偏好 `config.dbHideSystemSchemas`，由前端持有）。
- 分页：服务端 `pageSize = min(n, 1000)`，查询 `pageSize + 1` 行并只返回前 `pageSize` 行，`hasMore = rows.length > pageSize`（T7）；附带 `information_schema.TABLES.TABLE_ROWS` 近似总行数。
- 表结构：`describeTable({ table, database })`，带库前缀 `` DESC `db`.`table` ``。
- 写入：`updateCell` 以 `SET col = ? WHERE pk = ?` 参数化更新；`countRows` 按需执行 `COUNT(*)`（T5/T11）。
- 只读：首关键词白名单 `select|show|desc|describe|explain|with` + **全句写关键词扫描**；校验在建连之前执行（`:243-260`）。
- 结果：`normalizeResults` 把单条/多条统一成 `results[]`；`safeCell` 处理 Date/bigint/Buffer/自定义类型，避免 IPC 克隆失败（`:106-152, 262-292`）。

**PostgreSQL（`postgres.js`）**

- 连接：`clients: Map<sig, client>` + `refs`，`acquire` 用 `SELECT 1` 验证。
- 元数据：列出所有库，**当前连接库**展开「schema → 表」（排除系统 schema，空 schema 保留）；非当前库不展开，前端提供跨库连接入口（T3/T4）。
- 分页/排序参数与 MySQL 一致，查询显式 `"schema"."table"`（默认 `public`）；`describeTable` 返回列定义与 `is_primary_key`；`updateCell` 以 `$1/$2` 参数化更新；`countRows` 按需计数；多语句统一为 `results[]`；只读规则与 MySQL 同款双检。
- 跨库仍不支持（一个连接一个库），跨库查询显式报错。

**Redis（`redis.js`）**

- 连接：`clients: Map<sig, client>` + `refs` + `currentDbMap`，签名 = host:port（不含密码）；`retryStrategy: null`、`enableOfflineQueue: false`，便于快速暴露断线。
- 元数据：`INFO keyspace` 一次取回各 db 键数；db 列表 = `0..max(15, 实际出现的最大序号)`；INFO 被禁用时 `count` 不显示。
- 键列表：SCAN **游标模型**（非页偏移），`nextCursor` 由前端推进；type/ttl 走单次 pipeline；`COUNT` 取页大小（上限 1000）。
- 键详情：string/hash/list/set/zset 全覆盖，附 ttl；list/zset 每次约取 1000 条，前端再分批渲染。
- 写操作：`setKey / delKey / expireKey` 全部先 `checkWritable(readOnly)`；expose 的写能力仅这三种，不是通用命令白名单。
- `closeRedisConnection` 无参全清（退出兜底）。

### 2.4 前端能力

**tab 生命周期**

- 入口：书签双击 → `addTab` → `session.jsx` 懒加载 `DbSession`（`session.jsx:36, 256`）。
- 打开：`openDbTab(clone(tab), clone(sshBookmark))` + 首次 `getMetadata`；失败进入错误页，可重连。
- 关闭：组件卸载、`store/tab.js delTab`（`:287-288`）、app 退出 `on-close.js:28-34` 三处清理。

**顶栏（`.db-head`，`:1628-1705`）**

- 引擎名、连接目标（host:port · db · user）、连接状态点（connected / disconnected）、断线时「重连」。
- 系统库显示开关（写 `config.dbHideSystemSchemas`，立即重拉树）。
- 只读开关（常驻，切换即同步主进程，不用重开连接）。
- 元数据刷新、页面查找（统一 `SearchBar`）、全屏入口（`SessionBarActions`）。

**元数据树**

- MySQL 为库 → 表两级，PG 为库 → schema → 表（schema 节点带 `S` 标记）；节点 key 用 `JSON.stringify([db, schema, table])`，避免名称含 `.` 歧义。
- 宽度可拖拽 160~600px，松手写 `localStorage['electerm-db-tree-width']`。
- Redis 树为 db 节点，右侧显示键数；MySQL/PG 为库 →（schema →）表。
- 树面板顶部有独立筛选框（T2）：仅前端过滤已加载节点，命中自动展开、清空还原，与顶栏查找分工见 §3.1。

**MySQL 数据区（3 tabs，`:1605-1617`）**

- 数据网格头：表名（PG 为 `schema.table`）、近似/精确总行数、当前页行筛选（T1）、上一页/页码标签/下一页、跳页输入、每页行数（10/20/50/100/300/500/1000，默认 20，取 `config.dbPageSize`）、刷新。
- 行虚拟渲染：`DbGridTable` 用 ResizeObserver 实测容器与表头高度，`virtual={y > 0}`，横向滚动条常驻可视区底边、表头吸顶（`:127-179`）。
- 排序列 → 服务端 `ORDER BY`；跳页超出真实末页时用 `pageSize=1` 二分探测真实末页再回退（`:563-596`）。
- 单元格：单击选中 → 下方面板预览/格式化/复制；双击进入编辑；编辑在「非只读 + MySQL/PG + 表有主键（MySQL `Key='PRI'` / PG `is_primary_key`）」时开放，写入走主进程 `updateCell`，无主键提示改用 SQL 页（T5）。
- 上下分区可拖拽，比例持久化 `localStorage['electerm-db-cell-split']`。

**SQL tab**

- `Input.TextArea` + `Ctrl/Cmd+Enter` 执行；结果单条直接表格，多条按 `result N`（已 i18n）分 tab。
- 只读时显示 `read-only`（已 i18n）标签；写入仍由主进程白名单权威拦截。

**表结构 tab**

- 选中表即拉 `describeTable`；列定义按首行 key 动态生成（兼容 MySQL `Field/Type/…` 与 PG `column_name/data_type/…`），PG 的 `is_primary_key` 列渲染为 `PK` 徽标（T5）。

**Redis 数据区**

- 过滤条：match pattern + filter 按钮（SCAN MATCH），游标翻页（上一页用游标栈，**不支持任意跳页**）。
- 上下分区：键列表 / 键详情；键详情分批渲染，每批 200。
- string：值面板支持高亮、格式化、编辑保存（`setKey`）、设置 TTL、删除。
- hash/list/set/zset：网格展示 + `load more`（已 i18n）；TTL 与删除在详情信息栏。
- 只读时 TTL/删除/保存按钮禁用，并在单元格编辑处提示原因。

**通用表现**

- 页面内查找：把命中包 `<mark class='db-kw-hit'>`，textarea 无法插标，命中轮到时 `focus + setSelectionRange` 定位；支持 `(i/n)`、上一个/下一个、当前命中两色（`:51-115, 190-305`）。
- 关键字高亮与终端共用 `config.keywords` 与主题配置；大文本（>4KB）在网格内跳过高亮，值预览放宽上限。
- 数据面字体继承 tab 字体 / 全局终端字体，CSS 回落 `--font-mono`。
- 样式全 token（`db-session.styl` 无硬编码色值），空态/表结构/重连等文案走 `e()` + 本地补充词条。

### 3.1 数据库页「查找」与「过滤」的分工

> 状态：A、B 已落地；C（T6）经用户确认本轮不做。旧稿的倾向结论仍成立，C 可按需重新取舍。

**结论：不新增浏览页级通用“搜索框”；顶栏负责查找，面板工具条负责过滤。**

| | 查找（顶栏） | 过滤（面板） |
| --- | --- | --- |
| 回答的问题 | “这段文本在页面哪里” | “我只看满足条件的数据” |
| 作用对象 | DOM 可见内容（树/网格/键列表/详情） | 数据源（SCAN MATCH / WHERE） |
| 引擎 | DOM 扫描 + `<mark>` / textarea 选区 | 服务端命令或客户端行筛 |
| 是否滚动定位 | 是 | 否（结果集本身变小） |

**现状证据**

| 入口 | 位置 | 语义 | 状态 |
| --- | --- | --- | --- |

**为什么不建议再做独立搜索框**

1. 语义冲突：同页两个“搜索框”，用户无法区分与顶栏查找的差异。
2. 渲染边界：网格行虚拟渲染，DOM 只含可视区行；要搜全量数据本质是查询，只能走过滤。
3. 协议保护：`common/search-bar` 是纯 UI 查找条（注入 find/prev/next）；下放做数据过滤会引入服务端查询、防抖、清空回位等语义，破坏单一协议。
4. 已有先例：Redis 的 filter 长在数据源旁并绑定 SCAN MATCH，是面板级过滤的正确形态。

**A · 顶栏查找支持 textarea 选中定位** — ✅ 已实施（`fea6fd54`）

- 计数扫 `value` 全量偏移，命中并入 `(i/n)`；
- 轮到 textarea 命中时 `focus + setSelectionRange(start, end)`；
- 唯一妥协：textarea 内其余命中无法提前标色，轮到时才可见。

**B · MySQL 网格头「当前页行过滤」** — ✅ 已实施（T1，2026-10-21）

- 网格头「近似行数」之后新增 `筛选当前页` 输入框；纯客户端过滤当前页 `dataSource`，不触发 SQL。
- 不区分大小写、匹配所有可见列；命中用 `db-page-hit` 标色，不进入顶栏查找计数。
- 显示 `命中 / 本页`；翻页保留关键词，切换表 / 排序 / 页大小 / 刷新时清空；无匹配显示独立空态。
- 明确不做全表搜索；跨页找值属数据查询，见 C。

**C · WHERE 下沉服务端** — ❌ 本轮不做（T6，经用户确认）

- 仅在“跨大量行找值”成为高频场景时立项；涉及分页/排序联动、标识符白名单与只读复核。

**不做**：MySQL / Redis 浏览页各自独立的通用搜索框（理由见上）。

#### T1 · MySQL 当前页行过滤（✅ 已实施 2026-10-21）

- **目标**：解决“只想在眼前这 20 行里找值”的问题，不冒充全表搜索。
- **交互**：网格头新增筛选框（标题/近似行数之后、分页组之前），占位“筛选当前页”；输入即时过滤（页大小上限 1000，无需防抖），不区分大小写，匹配所有可见列；右侧显示 `命中/本页`；`Esc` 或 × 清空；无匹配时显示“本页无匹配行 + 清除筛选”，不能显示成“表为空”。筛选框可收缩至 96px，网格头不换行、不增高。
- **状态规则**：翻页保留关键词并对新页重新过滤；切换表、切换排序、修改页大小、刷新时清空。
- **实现**：仅改 `db-session.jsx`，由 `grid.rows` 派生 `filteredRows`；不改 `getPageData`、不新增 IPC、不改分页语义。
- **验收**：20 行页筛出 7 行时计数为 `7 / 20`；清空恢复；翻页/排序/换表行为符合上述规则；只读模式可用；键盘可达。

#### T2 · 元数据树筛选（✅ 已实施 2026-10-21）

- **目标**：库/表很多时快速定位节点，与顶栏“页面文本查找”分工明确。
- **交互**：树面板顶部 24px 筛选框，占位“筛选库 / 表”；不区分大小写子串匹配；命中分支自动展开并高亮；显示命中节点数；清空后恢复原展开状态；无匹配显示“没有匹配的库或表 + 清除筛选”。
- **实现**：仅改前端。基于已加载的 `treeData` 派生过滤树与 `expandedKeys`；不重新请求元数据，不改变当前选中表。
- **验收**：折叠状态下的命中表能被自动展开；清空后展开状态还原；选中节点不被过滤中断；Redis 树同样可用（按 db 名匹配）。

#### T3 · PostgreSQL schema 层级（✅ 已实施 2026-10-21）

- **目标**：让非 `public` schema 的表可见、可查询。
- **交互**：PG 树变为「库 → schema → 表」；当前连接库展开 schema，其他库仍为“未连接”；schema 节点显示 `S` 标记；选中表后网格标题显示 `schema.table`。
- **实现**：
  - `postgres.getMetadata` 查询当前库的 `pg_namespace` + `pg_tables`，返回 schema 子节点；非当前库 `children` 仍为空。
  - `getPageData` / `describeTable` 增加 `schema` 参数（默认 `public`），标识符统一按 `"schema"."table"` 双侧引用。
  - 前端节点 key 从 `[db, table]` 扩为 `[db, schema, table]`；selectedKeys、表结构、单元格编辑定位同步。
- **验收**：`public` 与非 `public` 表均可浏览/查询/看结构；MySQL/Redis 树不变；已有 PG 书签默认落在 `public`；schema 名含引号时仍安全引用。

#### T4 · PostgreSQL 跨库连接引导（✅ 已实施 2026-10-21）

#### T5 · PostgreSQL 单元格编辑（主键检测，✅ 已实施 2026-10-21）

#### T11 · 精确总行数（可选，✅ 已实施 2026-10-21）

- **目标**：默认打开不增加全表扫描，同时给“估算行数不够用”的场景一个按需精确值。
- **入口**：网格头 `approx rows: N` 旁增加文字按钮「精确」；Redis 不显示（无总行数概念）；PG 在实现后同样可用。
- **交互与状态**：
  1. 默认：显示近似值 + `approx` 标记，「精确」可点。
  2. 点击：按钮进入 `counting…` loading；当前页数据保持可操作。
  3. 成功：数值替换为精确值，标记改为 `exact`；不改变当前页、排序与滚动位置。
  4. 超时/失败：保留近似值，toast 提示“精确计数超时，仍显示估算值”，按钮恢复可点。
  5. 切换表、排序、页大小，或 T6 的 WHERE 条件变化：丢弃精确值，回到近似值。
- **实现**：
  - 新增 `countRows` op（仍走 `dbClientOp` 单通道，`OP_MAP` 增加 MySQL/PG 项），参数 `{ database, schema, table }`；适配器参数化构造 `SELECT COUNT(*)`，不拼接值。
  - `OP_TIMEOUTS.countRows = 60000`；计数失败只影响提示，不影响已加载的页面数据。
  - Redis 不注册该 op，前端按引擎隐藏入口；精确值只存组件 state，不写配置、不缓存。
- **为什么不做默认**：`COUNT(*)` 在大表/冷缓存下是全扫描，默认执行会把“打开表”变慢；现有 `TABLE_ROWS` + 空页二分已覆盖大多数浏览场景。
- **验收**：默认打开不产生 COUNT 查询；MySQL/PG 点击后返回精确值；超时/断网保留估算并提示；切换表/排序/筛选后精确值失效；只读模式可用；Redis 无入口。

#### T12 · Redis 写操作扩展（⏸ 本轮不做）

- **状态**：本轮不做（用户 2026-10-21 确认）；下列范围为后续需求储备。
- **目标**：把 Redis 从“看 + 改 string / 删键 / TTL”扩展到常用类型化编辑；不提供通用命令控制台。
- **范围（v1 候选）**：

| 类型 | 操作 | 命令 | 入口 | 二次确认 |
| --- | --- | --- | --- | --- |
| hash | 新增/修改字段 | `HSET` | 工具条 `+ field`；双击 value 编辑 | 否 |
| hash | 删除字段 | `HDEL` | 行操作菜单 | 是 |
| set | 添加成员 | `SADD` | 工具条 `+ member` | 否 |
| set | 移除成员 | `SREM` | 行操作菜单 | 是 |
| zset | 新增/改分 | `ZADD` | 工具条 `+ member`；双击 score 编辑 | 否 |
| zset | 移除成员 | `ZREM` | 行操作菜单 | 是 |
| list | 头/尾插入 | `LPUSH` / `RPUSH` | 工具条 `push` + 方向选择 | 否 |
| list | 按索引改值 | `LSET` | 双击 value 编辑 | 否 |
| list | 按值删除 | `LREM key 1 value` | 行操作菜单（提示“删除第一个匹配值”） | 是 |
| key | 重命名 | `RENAMENX` | 工具条 `rename` | 是（输入新名） |
| key | 删除 / TTL | `DEL` / `EXPIRE` / `PERSIST` | 现有入口 | 删除确认 |

- **UI**：
  - 详情工具条按类型显示 `rename`、`+ field/member`、`push`、`set ttl`、`delete`；行内双击 value/score 进入编辑（Enter 保存 / Esc 取消）；行尾或右键菜单提供删除。
  - 只读时全部写入口 `disabled`，tooltip 说明“只读模式”；写入中按钮 loading。
  - 成功后刷新当前键详情；删键后清空详情并从键列表移除；重命名后就地更新键列表行与详情标题，不重扫 SCAN。
  - set 的 member 是身份，不提供“改值”，只能添加/移除；zset 的 score 必须为数字，非法输入在提交前拦截。
- **后端**：
  - 新增类型化方法（`hSet/hDel/sAdd/sRem/zAdd/zRem/listPush/listSet/listRemove/renameKey`），全部先 `checkWritable(readOnly)`，参数化调用，不接受拼接命令字符串。
  - 重命名用 `RENAMENX` 而非 `RENAME`：目标键已存在时返回失败，避免静默覆盖；UI 提示更换名称。TTL 随键保留。

## 5. 验证环境陷阱与 IPC 边界规则

### 5.1 CDP 验证环境陷阱（记录于 2026-10-14，方法可复用）

1. 已安装的 `/opt/electerm` 会先占用 `--remote-debugging-port=9222` 与其内部服务端口；
2. 本仓库调试实例绑定 9222 失败后会静默继续，服务端口落在别的号段；
3. 于是 CDP 实际连到的是“用户安装版”，其 `assets` 是旧打包快照，与本地 `work/app/assets` 不是同一份；
4. 现象：新 chunk 404、旧 chunk 200。

固化手法：

```bash
# ① 独立端口，避开已安装实例
DISPLAY=:99 node_modules/.bin/electron work/app/app.js --no-sandbox --disable-gpu \
  --user-data-dir=/tmp/electerm-audit-profile --remote-debugging-port=9333
# ② 连上先自证身份：location.href 必须是本实例端口
# ③ 核对实际加载的 chunk：performance.getEntriesByType('resource')
```

另注意：`chunk/` 目录内新旧同名 chunk 会并存（vite 产物带不同 hash，旧文件不自动清理）。判断改动是否生效必须核对实际加载的 chunk 名。

### 5.2 IPC 边界对象序列化规则

`preload.js` 的 `runGlobalAsync` 走 Electron 结构化克隆，没有全局序列化保护；mobx observable proxy / 含函数或循环引用的对象会抛 `An object could not be cloned`。

**规则：凡把 store 派生对象传入 IPC，一律先 `clone(...)`（`to-simple-obj`）。**

现行 6 通道核查：

| 通道 | 调用点 | 实参 | 结论 |
| --- | --- | --- | --- |
| `testDbConnection` | `store/bookmark.js:40-44` | `clone(bookmark)` + `clone(sshBookmark)` | 安全 |
| `openDbTab` | `db-session.jsx:495-496` | `clone(tab)` + `clone(getSshBookmark())` | 安全 |
| `dbClientOp` | `db-session.jsx` 多处 | 字面量对象（`{sql}`、`{dbIndex,key}`、`{database,table,page,…}`） | 安全 |
| `setDbReadOnly` | `db-session.jsx:675` | `tabId` + boolean | 安全 |
| `closeDbTab` | `db-session.jsx:516`、`store/tab.js:288` | `tabId`（string） | 安全 |
| `closeAllDbTabs` | `on-close.js:30` | 主进程内部调用，无参 | 安全 |
