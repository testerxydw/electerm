#### [ ] 🔥 H1a · 网格可读性统一层（第一优先，排在 H1 之前）

> 触发：2026-10-28 用户反馈"SQL 结果页长内容列看不到——悬停无预览、列宽不能调"（附 `operation_log` 截图：`parameter`/`detail`/`detail_en` 三列被切）。
> 复核结论：**这不是 SQL 页专属问题**，5 处网格同病；且 SQL 引擎的 UI 层共用，一次投入 4 引擎全覆盖。

**根因（源码核验）**

| 现象 | 根因 | 证据 |
|---|---|---|
| SQL 结果列宽不能调 | 列硬编码 `{ width: 220, ellipsis: true }`，无 `onCell`、无拖拽手柄 | `db-session.jsx:3820-3835` |
| 悬停无预览（SQL 页 + 数据页同病） | rc-table 只在单元格 children 为字符串/单层字符串元素时生成原生 `title`；`renderCell` 返回高亮 `<span>` 树 → title 为空 | `@rc-component/table/es/Cell/index.js:9-27`、`db-session.jsx:3537-3561` |
| 数据页悬停只见操作提示 | td 的 `title` 被"单击预览/双击编辑"占用 | `db-session.jsx:3788` |
| SQL 结果点击无处可看 | 数据页有底部 `DbValuePane`，SQL 页 `.db-sql-result` 只有错误 + 网格 | `db-session.jsx:6170-6178` vs `4570-4620` |
| 短列空、长列切 | 数据页有按内容采样定宽（90~360），SQL 页未复用 | `db-session.jsx:3566-3583` |
| JSON 列预览看不全 | `renderCell` 对对象 `JSON.stringify(v).slice(0, 200)`，预览须重新序列化 | `db-session.jsx:3552` |
| SQL 结果类型/格式化失效 | 适配器把 `fields` 压成纯列名，mysql2 `columnType` / pg `dataTypeID` 被丢弃 | `db-client/mysql.js:1047`、`postgres.js:1025`、`pg-protocol/dist/messages.js:62` |

**覆盖范围（5 处网格 + 引擎边界）**

| 网格 | 现状 | 本批动作 |
|---|---|---|
| SQL 结果 `db-session.jsx:3922` | 固定 220、无 hover、无值面板 | 全套（自适应 + 拖拽 + 预览 + 底部面板） |
| 数据页 `:5135` | 已有拖拽/自适应/持久化/值面板 | 只补 hover 预览 + 列头一键自适应/重置 |
| 表结构页 `:4463`（`structColumns` 固定 200） | 注释/默认值长即切 | hover + 自适应 + 拖拽（内存态） |
| Redis 键列表 `:4479` | key 列无宽、无 hover | hover + 自适应 + 拖拽（内存态） |
| Redis hash/list/set/zset 详情 `:6468/6506/6544/6582` | value 列 `ellipsis` 无 hover | hover + 自适应（长 value 主战场） |
| 引擎边界 | mysql/postgres/tidb/oceanbase 共用同一 UI 层（`db-client/index.js:12-16`，tidb/oceanbase 复用 mysql 适配器） | UI 层改动**自动覆盖 4 引擎**；仅 H1a-3 需按引擎写类型映射 |
| Redis（无类型概念） | — | 跳过 H1a-3 |
| 未来 SQLite/Kingbase（H8a/H8b） | — | 走同一 UI 层，零额外成本 |
