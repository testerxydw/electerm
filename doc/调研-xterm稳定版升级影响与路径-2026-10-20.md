# 调研：xterm 稳定版升级影响范围与路径（T4 前置，2026-10-20）

> 结论先行：**当前不存在"无痛切稳定版"路径**。fork 的滚动条补丁 + addon 无 6.0 配套稳定版，是两个硬障碍。推荐：不立即升级，跟踪官方 6.1 稳定 + 上游 electerm 动作，届时一并处理；或小成本先试"官方 beta.315"验证 reflow 是否已修。

## 一、版本全景（npm 实测）

| 项 | 版本 | 说明 |
| --- | --- | --- |
| 本项目渲染 core | `@electerm/xterm@6.1.0-beta.292-electerm.2`（npm alias @xterm/xterm） | fork = 官方 beta.292 + electerm 补丁 |
| 本项目 addon ×9 | `0.x-beta.292`（webgl .291） | 配套 beta.292 |
| 本项目主进程 | `@xterm/headless@6.1.0-beta.292` | session-base.js 服务端 buffer |
| 官方稳定 core | `@xterm/xterm@6.0.0`（2025-12-22 发布） | **addon 无 6.0 配套稳定**（fit latest 0.11.0 是 5.x 时代） |
| 官方活跃 beta | `6.1.0-beta.315`（2026-10-13） | 官方仍在推进 6.1 线，未发稳定 |
| 上游 electerm master（5.6.10） | 与本项目完全一致（fork.2 + beta.292） | 上游作者也锁在此版本 |

## 二、fork 补丁真身（tar 对比实测）

`@electerm/xterm` 与官方 `@xterm/xterm@6.1.0-beta.292` 仅 4 个构建产物不同（xterm.js/mjs + map）。

- 补丁内容 = **electerm 定制内建滚动条**：`scrollbar.showScrollbar/showArrows/width` 选项 + `_scrollableElement` Viewport 重写 + `scrollLines/scrollToLine` 自管滚动（diff 量级 ~350KB minified）
- 含义：**任何"回官方包"的路径都会丢 electerm 滚动条**，需把补丁 port 到新版本（独立 XL 工作）
- fork repo `electerm/xterm.js` 活跃，未来可 rebase，但目前无 .293+ 分支

## 三、错乱问题真身（修正文档旧表述）

- 渲染错乱 issue 编号是 **electerm 仓库**的（如 [electerm#4499](https://github.com/electerm/electerm/issues/4499)，open）：5.2.0 长会话输出错乱、reload 不恢复、仅新会话可解；用户从 3.15.32（xterm 5.5.0 稳定）升级后复现，beta.302 仍错乱
- 关联上游 [xtermjs#5321](https://github.com/xtermjs/xterm.js/pull/5321) "reflow 对齐 conpty"：**已 merged 进 6.0.0 稳定**（2025-03）
- ⚠️ 矛盾点：#5321 进了 6.0.0，但 beta.302（>beta.288）用户仍错乱 → **reflow 重写本身可能引入新回归，官方 beta 线还在修**。"升到 beta.315 就好"没有证据，"6.0.0 稳定版能根治"同样未验证
- 旧文档"6 个渲染错乱 issue"编号均属 electerm 仓库（#4501/#4481/#4439 等），共同指向 6.1-beta 渲染回归

## 四、本项目耦合面（升级必过清单）

| 耦合点 | 文件 | 升级风险 |
| --- | --- | --- |
| 动态加载 10 包 | xterm-loader.js | import 路径/导出名若变即加载失败 |
| serialize 会话恢复 | term-init.js L59-60 + 主进程 headless | 序列化格式跨版本兼容性 |
| headless 服务端 buffer | session-base.js L14 | core 版本须与渲染端**严格同源**（headless 无 fork，若 core 换 fork 版本错位即 buffer 行为不一致） |
| 命令历史捕获 OSC 633 + manual 键入缓冲 | command-tracker-addon.js / term-suggestions.js | 渲染/回显时序变化即复发静默丢命令（此前修过 3 轮） |
| search-bar 高亮 | addon-search | API 稳定但装饰行为可能变 |
| webgl/dom 渲染切换 | rendererType 配置 | webgl .291 与新 core 配套性 |
| fit/resize | term:resize + fit addon | reflow 行为全变（正是要验证的点） |
| 单测 | ssh-reload-state.spec.js 直 import headless+serialize | 需随版本同步 |

## 五、三条路径对比

| 路径 | 内容 | 收益 | 成本/风险 | 结论 |
| --- | --- | --- | --- | --- |
| A 回官方 5.5.0 稳定 | core+addon 全回 5.5 | 3.15.90 时代稳定基线 | 丢 6.x 特性+滚动条补丁需 port 回 5.5（XL）；逆向演进，上游也不会跟 | ❌ 不做 |
| B 官方 6.0.0 稳定 | core 6.0.0 + addon ? | core 稳定、reflow 重写在内 | **addon 无 6.0 配套**（断层）；滚动条补丁丢失；headless 6.0.0 与渲染端混搭风险 | ❌ 结构性不可行 |
| C 升官方最新 beta.315 | 全家桶 .292→.315（fork 丢或 rebase） | 官方 4 个月的渲染修复全带上（含 reflow 后续修复） | 滚动条补丁丢（或 fork rebase XL）；回归面 = 七项清单；**收益未验证** | ⏸ 可低成本探路（见下） |
| D 等官方 6.1 稳定 + 上游动作 | 跟踪 | 届时 fork rebase / 上游自己解决，一次到位 | 时间未知（beta 活跃中） | ✅ 默认策略 |

## 六、建议

1. **默认策略 D**：不立即升级。锁定关注点：官方 6.1 稳定发布、electerm/xterm.js fork 出新 rebase、上游 electerm package.json 变动（三者任一出现即触发 T4 重启）
2. **可选低成本探路（半天级）**：本地分支把 10 包换成官方 .315（暂丢滚动条，纯验证），跑七项回归清单（分屏/查找/命令历史/建议/TUI vim-htop/序列化恢复/拖宽 reflow）——若 electerm#4499 复现场景消失，则 C 路径收益坐实、fork rebase 值得投入；若依旧错乱，则整个"升 beta"方案证伪，安心等 D
3. 立即可做的小项：把 TODO 文档里 "#4499（xtermjs）" 的仓库归属标注修正（本次调研已澄清）

## 七、一句话

**升级卡点不在 electerm 侧代码，而在 fork 滚动条补丁的 rebase 成本与官方 addon 无 6.0 稳定配套；建议默认等 6.1 稳定/上游动作，可选先花半天用官方 beta.315 做无滚动条验证版坐实收益。**
