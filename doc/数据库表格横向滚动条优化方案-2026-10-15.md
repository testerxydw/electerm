# 数据库表格横向滚动条优化方案

> **状态：✅ 已完成（2026-10-21 复核）**：DbGridTable 统一横滚条已落地，真实库+真机验证通过（`1d01a4b0`）。

## 一、问题

数据表（数据 tab 的表格页）行数超过可视区时，横向滚动条位于**全部行之下**，必须先纵向滚到最底部才能看到并拖动它。

根因：`.db-grid-table`（antd Table，`scroll={{ x: 'max-content' }}`）所在容器是唯一滚动容器（`flex 1; overflow auto`，`db-session.styl:218`），横向滚动条由这个"整页高"的容器产生，天然沉在内容最底部。

## 二、候选方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 纯 CSS 把滚动视口移进 antd 内层 `.ant-table-content` | 给 antd 内部 wrapper 链（5 层 div）逐层设 `height/max-height 100% + min-height 0` | 不改 JSX | 依赖 antd 6 内部 DOM 结构，升级易碎；antd 官方未承诺该层级稳定 | 弃 |
| B. `scroll={{ x: 'max-content', y: <数值> }}` | antd 官方用法：表头与 body 分离渲染，body 自己定高滚动 → 横向滚动条**固定在可视区底边，永远可见** | 官方能力、代码量小；顺带获得**表头吸顶**（滚行时列名不消失） | `y` 需数字，需测量容器高度（ResizeObserver） | **采用** |
| C. 自绘悬浮滚动条（overlay 同步原生滚动） | 在容器底边画一条假滚动条 | 不依赖 antd | 同步逻辑复杂、拖拽/键盘/惯性全要自己处理 | 弃（仅当 B 失效再议） |

## 三、推荐实现（方案 B，最小改动）

> **2026-10-15 更新**：按用户要求已统一处理所有会横向溢出的网格——抽为本文件内组件 `DbGridTable`（`db-session.jsx`），主数据网格 / SQL 结果 / 表结构 / Redis 详情（hash/list/set/zset）/ Redis 键列表 7 处全部换用；配套 CSS：`.db-grid-table-wrap`（scroll 容器）、`.db-sql-result` 内 antd Spin 包装层参与 flex 传高、`.db-struct-area` 用 `height 100%` 撑满 tabpane（块级父级里 flex-basis 不生效）。真实库（192.168.115.67:13306 tgfsom.tgfsom_operation_log，24 万行）实测：data/SQL/表结构三处横滚条均常驻可视区底边（偏差 0px）、表头吸顶；Redis 页共用同一组件与布局模式（本机无 redis 服务未实测，待用户环境复测）。

原设计范围（初版仅主网格）：

### 改动点

1. `db-session.jsx`（dataArea）：
   - Table 外包一层 `<div className='db-grid-table-wrap' ref={wrapRef}>`，接管原 `.db-grid-table` 的 `flex 1 1 0; min-height 0`。
   - 新增一个**组件内局部**的容器高度测量（`useRef` + `useEffect` + `ResizeObserver`，直接写在 `db-session.jsx` 内，不新建文件——当前只有一处调用，不满足抽 hook 的条件）：
     ```jsx
     const gridWrapRef = React.useRef(null)
     const [gridWrapH, setGridWrapH] = React.useState(0)
     const [gridHeadH, setGridHeadH] = React.useState(0)
     // 容器高度：ResizeObserver 观察 wrap；表头高度：MutationObserver/轮询一次读取 .ant-table-thead
     // y = gridWrapH - gridHeadH，二者任一 <=0 时不传 y（保持现状）
     ```
   - Table 改为 `scroll={{ x: 'max-content', ...(gridWrapH > gridHeadH && gridHeadH > 0 ? { y: gridWrapH - gridHeadH } : {}) }}`。
   - ⚠️ hook 必须写在 `db-session.jsx` 既有的 `if (error) return` / `if (!ready) return` **之前**（hook 顺序契约，此前已踩过崩页坑）。
2. `db-session.styl`：
   - 新增 `.db-grid-table-wrap { flex 1 1 0; min-height 0; display flex; flex-direction column }`。
   - `.db-grid-table` 去掉 `flex 1 1 0; min-height 0; overflow auto`（滚动权移交 antd 内部 body），仅保留类名挂载。
   - 颜色/圆角不涉及，无 CSS 契约新增风险；如新增 token 需过 `css-tokens.spec.js`。

### 行为效果

- 行多 + 列宽（如截图 1 的 `tlp_hbon_hook_task`）：横向滚动条常驻可视区底边；表头吸顶，纵向滚动时列名恒可见。
- 行少（截图 2 `tlpbon_operation_log` 一屏内）：无变化。

### 边界与风险

| 点 | 处理 |
|---|---|
| 首帧 height=0 | `y` 不传，保持现状渲染；ResizeObserver 回调后再 setState 补上（一次闪动可接受） |
| 窗口/分屏/树宽拖拽导致容器变化 | ResizeObserver 天然覆盖 |
| antd `scroll.y` 模式下列宽 | `scroll.x='max-content'` 已存在，header/body 分离下 antd 用同一 colgroup 对齐，不受影响 |
| 错误 Alert/分页条占位 | 它们在 wrap 之外（`.db-grid-area` 内、wrap 之前），wrap 实测高度自动扣除，无需手算 |
| 屏幕阅读器/键盘 | 原生滚动容器不变（只是从外层移到 antd body 层），无回归 |
