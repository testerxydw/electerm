# 关键字高亮：色板复用与密度治理 · 设计（2026-11-05）

状态：**设计定稿，未开工**。用户 2026-11-05 三条指令：① 共享规则抽单独分组，组与组之间不得有重复规则（共享的也不行）；② 100 多条太多，精简；③ 参考 WindTerm 默认高亮规则，其他规则尽量精简。两处待拍板（通用组拆分粒度、老配置迁移方式）按本文 §3 的建议执行。

## 1. 实测基线（本文所有判据的来源）

探针：把 `keyword-presets.js` 全量启用 → `activeKeywords` 去重 → 复刻 `highlight-addon.js` 的"合并大正则定位 + 同起点锚定取最短"裁决，对 13 类代表性输出逐条统计。脚本口径可复现（本轮为一次性探针，落地时固化成 `self-test/keyword-density-*`，见 §8）。

| 事实 | 数 |
| --- | --- |
| 预设组 / 组内条目 / 去重后生效 | 13 组 / **152 条** / **105 条** |
| 被多组重复引用的共享规则 | **19 条**；`ipv4` 一条出现在 **9 个组** |
| 全选用后对 15 行真实日志的染色面积 | **44%**（608/1396 字符） |
| 染色面积按色分布 | blue 47.9% · cyan 38.0% · green 5.1% · red 3.5% · magenta 3.1% · yellow 2.5% |
| 单行最惨 | **93%**（一行日志文件路径被 `absPath` 整条吃掉） |
| 面积大户 Top6 | `srcFile`(蓝) > `ts`(青) > `absPath`(蓝) > `URL`(蓝) > `ipv4`(青) > `num`(青) |
| 命中面最广 | `num` 13/13 类输出、`lvlError` 8 类、`ts` 6 类、`ipv4` 5 类 |

**结论一（满屏蓝的成因）**：不是色不够，是**每行必中的"结构类"信号占了 86% 的染色面积，且它们全挤在 blue/cyan 两色**；语义信号（红=错误、黄=警告、绿=成功）合计不到 12%，被淹没。

**结论二（面板口径失真）**：152 条目 vs 105 生效，"已应用 N/M"与实机着色对不上，根源是共享规则被按组重复写入——正是用户要消灭的那件事。

⚠️ 探针里"32 条在我这批语料 0 命中"**不能当死规则**：样例是我手写的，没覆盖 git diff hunk、TLS 指纹、SQLSTATE、UUID 等形状。它只能当"命中面窄"的参考，删除判据见 §5。

## 2. WindTerm 基准（实测，不是二手转述）

来源：`WindTerm_2.7.0_Linux_Portable_x86_64.zip` → `WindTerm_2.7.0/terminal/schemes/linux/linux.lexer`（7244 字节，291 行；仓库是发布壳，规则文件只在二进制包里，源码仓库无）。

| 维度 | WindTerm 默认 Linux | electerm 全选现状 |
| --- | --- | --- |
| 顶层语义类 | **9**（keyword / datetime / ip / mac / number / option / path / permissions / operator + string） | 13 组 |
| match/begin 模式条数 | **约 30** | **105**（条目 152） |
| "词档"条数 | **4**（error / success / warn / info，各一条大 alternation） | 20+ |
| 结构信号用色 | **`markup.heading` 一档一色吃下 datetime + IP + IPv6 + MAC** | 拆成 `ts`/`tsBracket`/`ipv4`/`ipv6`/`mac` 5 条、cyan+magenta 两色 |
| 层次手段 | grammar 上下文：prompt 行内才认 command/option、字符串整体一档、权限位逐字符四色 | 只有"整条匹配配一种颜色"，无行级上下文 |

**结论三（精简的正确姿势）**：WindTerm 的克制不在"词表小"，而在**结构信号只给一档一色**。我们反向做了——同一类结构信号拆成多条、占两色、抢 86% 面积。所以精简的重点是**收敛结构信号（合并 + 单色 + 降档）**，而不是砍错误词表。

**搬不动的三档**（`keyword-presets.js` 文件头已声明，本文维持该口径）：prompt 行内的 command/option 分色、引号字符串整体染色、权限位逐字符四色——本引擎给整条匹配配一种颜色且无行级上下文，硬搬只会更难看。

## 3. 两处拍板（按建议执行）

1. **通用组拆三档**，不做一条整组：`通用 · 级别与状态`（signal）/ `通用 · 时间与数值`（structure）/ `通用 · 地址与路径`（structure）。
   理由：满屏蓝的主力恰是后两档；合成一条整组的话，"只想要错误词"的人必须连时间戳、裸数字一起吞下，密度问题原样保留。拆三档后，勾选粒度 = 密度粒度。
2. **老配置自动归并 + 保留用户改过的色**：把命中共享集合的条目改写为 `group='通用 · …'`，同正则的重复条目折叠成一条；**折叠时若某条的 `color` ≠ 预设默认色，判定为用户手改，保留该色**（并保留它所在的那条），只丢与它同正则同色的冗余项。
   理由：不迁移的话，面板分组计数、勾选态、"已应用 N/M"全错；无脑归并的话，用户辛苦调过的色会被抹平。两条都不可接受，取"归并 + 保色"。

## 4. 分组改造：跨组唯一

- 新增 `keyword-presets.js` 内三个通用组，**业务组一律不再引用共享规则对象**，只留本领域独有规则。
- 不变量升级（`keyword-presets.spec.js:58` "every preset is well formed"）：现在只查"组内不重复 + 同正则同色"，改为 **任一正则在全部预设里只出现一次**（跨组唯一）。这条一断，152/105 的错位从结构上不可能再发生。
- `mergeKeywordPreset` 的按正则去重降级为**兜底**（注释同步改口径：正常路径下不该再命中它）。
- 新增迁移函数 `regroupSharedRules(list)`（放 `keyword-groups.js`，纯函数、可单测）：按 §3.2 归并老配置，幂等。
- 面板统计口径随之变诚实：每组 `已应用 n/total` 的 total = 该组真实生效数。

## 5. 精简：105 → ≤40，每组 ≤4

判据按优先级，不用"我这批语料没命中"当理由：

1. **同色同类合并**（对齐 WindTerm 的 `markup.heading`）：`ts` + `tsBracket` 合 1；`srcFile` + `srcLoc` 合 1；`dur` + `durKey` 合 1；`ipv4` + `ipv6` + `mac` 合 1（同色后合并才允许，见文件头纪律 3）。Networking 的 `%FACILITY-N-` 三条 syslog severity 压成 1 条（只保留红档，6-7 档随通用 info/debug）；HTTP 的 `[core:error]/[warn]/[info]` 三条与通用级别档重叠 → 删；Git 的 `diff --git` / `+++ ---` / `index` / `@@` 四条合成 1 条 diff-header。
2. **删低信噪比档**：`wordNote`（ACCESS/AUTH/PASSWORD 这类词几乎不带信息量，还要一大段否定式 lookahead 才不抢红档）、`permStr`（WindTerm 逐字符四色，我们整串一色反而更难看，文件注释自己承认只是"看得出来"）、`devAddr`（PCI 地址，只在 lspci/dmesg 有用，属内核组独有，不该占通用档）。
3. **业务组只留"通用装不下的"**：每组 ≤4 条，超出的必须先说明为什么不能并进通用档。
4. **硬上限防反弹**（spec 断言）：`每组 keywords.length ≤ 4`、`全选生效总数 ≤ 40`。以后加一条得先减一条。

目标形态（草案，条数以 §4 跨组唯一后的实际生效数为准）：

| 组 | 条数 | 内容 |
| --- | --- | --- |
| 通用 · 级别与状态（signal） | 6 | lvlError / lvlWarn / lvlInfo / lvlDebug / wordOk / exc |
| 通用 · 时间与数值（structure） | 4 | ts(含方括号) / dur(含 key=value) / size / num(含 hex) |
| 通用 · 地址与路径（structure） | 4 | addr(ipv4+ipv6+mac) / path(absPath+srcFile+srcLoc) / optFlag / url |
| Networking / Syslog / Kernel / HTTP / AppLog / Stack / Docker / Build / Git / Auth / Database | 各 ≤4，合计 ≤24 | 只留领域独有词表与状态机 |

## 6. 密度控制（砍条数不等于砍密度）

1. 规则加 `tier: 'signal' | 'structure'`（缺省按 signal 处理，老配置零迁移）。
2. **"全部应用"语义改为 signal 全开 + structure 按需**：现在 `kwApplyAll` 把 105 条全上，等于强制打开最吵的结构档。改后全选 = 结构档默认关，面板上单独给"结构档"开关。
3. **单行覆盖率上限**：一行染色占比 > 阈值（默认 35%）时只保留 signal 命中——直接消灭 93% 那种整行花屏。落点在 `highlight-addon.js` 的 `filtered` 之后加一道裁决，网格侧 `db-highlight.jsx` 同口径（两处必须一起改，否则又出现"终端与网格结论不一样"）。
4. **结构档限跨度**：`path` 一条吃 96 字符，给 structure 档设 max span（超限只染首段或不染）。

## 7. 色板复用书签色卡

- 落点：`keywords-form.jsx:57` 的 7 色 `Select` → 换成 `components/common/color-card.jsx`（24 色点 + random + HexInput），外面套 `bookmark-form/common/color-picker.jsx` 的 swatch + Popover 形态。
- 字段：`color` 允许 ANSI 名 **或** `#rrggbb`；`keyword-compile.js:27` 双分支——终端侧名走现有 `3Xm`（跟主题），hex 走 `\u001b[38;2;r;g;b`（转义由我们本地注入 xterm 5.x，不涉及远端能力协商）；网格侧名继续读 `themeConfig[color]`，hex 直接 `style.color`。老配置零迁移。
- **两个坑（必须实现，不是可选项）**：
  1. hex 不跟主题。色卡 24 色是为"徽标底色 + 运行时按 isDark 现算字色"挑的（`rand-hex-color.js:13` 注释），关键字场景是"前景色 + 主题背景"：深色主题选 `#24292e`、浅色主题选 `#ffd33d` 直接看不见。→ 复用同一张卡但加**按当前主题 background 的对比度门槛**（`is-color-dark.js` 同族亮度算法），不达标色点标灰 + 提示，或自动给同色相的主题适配档。
  2. 预设规则现在只读（`editable={!isPreset}`），色钉死在定义处 → 只给用户规则换色卡碰不到问题本体。→ 改色入口挂在 **role/组** 上（一次改一档），不是逐条点 40 次。
- 与 §5/§6 的关系：色卡解决"能区分"，role 解决"改得动"，tier + 覆盖率上限解决"别糊屏"。三者缺一，满屏蓝都还在。

## 9. 不做的事

- 不引入 grammar/行级上下文引擎去复刻 WindTerm 的 prompt 档与字符串档——成本与收益不匹配，且会推翻现有"整条匹配一色"契约。
- 不把 105 条规则改成逐条色卡（用户不会点 105 次色卡，改色挂在 role/组上）。
- 不用"探针语料 0 命中"当删除依据（§1 的告警）。
- 不动 `config.keywords` 的扁平存储结构，只加字段（`tier` / `color` 允许 hex），老配置零迁移。
