## 一、①功能正确性

### 1.1 空 catch 吞错（确证）

静默吞掉异常会让功能"点了没反应"且无日志，本项目已有多次此类前科。

| 位置 | 现象 |
| --- | --- |
| `src/app/lib/db-tunnel.js:37, 67, 70` | 隧道 socket/ssh2 错误被空 catch 吞；失败时用户只看到"连不上"无原因 |
| `src/app/server/spice-proxy.js:213, 401` | 代理断链错误静默 |
| `src/app/widgets/instance-log.js:72, 93` | 实例日志读写失败静默 |
| `src/app/server/session-local.js:30` | 本地会话初始化失败静默 |
| `src/client/components/terminal/attach-addon-custom.js:372` | 终端 addon 异常静默 |
| `src/client/components/spice/spice-session.jsx:91` | SPICE 会话异常静默 |

**建议**：至少补 `log.debug`；db-tunnel / spice-proxy 这两个面向用户失败路径的应升为 `log.warn` 并可上报。

### 1.2 VNC `checkScreens` 无 gate（确证，前审计遗留）

`src/client/components/vnc/vnc-session.jsx:491, 495, 520` —— `onDesktopname` 每次事件、`onCapabilities` 每次 capabilities 都触发 `checkScreens()` → 无条件 `setState`。远端频繁广播 desktopname 时会反复重渲染。

**建议**：比对 screens 内容后再 setState（浅比较数组长度+首屏 id），或加 1s 节流。

### 1.3 未验证项（需真机，非代码缺陷）

- Redis 键空间页真机复测（前审计 §一-1，代码已提交）；

### 2.2 默认 AI 配置被上游改写（确证，需知悉）

## 七、⑦风险与可回滚性

### 7.1 上游合并成本（确证，**结构性风险**）

以下必须人工/CDP 验证，无自动化兜底：
- 全屏布局（本次改动区：右面板隐藏、GUI 远程桌面底栏）；

**建议**：沉淀一份"CDP 六场景验收清单"到 `doc/`，作为打包前固定动作。

### 7.3 回滚粒度（确证，健康）

近期提交均为单点小提交（如 `4c361d8b` 全屏底栏、`5434fab2` i18n），逐个 revert 即可；未见需要整批回滚的耦合改动。
