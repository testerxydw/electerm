## 2. SQL 编辑器与补全

### 实现光谱（从简到繁）

| 项目 | 做法 | 规模 | 关键缺陷/优点 |
|---|---|---|---|
| antares | Ace + store 驱动的字段补全 | ~100 行 | 无 token 扫描，最简；不支持上下文分类 |
| dbgate | Ace + `analyseQuerySources` token 扫描 | ~200 行 | 向前扫 `FROM/JOIN` 后 token 得源列表；**不支持 CTE/子查询** |
| DBeaver | 语义模型 + kind→priority 枚举 | 4171 行（11 文件） | 补全结果 = **替换区间 + 候选集**，非"插入文本"；kind 与优先级绑死 |
| DBX | 30+ 字段上下文对象 + 三层解析 | 7008 行 | 覆盖全部高频场景；踩坑记录最完整 |
| CloudBeaver | CM6 + 方言由元数据生成 | 装配级 | 装配方式可直接抄（见下） |

### 可直接落地的四个结论

1. **补全结果模型用 DBeaver 的**（`SQLQueryCompletionSet`）：一个**替换区间** `(from, to)` + 候选集，而不是"插入文本"。展示串与替换串分离（`displayString` vs `replacementString`），天然支持引号/别名前缀替换。
   优先级表（`SQLQueryCompletionItemKind` 构造函数 `(tableLike, columnLike, priority)`）：

   | kind | priority | 说明 |
   |---|---|---|
   | `JOIN_CONDITION` | 0 | 连接条件（写 JOIN 时最有用） |
   | 列类（`TABLE_COLUMN_NAME` 等） | 100 | |
   | 外键关联表 | 150 | |
   | 表/别名 | 200 | |
   | schema / catalog | 250 / 275 | |
   | 过程 | 300 | |
   | 关键字 | 400 | |
   | 伪列 | 500 | |

2. **上下文解析必须分三层**（DBX 的核心教训）：
   - `scanCteDefinitions` + `maskResolvedCteBodies`：把 CTE 体**挖空**再解析外层，避免 CTE 内部表污染外层作用域
   - `extractReferencedTables` → `{name, alias, columns}`；`extractSubqueryReferences` 合并 `(SELECT ...) t` 别名
   - **语句区间隔离**：按 `;` 切当前语句（跳过字符串/注释内的分号），多语句脚本只在当前语句内解析
   - **词法抑制**：`isSqlStringLiteralContext / isSqlCommentContext` → 光标在字符串或注释内**不弹补全**

3. **场景化补全是价值最高的部分**（DBX 逐项验证过）：`INSERT INTO t (` 只补该表列、`ON a.id = b.` 只补另一侧列、`ORDER BY` 优先补 SELECT 别名、建表时补数据类型。

4. **CM6 装配照 CloudBeaver**：
   - 方言由元数据生成（`SQLDialect.define({keywords, builtin, types, quote, hashComments...})`），用 `Compartment` 包住，**切引擎热替换不重建编辑器**
   - 编辑器 `React.lazy` 懒加载（CM6 ~250KB gz，不能拖慢不用数据库的 SSH 用户）
   - 补全快捷键 `Prec.high` 注册（`Mod-Space` 手动/Tab 接受），关掉自动补全时保留手动触发
   - 默认扩展用 flags 对象（行号/折叠/换行/高亮当前行…）逐项可关

### 必须规避的坑（DBX issue #12008）

补全要替换**含起始引号**的区间（`` `test_ ``）时，CM6 会拿文档文本（含反引号）去匹配候选 label（不含反引号），导致**候选全被过滤、菜单空白**。
处置：这类候选返回 `filter: false` 并由 provider 自带 `match` 区间；或把 `from` 抬到引号之后、把引号并入 `apply`。

## 3. 结果集与网格视角

- **DBeaver `DBDDataFilter`** 是"视角"的工业级定义：`constraints[]`（每列 `attribute/operator/criteria/visible/orderPosition`）+ 自由 `where` + `order` + `hiddenAttributes` + `dirty` 标记，派生 `hasFilters()/isDirty()/reset()`。一个模型同时解决**筛选、排序、列显隐、脏状态**四件事。
- **DBX 网格**（17,883 行）拆得清，可借鉴四点：手写 WHERE 与结构化条件用 `combineWhereInputs` 合并；`previewSqlText` 把**即将执行的语句拼给用户看**；`dirtyRows` + `commitBatch` 暂存编辑；`virtualRowIdentifier` 用列值组合定位无主键行。
- **Beekeeper `BuilderFilter.vue`（仅 101 行）** 给出正确交互形态：**默认构建器（列/算子/值三下拉）⇄ 一键切原始 SQL**，两者共用同一个 `whereDraft` 字符串。构建器只是"字符串生成器"，最终产物仍是 SQL 片段——接口契约不变，只是多一层人机友好入口。
- **dbgate `PerspectiveConfig`**：每表持久化筛选/排序/列显示格式。注意不能存 localStorage（本项目 UI server 动态端口导致 origin 漂移，`db-sql-history.js` 已记录该坑）。
- **写操作的安全交互**（Beekeeper/TablePlus）：按钮上直接显示 `{n} pending changes`；丢弃需二次确认；生产库用 **Safe Mode 挂在连接上**（书签级 `production`），而不是每次执行时问一遍。

## 4. 元数据与结构

**这是本轮最重要的发现：electerm 的功能缺口有一半是这个地基缺口的下游。**

| 事实 | 证据 | 被卡住的功能 |
|---|---|---|
| `describeTable` 只回 4 字段（`column_name/data_type/is_nullable/column_default`）+ 前端补 `is_primary_key` | `src/app/lib/db-client/postgres.js:149-172`、`mysql.js` 同构 | 数据字典、结构对比、ER 图、外键导航、表头注释 |
| 对象树只有 `database → [schema] → table`，**无视图** | `postgres.js` 的 `getMetadata` 仅查 `pg_tables`；MySQL 仅 `SHOW TABLES` | 只读视图查不了；对象树与竞品差一档 |
| `safeCell()` 把 `Uint8Array` 转成字符串 `<binary N bytes>` | `mysql.js:108-142`；导出走同一份 rows（`db-csv.js:22`） | **BLOB 列导出即数据丢失** |

- **pgAdmin `directory_compare.py`（940 行）** 的结构对比方案：把对象展开成**属性字典逐键比较**，而不是两份 DDL 文本做行 diff；忽略项（空白/属主/授权/表空间）是**比较参数**而非预处理。→ 单表结构对比应做属性级（列/索引/FK），DDL 只在"查看"里展示全文。
- **pgAdmin ERD**：`ERDCore.js`（868 行）用 dagre 自动布局，拖动时用节流标志吃掉重复事件；后端把 FK 从 oid 翻译成 `{schema, table, local_column, referenced}`。→ 只取"只读 + 自动布局 + FK 连线"，**不取正向工程**（会引入第二套建表逻辑，与"不做表设计器"冲突）；布局不引 dagre，FK 图天然分层，自写"入度 0 分层 + 层内按度数排序"约 80 行。
- **CloudBeaver `plugin-data-viewer-references`（579 行）** 外键侧栏：状态只有 `{associationId, presentationId, modelId}`；把 FK 列 → 源单元格值做映射，再新建独立数据模型查被引用表；展示层与主表格共享网格组件。

## 5. 值呈现与二进制

**CloudBeaver `ValuePanelPresentation` 是本轮最值得抄的架构**：注册项 = `{ key: 'application/json' | 'text/html' | 'application/octet-stream;type=hex'; name; isHidden(context) }`；组件全部懒加载；可用性判定分两处（看列类型 `isImageValuePresentationAvailable` / 看选中值是否 binary）；`MAX_BLOB_PREVIEW_SIZE` 给预览设上限；`isTextValueReadonly` 决定该视图只读。

对照 electerm：`db-value-pane.jsx`（291 行）+ `db-value-format.js`（`detectFormats`/`formatValue`，支持 json/python/xml/url）已覆盖文本类，缺**二进制/图片视图**、**BLOB 大小保护**、**二进制可编辑性判定**（现在只要 `editable` 就允许编辑，写回会损坏数据）。这不是新功能，是把现有组件重构成轻量注册表。

**ARDM** 的 `Viewer{Text,Json,Hex,Binary,Gzip,Brotli,...}.vue` 按内容探测自动切换，验证了同一思路；其 `KeyContent{String,Hash,List,Set,Zset,...}.vue` 按类型拆组件，是 Redis 类型化写的组织参考。

## 6. 导入导出与写操作

- **antares `BaseImporter`**（MIT，可直接改编）：`createReadStream({highWaterMark: 4*1024})` 4KB 块 + `EventEmitter`（`start/progress/cancel/error/end`）+ `emitUpdate({op:'cancelling'})` 支持取消。`SqlExporter` 带头尾 SET 语句；**PG 用 `pg-query-stream` 做游标流式导出**（不落 LIMIT 分页），MySQL 无 query-stream 故按 LIMIT 分块循环。
- **DBeaver `DataTransferPipe`** = `(Producer, Consumer)` 二元组，格式与通道解耦。Consumer 侧三个必抄开关：清空/覆盖语义、**冲突策略**（insert ignore / replace / upsert）、多行 INSERT 批大小。
- **DBX 迁移对话框**：模式 `append | overwrite | upsert | rebuild` + 每对象超时。
- **Navicat 数据/结构同步的六段式骨架**（值得抄"流程"不值得抄"产品"）：**差异 → 挑选 → 预览 → 重排 → 执行 → 记录**。这是"写操作类功能"的通用骨架，导入导出与危险确认都应沿用（预览在前、执行在后、结果可追溯），但**不实现差异计算**。
- **DBX `sqlRisk.ts`（480 行）+ `sqlExecutionDangerStore`（129 行）是本轮性价比最高的新功能**：
  - `splitSqlStatementsForSafety(sql, dialect)` 按方言处理引号/转义后切分（MySQL 反斜杠、PG `E''`、Oracle `q'[...]'`）
  - `sqlSafetyText` 先剥注释/字符串，防 `SELECT 'dir\'; DELETE FROM users;` 这类绕过
  - 分级 `read | write | ddl | transaction | unknown`，`EXPLAIN` 特判为 read
  - 待确认请求按 scopeId **记住本次批量决策**（上限 50），"一批 10 个目标只问一次，不同批次重新问"
  - `isScopedUpdate` 要求 WHERE 命中 `id/_id/uuid/key` 类列才算低风险写入，`WHERE 1=1` 判危险

## 7. 事务与写安全

**CloudBeaver `plugin-datasource-transaction-manager`** 服务层仅 28 行，价值在 UI 与语义：三个动作 `COMMIT / ROLLBACK / COMMIT_MODE_TOGGLE`；**事务日志弹窗**（时间/时长/语句，可点开 SQL 详情）；**连接级而非编辑器级**——同一连接上的多个查询共享一个事务。

**pgAdmin `MainToolBar.jsx`** 把 `auto_commit` 开关与 Commit/Rollback 按钮并列，验证了同一形态。
**TablePlus Code Review** = 变更清单，可与事务日志合并成同一面板。

对 electerm 是**真空白**（全仓 `autocommit|commit|rollback` 命中 0 次）。实现前提是"把连接钉住"（`db-client` 已有 `acquire/release`，但当前每 op 取用即还），属中等风险改造，因此排在最后。

## 8. 非数据库赛道：会话与多机

**先纠正一个认知偏差：electerm 在主战场并不落后，很多能力比竞品更全。** 不做这层盘点就会把已有功能误判成缺口。

### 已有且领先（不应重复造）

| 能力 | 证据 | 竞品对照 |
|---|---|---|
| 协议广度（SSH/Telnet/串口/本地/FTP/Web/RDP/VNC/SPICE） | `src/app/server/session-*.js` 14 个后端 | Tabby 无 RDP/VNC/SPICE；Wave 只有本地+SSH |
| 多跳跳板机 | `session-hop.js`（96 行）编译成 dynamic SOCKS5，供 VNC/RDP 复用 | Tabby 单跳；MobaXterm 单跳 |
| 端口转发三型 + 多条目 | `ssh-tunnel.js`（207 行） | 多数国产客户端只有 local |
| 终端内传输协议 | `zmodem.js`/`xmodem.js`/`trzsz.js` | Tabby 仅 zmodem |
| 会话录制（asciinema v2） | `session-recorder.js`：OSC 133/633 剥离、密码期避录、500ms/256KB 微批 | **Tabby/Wave/Termius 均无内置录制** |
| 触发器自动化 | `terminal/automation/`（1116 行） | Tabby 仅一次性 login scripts |
| AI Agent（工具调用+护栏） | `components/ai/` 30 文件 4402 行 | Wave/Warp 同代 |
| SFTP 文件比较 / 远程对远程 / cwd 跟随 | `sftp/code-compare.jsx` 等 | **FileZilla/WinSCP 无内建 diff** |
| 分块并发传输 | `transfer.js`：chunkSize + concurrency | WinSCP 单流为主 |
| 配置同步三通道 | `sync.js`：GitHub/Gitee/WebDAV | Termius 云同步付费 |

### 真实缺口（8 项，代码级确认）

广播输入、录制回放、SFTP 预览、远程归档、目录镜像、主密码密钥库、密钥生成/known_hosts UI、审计视图。

### 两个可模仿的实现

- **Tabby `multifocus.service.ts`（112 行）**：一个开关 + 一个 input 订阅 + 一条常驻提示 `Broadcast mode. Click anywhere to cancel.`；快捷键两个语义（跨 tab / 分屏内）。**退出靠"点任意处"比"再点一次按钮"更防误留**。
  electerm 的扇出点更简单——输入只有一个汇聚点 `attach-addon-custom.js:772 sendToServer(data)`（`onData`/`onBinary` 都汇于此）。但必须补 Tabby 没有的两道闸：**密码输入期不镜像**（可复用 recorder 的 `_passwordPromptDetected`）、**OSC 应答不镜像**。
- **Tabby `vault.service.ts`**：`PBKDF2_ITERATIONS=100000`、`sha512`、`aes-256-cbc`；`StoredVault{version, contents, keySalt, iv}`，密钥只在内存；`VaultSecret{type,key,value}` 的 secret 类型由插件自定义。
  electerm 现有 `lib/enc.js` 是"固定口令 + 每记录随机 salt"（**GCM 是对的，不要改成 CBC**），缺的是"口令由用户掌握"→ 保留 GCM，把密钥改成**主密码派生的 KEK 包裹 DEK**。

## 9. 非数据库赛道：文件与凭据

- **Wave `preview` 视图**：按内容分流（图片/PDF/Markdown/CSV/目录）+ `preview-streaming.tsx` 对大文件只渲染尾部。这是 SFTP 预览的正确形态。
- **electerm `readRemoteFile()` 的问题**：全量 `Buffer.concat + toString()`，**无 size 上限、无二进制分支**。10MB 图片或 1GB 日志会直接吃满内存。预览前必须先加 `readRemoteFileChunk`（`createReadStream({start, end})` + `stat()` 先取 size）。
- **Tabby `forwards.ts`**：转发是"对象列表"而非表单字段，有 `startLocalListener/stopLocalListener` 与 `toString()` 人类可读描述。electerm 有 `sshTunnels[]` 但**缺运行时启停与状态显示**。
- **Wave 视图注册表**：14 种 view 全部同构，加一个功能 = 注册一个 view。electerm 是"会话类型与渲染器硬绑定"，但**不必重构**——把预览/审计做成右侧面板组件而非新 session 类型，就能拿到同样的扩展性。
- **Wave `wsh`（30+ 子命令）**：把自己的一切能力暴露成命令行，AI 不需要专用插件。electerm 已有内置 MCP server（等价目标、不同协议），所以不新增功能，但提示：MCP 工具粒度应到 `sftp.read / sftp.write / term.send` 级，而非"打开一个 tab"。

## 10. 明确不做（附理由）

| 项 | 理由 |
|---|---|
| 数据同步（行级差异）、结构同步套件、跨库传输、备份还原、自动运行、BI、脱敏/数据生成、模型套件 | 需常驻调度器或独立产品面，与"SSH 客户端 + 轻量 DB 面板"定位不匹配 |
| ERD 正向工程（图 → DDL） | 等于引入第二套建表逻辑，与"不做表设计器"冲突 |
| 条件格式/色阶 | 规则模型（百分位/插值/多停靠点）成本高于收益 |
| 事务保存点/嵌套/跨 tab 事务 | 语义复杂且与连接池模型冲突 |
| 断线续跑（durable session） | 需在目标机部署 helper，与"随手连陌生服务器"场景冲突 |
