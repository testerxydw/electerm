## 1. S3-B · CSV 导出（P1，先行）

### 1.1 范围决策

**v1 只做「当前可见结果集」导出**（所见即所得）：
- MySQL/PG 数据网格：导出 `filteredRows`（含 T1 当前页过滤结果，未过滤时即整页）。
- SQL 结果：每个 result tab 可导出该结果集 `rows`。
- **不做全表导出**：大表需后端流式 + 进度 + 断点，属独立大项（与 SFTP 大文件传输同源问题），二期另立项；网格行虚拟渲染下"导出全部"本质是查询行为，混入 UI 会破坏"查找/过滤分工"（总览 §3.1）。

Redis 不接入（键详情分批加载无完整结果集概念），二期与 T12 一起考虑。

### 1.2 交互

- 网格头「导出 CSV」按钮：位于分页组之后（与刷新同组），无数据时禁用。
- SQL 结果 tab 头：`result N` 标签旁下载图标按钮。
- 点击即下载（无弹窗），文件名 `db-{database}-{table}-{yyyymmdd-hhmmss}.csv` / `db-sql-result-{n}-{ts}.csv`。
- 导出列 = 当前表头列（含列名行），值统一 `String(cell)`，`null` → 空串。

### 1.3 实现

- 新增公共纯函数 `src/client/common/db-csv.js`：`toCsv(headers, rows)`。
  - RFC 4180 转义：含 `,` `"` `\n` `\r` 的字段双引号包裹、内部 `"` 翻倍。
  - 文件头写 BOM `\uFEFF`（Excel 中文兼容）。
  - 行连接 `\r\n`。
- 下载走既有 `window.pre` 文件保存能力或 Blob + a[download]（与 SFTP 导出对齐，实现时核实现成 API 优先复用）。
- 无新 IPC、无后端改动。

### 1.4 验收

- 含逗号/引号/换行/中文/null/大数（bigint 不失精度，走 `safeCell` 已有逻辑）/Date 字段的表导出后可被 Excel 与 LibreOffice 正确打开。
- T1 过滤后导出仅含命中行；SQL 多结果集各 tab 独立导出。
- 单测：转义矩阵（引号翻倍/逗号/换行/BOM/空表头）。

## 2. S3-C · SQL 执行历史（P1）

### 2.1 存储设计

- `localStorage['electerm-db-sql-history']`，环形上限 **200 条**，超出丢最旧。
- 条目：`{ sql, dbType, dbHost, dbName, ts, ok }`——**不存结果、不存密码**（SQL 文本可能含敏感字面量，UI 明示"历史仅存本地"）。
- 连续重复（相邻同 sql）不重复入栈；失败语句也记录（`ok:false`，排查常用）。

### 2.2 交互

- SQL 编辑器上方工具行加「历史」按钮（与执行按钮同排）→ Popover 列表（时间倒序）：
  - 每条：首行摘要（截 80 字符）+ 相对时间 + 引擎/库标签 + 失败红点。
  - 点击回填 `sqlText` 并聚焦编辑器（不自动执行）。
  - 顶部「清空」按钮（二次确认）。
- 只读模式下历史照常记录（记录 ≠ 执行）。

### 2.3 实现落点

- `db-session.jsx` runSql 成功/失败分支各 append 一条（`:760-777` 附近）。
- 历史读写抽纯函数 `src/client/common/db-sql-history.js`（append/list/clear，供单测 vm 沙箱验证）。
- localStorage 读写做 try/catch（隐私模式/满额容错）。

### 2.4 验收

- 执行 205 条后仍为 200 条且最旧的被丢；相邻重复不叠加；清空后列表空。
- 切 tab 回来历史仍在（localStorage 持久）；重启后仍在。
- 单测：环形上限/去重/时间倒序/损坏 JSON 容错。

## 3. S3-D · quick-connect URI（P2）

### 3.1 交互

- 书签分组列表顶部「快速连接」入口 → Modal：URI 输入框（password 掩码显示切换）+ 「连接」。
- 解析成功 → 按 T4 临时 tab 模式直接连（**不写 bookmarks**），tab 内提供「另存为书签」按钮（预填后的表单走既有保存流程）。
- 解析失败：明确报错（不支持的协议 / 格式错误），不静默。

### 3.2 解析规则（纯函数 `parseDbUri(uri)`）

| scheme | 映射 | 备注 |
| --- | --- | --- |
| `mysql://` | dbType=mysql | 缺省端口 `dbDefaultPortMap.mysql`(3306) |
| `postgres://` `postgresql://` | dbType=postgres | 5432 |
| `redis://` `rediss://` | dbType=redis | path `/0` → `dbIndex`；rediss 置 `ssl:true`（表单无该字段则 v1 提示暂不支持 rediss） |
| 其他 | 报错 | 不支持协议 |

- `user:pass@host:port/db`；密码含特殊字符须 percent-encoding（`encodeURIComponent` 侧说明写进占位提示）。
- 输出：`{ dbType, dbHost, dbPort, dbUser, dbPassword, dbName }`（redis 为 `{ ..., dbIndex }`）。
- 临时 tab 构造复用 T4 的 clone(tab) 路径；密码只随 IPC 传递，不进 DOM 明文（掩码切换除外）、不进日志/标题。

### 3.3 验收

- 5 类 URI 解析正确（含缺省端口/无密码/无库名/redis db 序号）；特殊字符密码 round-trip 一致。
- 非 http(s)/ftp 等其他 scheme 明确报错；URI 错误不产生半成品 tab。
- 单测：解析矩阵 + 错误分支（纯函数，vm 沙箱）。

## 4. S3-A · 数据行增删 INSERT / DELETE（P1 价值最高，最后做）

### 4.1 现状与缺口

- 已有：`updateCell` 单元格 UPDATE（`mysql.js:266-285`，PG `$1/$2` 同模式）、主键检测（`Key='PRI'` / `is_primary_key`）、只读双检。
- 缺口：整行新增（INSERT）与整行删除（DELETE）。

### 4.2 后端设计（`OP_MAP` 扩 2 op，mysql + postgres 各自实现）

**`insertRow`**：参数 `{ database, schema, table, values: { col: val } }`
- `INSERT INTO db.table (c1, c2) VALUES (?, ?)`——列清单由 values keys 生成，全部 quoteIdent，值占位绑定。
- 至少 1 个非空列，否则报错；`schema` 仅 PG 使用。
- 返回 `{ affected }`（MySQL 可附 `insertId`）。

**`deleteRows`**：参数 `{ database, schema, table, pkColumn, pkValues: [] }`
- `DELETE FROM db.table WHERE pk IN (?, ?, ...)`。
- `pkValues` 上限 **200**（防误操作大范围删除 + IN 子句过长）；空数组报错。
- 复用 `checkWritable`；返回 `{ affected }`。

**无主键表**：`deleteRows` 直接拒绝（无法安全定位行），报错文案引导改用 SQL 页；`insertRow` 不受主键限制。

### 4.3 前端设计

- **添加行**：网格头「添加行」按钮（只读模式禁用；无主键仍可添加）→ Modal 按列清单（`describeTable` 结果已有缓存）生成表单：
  - 每列：文本输入 + 「NULL」checkbox（勾选后该列写 NULL）；数值列提交前数字校验；主键列为自增（`Extra: auto_increment`）时默认留空并标注"自增"。
  - 提交 → `insertRow` → 成功后刷新当前页 + toast `affected`。
- **删除行**：DbGridTable 加行选择（`rowSelection` checkbox）→ 选中 >0 时浮动条「删除 N 行」→ Popconfirm 二次确认（显示表名与行数）→ `deleteRows`（`__rowKey` 取主键值）→ 成功刷新当前页；只读禁选（或不显示 checkbox）。
  - 若 DbGridTable 现无 rowSelection，最小实现为行尾操作列「删除」单行入口（Popconfirm），批量勾选作为可选增强——实现时按现状取最小改动面。
- T1 过滤状态下的删除：按 `filteredRows` 选中的原始行 `__rowKey` 定位（过滤仅前端视图，不影响主键定位）。

### 4.4 验收

- MySQL/PG 有主键表：插入 1 行 / 删除 1 行 / 批量删除 N 行（N≤200），`affected` 正确。
- 无主键表删除被拒并提示；只读模式下主进程拒绝（渲染层隐藏入口 + 主进程兜底双重）。
- 值含引号/中文/NULL/Date 的 round-trip 正确；自增列留空可插入。
- `pkValues` 超 200 报错；值绑定全部占位符（单测断言无字符串拼接路径）。
- 单测：参数化构造（mysql 反引号 / pg 双引号）、只读/无主键拦截、IN 上限、NULL 语义。

## 5. 实施顺序与里程碑

**S3-B（CSV，最小零风险）→ S3-C（历史）→ S3-D（URI）→ S3-A（行级写，最谨慎）**；每项独立提交：改码 → `npx standard` → `npm run test-unit-ci` → `npm run compile` → CDP 实测（独立端口 9333 + DATA_PATH 隔离）→ 打包真机回归。

| 里程碑 | 交付 | 验证环境 |
| --- | --- | --- |
| M1 | S3-B + S3-C | 本机即可（连接失败态也能验证 SQL 历史；CSV 需真库或假数据页） |
| M2 | S3-D | 本机可测解析；连接验证走 192.168.115.67:13306 |
| M3 | S3-A | 需真实库（与 T9 真实库验证日合并：先 M3 后跑 T9 全链路，行级写必须在真库回归） |

## 6. 风险与边界

| 风险 | 缓解 |
| --- | --- |
| 行级写误删数据 | DELETE 仅主键 IN 定位 + 上限 200 + Popconfirm 二次确认 + `affected` 反馈；只读默认 |
| 大表全量导出诱惑 | v1 明确只导当前结果集，全表导出二期独立立项（流式 + 进度） |
| 历史泄露敏感 SQL | 仅存本地 localStorage + UI 明示 + 不存结果；后续可加"敏感语句排除"开关（待需求） |
| URI 密码暴露 | 掩码显示 + 不进日志/标题/DOM 明文；T4 密码边界规则直接沿用 |
| INSERT 类型错配 | v1 数值列前端校验 + 服务端类型错误原样透出（不预判全部类型，错误即报错不吞） |

## 7.1 B1 · 行级 INSERT/DELETE（沿用 §4，实施确认）

按 §4 后端设计执行（`OP_MAP` 扩 `insertRow`/`deleteRows`，占位绑定，`pkValues` ≤ 200，`checkWritable` 双检）。前端落点按 7.0 现状确认：

- **行选择**：`DbGridTable` 增加 `rowSelection` props 透传（checkbox 列），仅主数据网格传（结构/SQL 结果/Redis 不传）。`selectedRowKeys` 存 DbSession state，按 `__rowKey` 定位；切表/刷新页时清空。
- **添加行**：网格头 `[+ 添加行]` 图标按钮（只读隐藏）→ Modal 表单，列清单由 `structure.rows` 经**归一化函数 `buildInsertFormColumns(structureRows, dbType)`** 提取（两引擎字段名不同，返回 `[{name, type, isPk, isAutoInc}]`）：
  - 自增列默认留空并标注「自增」；每列带 NULL checkbox（勾选写 NULL）；数值列提交前数字校验。
  - 提交 → `insertRow({database, schema, table, values})` → 成功刷新当前页 + toast affected。
- **删除行**：网格头 `[删除选中(n)]` 按钮（`n>0` 才显示；只读/无主键隐藏）→ Popconfirm 二次确认（显示表名+行数）→ `deleteRows({..., pkColumn, pkValues})`（选中行的主键值）→ 成功清空选中 + 刷新当前页。
- T1 过滤不影响主键定位（沿用 §4.3）。

## 7.2 A1 · 复制为 INSERT / UPDATE / JSON / TSV（纯前端）

- **UI**：网格头导出按钮旁 `[复制▾]` Dropdown（CopyOutlined），菜单 4 项。
- **范围语义**：B1 已引入行选择 → **有选中行 = 仅复制选中行；无选中 = 当前可见结果集全部**（含 T1 过滤效果，所见即所得）。
- **格式规范**（表名 `sel.table`，标识符 mysql/tidb/oceanbase 反引号、pg 双引号；转义仅 `'\''`→`''` 翻倍，mysql 系额外 `\\`→`\\\\`；null→`NULL`，数字/bool 原样，Date→ISO 字符串）：
  - INSERT：`INSERT INTO \`t\` (\`c1\`) VALUES ('v');` 每行一条。
  - UPDATE：`UPDATE \`t\` SET \`c1\`='v' WHERE \`pk\`='k';` 每行一条；**无主键表该项禁用**（title 提示复用 dbNoPrimaryKey 语义）。
  - JSON：`[{...}]` 2 空格缩进，null 保留。
  - TSV：`\t` 分隔（值内 `\t`/`\n` 替换为空格），首行列名，贴表格软件。
- **实现**：纯函数 `buildCopyStatements(kind, {table, headers, rows, pkColumn, quote})` 放 `src/client/common/db-csv.js`（同文件：同属"结果集→文本"导出概念，同变化原因）；复制走既有 `common/clipboard` 的 `copy()`。
- 单测：转义矩阵（单引号/反斜杠/换行/中文/null/bigint）、无主键禁 UPDATE、选中/全页两分支。

## 7.3 A2 · DDL 查看（零后端改动）

- **范围**：v1 仅 mysql/tidb/oceanbase（`SHOW CREATE TABLE`，走既有 `executeSql` op，SHOW 在只读白名单内）。**PG 隐藏入口**：PG 无 SHOW CREATE，拼装 DDL 缺索引/外键/序列，半成品比没有更危险（诚实边界），二期独立设计。
- **UI**：structureArea 顶部加一行工具行 `[查看 DDL]`（仅 mysql 系显示）→ Modal：等宽 pre（`--db-code-font`）+ 复制按钮。结果取 `rows[0]` 的 `Create Table`/`Create View` 字段。
- **实现**：点击 → `executeSql('SHOW CREATE TABLE `db`.`table`')` → Modal 展示。零新 op、零新 IPC。
- 单测：DDL 提取纯函数（字段名兼容 Create Table/Create View）、非 mysql 系不渲染入口（源码断言）。

## 7.4 A3 · SQL 格式化（自写轻量 formatter，不引包）

- **实现**：纯函数 `src/client/common/db-sql-format.js` `formatSql(sql)`（~60 行）：
  - tokenizer 跳过 `'...'`/`"..."`/`` `...` `` 字面量，仅处理其外文本（防字符串内容被改写）；
  - 关键字大写（SELECT/FROM/WHERE/AND/OR/JOIN/ON/LEFT/RIGHT/INNER/GROUP BY/ORDER BY/LIMIT/UNION/INSERT INTO/VALUES/UPDATE/SET/DELETE/CREATE/TABLE 等）；
  - 主子句前换行 + 2 空格缩进；逗号不拆行（v1 保持简单）。
- **UI**：SQL bar 执行按钮后 `[格式化]` 图标按钮（小号）→ `setSqlText(formatSql(sqlText))`；快捷键 `Ctrl/Cmd+Shift+F` 挂进既有 `onSqlKeyDown`。
- 单测：关键字大写矩阵、引号内不替换、子句换行缩进、空串/纯空白容错。

## 7.5 A4 · 导出菜单化 CSV / JSON / SQL INSERT

- **db-csv.js 扩展**（不新建文件，同导出概念）：`toJson(headers, rows)`、`toSqlInsert({table, headers, rows, quote})`（复用 A1 的语句生成核心——**A1 的 `buildCopyStatements` 与 A4 共用底层行→语句函数，仅复制/下载出口不同**）；`downloadCsv` 内部 Blob 逻辑抽 `downloadText(filename, mime, text)` 通用化（downloadCsv 调它，既有 13 个单测不动仍过）。
- **UI**：两处导出按钮改 Dropdown：
  - 网格头（:1575）：CSV / JSON / SQL INSERT 三项（INSERT 用 `sel.table`）。
  - SQL 结果 tab（:1093）：CSV / JSON 两项（**无表名，INSERT 禁用**——生成 `INSERT INTO unknown` 无意义）。
  - 文件名后缀 `.csv`/`.json`/`.sql`，时间戳命名沿用 S3-B。
- 单测：toJson（null/嵌套字符串）、toSqlInsert 引号风格、downloadText mime。

## 7.6 实施顺序（更新 §5）

依赖链：B1 的 rowSelection 是 A1 选中态语义的前提 → 先 B1 后 A1；A4 与 A1 共用语句生成核心 → A1 先行。

## 7.8 风险与边界（增量）

| 风险 | 缓解 |
| --- | --- |
| 复制生成 SQL 被直接执行注入 | 纯辅助用途文本；值转义单引号翻倍 + mysql 反斜杠翻倍；不做隐式可信声明，UI 不引导直接执行 |
| DDL Modal 大文本卡顿 | SHOW CREATE 单行结果，pre 展示 + max-height 滚动 |
| 格式化改写用户 SQL 语义 | tokenizer 严格跳过引号字面量；格式化前 dirty 提示不做（Ctrl+Z 可回退，textarea 原生栈） |
| rowSelection 与 T1 过滤交互 | 选中按 `__rowKey` 持久，过滤仅视图隐藏不取消选中；删除仍按主键定位 |
| 网格头按钮拥挤 | 新按钮均为 icon+Tooltip 小号；db-page-filter 已可收缩（flex 0 1 132px） |
