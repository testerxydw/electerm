## 1. 结论摘要

1. **功能骨架已达业界"及格线"的大部分**。商业阵营总结的"人手一份且做得深 Top 10"里，本工具已达标 6 项、部分达标 3 项、仅 1 项整块缺失（表设计器）。此前多轮批次（H1/H2/H3/H4/H6/H7、F1/F2、E1/E2、R1、D 批类型化写、B 批收藏/AI）确实把清单吃掉了大半——**10-28 那份文档的缺口清单今天已大面积过期**。
2. **真正剩下的差距集中在四处**：① 编辑暂存模型（改数据不预览生成的 SQL、不能统一提交/回滚）；② 结构比较只"描述差异"不生成 DDL，因此表设计器无从落地；③ Redis 模块类型与运维盲区（无 JSON/Search/Vector/TS/bitset、无命令控制台、无 Cluster）；④ AI/MCP 这一新范式的**广度**（我们是"只读 5 工具"，业界已把连接/schema/执行/审批全暴露，且 MCP 已是 DBX / DBeaver / DbGate / DataGrip / SSMS 五家的标配）。
3. **一条安全短板必须优先补**：三个引擎的 TLS 全部硬编码 `rejectUnauthorized: false`（[mysql.js:22-23](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/mysql.js#L22-L23)、[postgres.js:22-23](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/postgres.js#L22-L23)、[redis.js:24-27](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/redis.js#L24-L27)）。加密但**不校验证书链**，等于对 MITM 不设防。业界（Navicat / DBeaver / TablePlus / pgAdmin）普遍提供 CA 文件 + 校验开关，这既是及格线项也是安全项，二者叠加使它成为本表唯一 P0 安全项。
4. **本工具有三处领先或独有，应当守住而不是被"对标焦虑"带走**：
   - **AI 产出默认不落执行**：`db_insert_sql` 只把 SQL 放进编辑器，人按运行再过 `confirmSqlRisk`（[mcp-handler.js:1658-1661](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/store/mcp-handler.js#L1658-L1661)）。这与 2026 业界共识（"AI 产出默认不落执行，写操作必须过人"，MongoDB MCP readOnly / DBeaver 可配置审批）**方向一致，且实现得比多数竞品更严格**。
   - **Redis 任意跳页**：`scanKeysToPage`（[db-session.jsx:4029](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/components/database/db-session.jsx#L4029)）+ 跳页告警阈值 `:249`。Redis Insight / Tiny RDM / ARDM **三家都只做顺序滚动、无跳页**。
   - **终端 + SFTP + DB 同上下文**：DataGrip / DBeaver 永远没有，是我们做 Agent 网关的独有组合优势。
5. **工程债本身是一项功能差距**：`db-session.jsx` 已到 **10228 行**，业界同代产品（DBX）已用分层 crate + CI 架构守卫把方言/驱动/编排拆开。不先拆，后续 N2~N5 每一项都会继续往同一个文件里堆。

### N1 · TLS 证书校验可配置 【P0，安全】

- **目标**：把"加密但不验证书"改成默认校验、可按需降级，并提供 CA 配置面。
- **对标**：Navicat / DBeaver / TablePlus / pgAdmin / SSMS 全部提供 CA 文件 + 校验开关（§4.4）。
- **现状**：[mysql.js:22-23](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/mysql.js#L22-L23)、[postgres.js:22-23](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/postgres.js#L22-L23)、[redis.js:24-27](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/redis.js#L24-L27) 三处硬编码 `rejectUnauthorized: false`。
- **改动层**：书签表单 + 连接构造 + 单测（+ 主进程 CA 读取）。
- **实现要点**：
  1. 书签字段新增 `dbSslVerify`（`none` / `ca` / `system`）与 `dbSslCa`（PEM 路径）。**默认 `system`**（走系统根）。
  2. 连接池键必须把校验模式与 CA 指纹纳入，否则同 host:port 不同校验会复用错连接——现有键格式是 `host:port:user:db|ssl=0|1`（[mysql.js:16-17](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/mysql.js#L16-L17)），要扩成三段。
  3. 旧书签（无该字段）按 `none` 解释并**保持 `false`**，避免升级即连不上自签内网盘；UI 明示"未校验证书"警告徽标。
  4. CA 文件读取失败给出可诊断错误（路径/格式），不静默降级为不校验。
- **验收**：① 自签 + 指定正确 CA → 连上；② 自签 + 校验开启不给 CA → **失败并报证书错误**（这条是关键回归）；③ 旧书签行为不变；④ 三种校验模式产生三条不同连接池键；⑤ 单测覆盖键构成与降级分支。
- **风险**：升级后既有内网用户可能连不上 → 用"旧书签默认 none"规避；密码/CA 路径不得进入日志与 DOM。
- **成本**：中。

### 10.1 N1 · TLS 证书校验可配置（2026-11-06 已完成）

**口径收口**：新增 `src/app/lib/db-client/db-tls.js` 作为三引擎唯一的档位解析（`none` / `system` / `ca`），
mysql / postgres / redis 三个适配器只负责把解析结果封装成各自驱动的选项形状（`ssl` / `ssl` / `tls`），
池键标记统一由 `tlsSigTag` 给（档位 + CA 文件内容指纹，换 CA 即换新池）。

**实现要点（都是踩过才写下来的）**：

- `none` 是旧书签的缺省档：`resolveVerifyMode` 对缺省/空/非法值一律回落 `none`，表单侧用
  `isNew ? 'system' : 'none'`（`bookmark-form/config/database.js`）。默认成 `system` 会让升级当天
  所有自签内网盘连不上，且没人会怀疑到"打开过一次表单"。
- **CA 读不到不降级**：`resolveTlsProfile` 返回 `error`，适配器在建连点 `throw`，绝不静默退回不校验。
- **mysql2 独有的 `verifyIdentity`**：mysql2 只在 `ssl.verifyIdentity` 为真时才校验证书身份
  （它把 `checkServerIdentity` 默认置成永远通过），node 的 pg/ioredis 在 `rejectUnauthorized`
  为真时默认就验。严格档位不给这个键，MySQL 侧会出现"链过了、名不对也照连"，所以档位解析里带
  `verifyIdentity`，只在 mysql 适配器摊开。
- **ioredis 吞真因**：建连失败统一报 `Connection is closed.`，验收②要求的"报证书错误"取不到，
  新增 `connectClient`/`withRealCause` 在建连这一步把 `error` 事件上的真实原因取回来
  （不改命令级错误，`db-session.jsx` 的失效连接判定 `CONN_ERR_RE` 不受影响）。
- 表单：`dbSslVerify` 下拉 + `dbSslCa`（复用库文件选择器组件，只换 filters 与文案）+ 风险说明 Alert；
  CA 空路径用**提交时取值**的动态 rule 拦住（不靠 `showWhen` 联动显隐，那个只比较 `dbType`）。

**验收对照**（§7 N1 的 5 条）：

| 验收 | 证据 |
|---|---|
| ① 自签 + 正确 CA 连上 | `self-test/db-tls-handshake.js` L1 真 TLS 握手 + L2 真实 ioredis 路径 `redis PONG` |
| ② 校验开启不给 CA → 失败并报证书错误 | 同上：`DEPTH_ZERO_SELF_SIGNED_CERT`、`Cannot read CA certificate file ... (ENOENT)` 两类都命中 |
| ③ 旧书签行为不变 | `self-test/db-tls-form-demo.js` D1–D5（真实页面：旧形状书签显示"只加密、不校验"，直接保存仍是 `none`） |
| ④ 三种模式三条池键 | handshake L3：关 TLS / none / system / CA₁ / CA₂ = 5 条互不相同，且不含密码与 CA 路径 |
| ⑤ 单测覆盖键构成与降级分支 | `src/test/unit-ci/db-tls.spec.js`（档位解析本体）+ `db-ssl-contract.spec.js`（三适配器用上口径的源码契约 + vm 里跑函数体） |

**测试规模**：`node --experimental-detect-module --test src/test/unit-ci/*.spec.js` → 4976 tests / 0 fail；
`standard` 干净；handshake 脚本 34/34、表单 CDP 实机 30/30。

所以"MySQL/PG 真库回归"不是真库跑的。替代做法是分三层：

**真正拍板的是四条口径**（不是行搬家）：

1. **预览文本 ≠ 可执行 SQL**。仓库里已经有两份"看起来能跑的 SQL"：导出/复制那套
   `buildCopyStatements`（按引擎引用标识符、值转义、能直接粘去执行）和 E1 危险确认那套

   模块头注释。

   变更集 = **暂存变更 / 应用**（前端内存，数据库一个字节都没动，关页面即丢）；
   F2 = **手动事务 / 提交 / 回滚**（已经执行进事务，服务端空闲会自动回滚）。
   叠加语义：手动事务开着时，"应用"就是把变更集当普通 op 发进去，于是这批语句同时出现在
