## 1. 结论摘要

1. **功能骨架已达业界"及格线"的大部分**。商业阵营总结的"人手一份且做得深 Top 10"里，本工具已达标 6 项、部分达标 3 项、~~仅 1 项整块缺失（表设计器）~~ **无整块缺失项**（该项 2026-11-08 由 N3a/N3b 收口为"受限表设计器"，计分以 §4.7 逐行为准）。此前多轮批次（H1/H2/H3/H4/H6/H7、F1/F2、E1/E2、R1、D 批类型化写、B 批收藏/AI）确实把清单吃掉了大半——**10-28 那份文档的缺口清单今天已大面积过期**。
2. **真正剩下的差距集中在四处**：① ~~编辑暂存模型~~（改数据不预览生成的 SQL、不能统一提交/回滚）——**已由 N2 收口**（§10.5/§10.6）；② ~~结构比较只"描述差异"不生成 DDL，因此表设计器无从落地~~——**已由 N3a/N3b 收口**（§10.8/§10.11，设计器仍受限：外键/分区/建表向导主动不做）；③ Redis 模块类型与运维盲区（无 JSON/Search/Vector/TS/bitset、无命令控制台、无 Cluster）；④ AI/MCP 这一新范式的**广度**（我们是"只读 5 工具"，业界已把连接/schema/执行/审批全暴露，且 MCP 已是 DBX / DBeaver / DbGate / DataGrip / SSMS 五家的标配）。
3. **一条安全短板必须优先补**：三个引擎的 TLS 全部硬编码 `rejectUnauthorized: false`（[mysql.js:22-23](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/mysql.js#L22-L23)、[postgres.js:22-23](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/postgres.js#L22-L23)、[redis.js:24-27](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/redis.js#L24-L27)）。加密但**不校验证书链**，等于对 MITM 不设防。业界（Navicat / DBeaver / TablePlus / pgAdmin）普遍提供 CA 文件 + 校验开关，这既是及格线项也是安全项，二者叠加使它成为本表唯一 P0 安全项。
4. **本工具有三处领先或独有，应当守住而不是被"对标焦虑"带走**：
   - **AI 产出默认不落执行**：`db_insert_sql` 只把 SQL 放进编辑器，人按运行再过 `confirmSqlRisk`（[mcp-handler.js:1658-1661](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/store/mcp-handler.js#L1658-L1661)）。这与 2026 业界共识（"AI 产出默认不落执行，写操作必须过人"，MongoDB MCP readOnly / DBeaver 可配置审批）**方向一致，且实现得比多数竞品更严格**。
   - **Redis 任意跳页**：`scanKeysToPage`（[db-session.jsx:4029](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/components/database/db-session.jsx#L4029)）+ 跳页告警阈值 `:249`。Redis Insight / Tiny RDM / ARDM **三家都只做顺序滚动、无跳页**。
   - **终端 + SFTP + DB 同上下文**：DataGrip / DBeaver 永远没有，是我们做 Agent 网关的独有组合优势。
5. **工程债本身是一项功能差距**：`db-session.jsx` 已到 **10228 行**，业界同代产品（DBX）已用分层 crate + CI 架构守卫把方言/驱动/编排拆开。不先拆，后续 N2~N5 每一项都会继续往同一个文件里堆。

### N1 · TLS 证书校验可配置 【P0，安全】

- **目标**：把"加密但不验证书"改成默认校验、可按需降级，并提供 CA 配置面。
- **对标**：Navicat / DBeaver / TablePlus / pgAdmin / SSMS 全部提供 CA 文件 + 校验开关（§4.4）。
- **现状**：[mysql.js:22-23](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/mysql.js#L22-L23)、[postgres.js:22-23](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/postgres.js#L22-L23)、[redis.js:24-27](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/redis.js#L24-L27) 三处硬编码 `rejectUnauthorized: false`。
- **改动层**：书签表单 + 连接构造 + 单测（+ 主进程 CA 读取）。
- **实现要点**：
  1. 书签字段新增 `dbSslVerify`（`none` / `ca` / `system`）与 `dbSslCa`（PEM 路径）。**默认 `system`**（走系统根）。
  2. 连接池键必须把校验模式与 CA 指纹纳入，否则同 host:port 不同校验会复用错连接——现有键格式是 `host:port:user:db|ssl=0|1`（[mysql.js:16-17](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/mysql.js#L16-L17)），要扩成三段。
  3. 旧书签（无该字段）按 `none` 解释并**保持 `false`**，避免升级即连不上自签内网盘；UI 明示"未校验证书"警告徽标。
  4. CA 文件读取失败给出可诊断错误（路径/格式），不静默降级为不校验。
- **验收**：① 自签 + 指定正确 CA → 连上；② 自签 + 校验开启不给 CA → **失败并报证书错误**（这条是关键回归）；③ 旧书签行为不变；④ 三种校验模式产生三条不同连接池键；⑤ 单测覆盖键构成与降级分支。
- **风险**：升级后既有内网用户可能连不上 → 用"旧书签默认 none"规避；密码/CA 路径不得进入日志与 DOM。
- **成本**：中。

### N2 · 变更预览与统一提交（staged diff）【P0，及格线 #2】

- **目标**：网格/单元格/加行删行的改动先累积为**待提交变更集**，展示生成的 INSERT/UPDATE/DELETE，确认后一次性提交，支持逐条撤销。
- **对标**：DBX `DataGridSqlPreviewDialog.vue`（提交前预览 INSERT/UPDATE/DELETE）、DBeaver change preview、DB4S / SQLiteStudio 全局 staged changes + Save All/Revert、HeidiSQL 待执行 SQL 预览、商业 Top10 第 2 项。
- **现状**：单格编辑 `:2193`、批量 `:2447`、加行删行**即时执行**；已有 F2 手动事务的连接级待提交清单（[db-session.jsx:2045](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/components/database/db-session.jsx#L2045)、`:9852`），可作 UI/心智基座。
- **改动层**：前端为主 + 复用 `updateCells/insertRows/deleteRows` 的 SQL 构造。
- **实现要点**：
  1. **不改后端 SQL 生成口径**：把既有语句构造函数抽出纯函数（键定位、参数化、标识符引用沿用 [safe-clause.js](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/safe-clause.js)），前端用它生成预览文本，**提交仍走同一批 op**，避免两套语义漂移。
  2. 变更集以"行主键 + 列"为单位，`Map` 存，重复编辑同格合并；无主键表**禁用暂存**（沿用"有主键才可编辑"边界）。
  3. 提交顺序：INSERT → UPDATE → DELETE（外键安全的最小版本），并复用 F2 事务包裹（`beginDbTx/commitDbTx/rollbackDbTx`，[index.js:777-885](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/index.js#L777-L885)）。
  4. 底部"变更 (n)"页签：逐条 SQL + 撤销 + 全部丢弃 + 提交；离表/关页签时**明确提示丢弃**（与既有 `.sql` 脏标记关闭告警同一手感，[db-session.jsx:2151-2191](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/components/database/db-session.jsx#L2151-L2191)）。
  5. 只读模式禁用整个暂存入口。
- **验收**：改 3 行 1 列 → 预览 3 条 UPDATE 且 WHERE 只含主键 → 提交后事务生效；中途撤销 1 条不提交；无主键表入口不可用；只读模式无入口；断线时变更集保留可重试；真库回归 mysql + pg 双引擎。
- **风险**：与 F2 事务清单**语义重叠**（一个是连接侧已执行未提交，一个是前端侧未执行）——必须在 UI 上分名分列，否则用户混淆两套"待提交"。**这是本项最大设计风险**。
- **成本**：中-高（建议拆 2 个提交：预览只读 → 提交/撤销）。

### N3 · 结构比较生成 DDL + 受限表设计器【P1，及格线 #5+#6】✅ N3a `e951397a` / N3b `33e760b4`（§10.8、§10.11）

- **目标**：先把"比较 → 可执行 ALTER"打通（N3a），再在其上加一个**只做列/索引/注释**的轻量设计器（N3b）。
- **对标**：Navicat / DBeaver / DBX(`ddl_profile` + `schema_diff.rs`) / pgAdmin / dbForge。
- **现状**：~~[db-structure-diff.jsx](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/components/database/db-structure-diff.jsx) 只描述差异；`getObjectDdl` 只读；无 ALTER 生成（§6 I11）~~

  `getObjectDdl` 仍为只读查看（DDL **编辑**未做，属本条剩余范围）。
- **改动层**：主进程（方言 DDL 生成）+ 前端（勾选与预览）。
- **实现要点**：
  1. **N3a 先行**：同连接两表 → 差异项每条挂一条候选 DDL，人工勾选 → 预览脚本 → 走 `executeSql` + E1 危险分级确认。跨连接比较后置。

- **改动层**：主进程 importer + exporter，前端对话框。
- **实现要点**：
  1. 先做 **JSONL 导入**（与 JSONL 导出严格对称，流式逐行，成本最低、收益最直接），再做 **SQL 导入**（分语句 + 多语句护栏，注意 PG 拒绝多语句）。
  2. **Excel**：需要新依赖（xlsx/sheetjs 家族），评估依赖体积与许可证后再定；列为 N4b 可裁。
  3. Parquet 明确**本轮不做**（依赖重、无既有场景）。
  4. 导入复用既有列映射 / upsert / 列转换管线，只加"源解析器"一层；解析器注册表化，与 `value-renderers` 同构。
- **验收**：导出 JSONL → 清空 → 导入 JSONL → 行数与内容一致（真库回归）；导入中途取消不留半截（沿用 upsert 与分批 [insert-batch.js](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/insert-batch.js)）；大文件不阻塞主进程。
- **风险**：新依赖引入体积与许可证审查；SQL 导入的多语句解析要与执行层一致，避免"解析器认为是一条、驱动认为是两条"。
- **成本**：中（N4a）/ 中-高（N4b Excel）。

### N5 · Redis 深度批次【P1，D3】

- **目标**：补 Redis 运维三件套 + 模块类型盲区里最常用的一档。
- **对标**：Redis Insight 3.x / Tiny RDM / ARDM 全部具备（§4.5）。
- **现状**：基础 6 类型 + INFO + 慢日志 + Stream 读 + 跳页已有；**无命令控制台、无 Profiler、无 Cluster/Sentinel、无大 Key、模块类型全缺**（已用代码核实：[redis.js](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/redis.js) 类型分支仅 6 种；grep `cluster|sentinel` 无）。
- **拆子项（按性价比排序）**：
  - **N5a 命令控制台**（低）：自由命令输入 + 命令名补全（复用 `db-quick-open` 的补全形态）+ 结果按 reply 类型呈现；写命令过只读护栏；**禁止** `FLUSHDB/FLUSHALL/KEYS`（沿用 [设计 §T12 不做清单](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/doc/已完成/数据库功能总览-2026-10-21.md#L410)）。
  - **N5b 大 Key / MEMORY USAGE**（中）：列 `MEMORY USAGE` + `SCAN`+`TYPE`+ 大小聚合的迷你 `--bigkeys`，带进度/取消/上限（对齐键树 10000 上限的既有纪律）。**Redis 三强里只有官方做了**，属差异化。
  - **N5c Profiler（MONITOR）**（中）：实时命令流，可暂停/过滤/复制；**MONITOR 对生产有性能影响，默认关 + 显式告警 + 只读连接可用**。
  - **N5d 模块类型 `RedisJSON`（`JSON.GET/SET`）**（中）：只加一档最常见的，Vector/Search/TS/Bloom 后置。
  - **N5e Cluster / Sentinel**（高）：ioredis Cluster 改动连接模型，**单列批次、需先评审**。
  - **N5f Pub/Sub**（低-中）。
- **验收**：每子项独立提交；控制台写命令在只读下被主进程拦截；大 Key 扫描可取消且分块 IPC 不阻塞事件循环；Cluster 首版只要求单入口多 slot 读。
- **成本**：低（N5a）→ 高（N5e）。

### N6 · 引擎级会话与状态（只读最小版）【P2，D1 ④】

- **目标**：在不重启"已被驳回的 H5"的前提下，补引擎侧可见性。
- **关键澄清**：10-28 驳回 H5 的理由是"`remote-monitor` 已覆盖主机进程"（[原文:106,248](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/doc/已完成/分析-功能差异与重点项目复核-2026-10-28.md#L106)）。**但 `SHOW PROCESSLIST` / `pg_stat_activity` 看的是"数据库会话与正在跑的语句"，与 OS 进程列表不同源、不等价**——主机侧看不到"哪条 SQL 跑了多久、被谁锁住"。业界（SQLyog/HeidiSQL/DBeaver/Navicat/pgAdmin）把它当标杆，属 D1 缺口而非重复建设。
- **边界（严格遵守）**：**只展示、不 kill**。给 `KILL` 就落入原驳回理由（高危低频）。用户要终止会话，走已有的主机级 `remote-monitor` 或直接执行 SQL。
- **改动层**：后端新增 2 个只读 op（`listSessions` / `getServerStatus`）+ 前端一个页签。
- **实现要点**：MySQL `information_schema.PROCESSLIST`（或 `SHOW FULL PROCESSLIST`）、PG `pg_stat_activity`；变量/状态用 `SHOW VARIABLES`/`SHOW ENGINE INNODB STATUS` 与 `pg_settings`/`pg_stat_bgwriter`；**必须过只读白名单**；默认不自动刷新（对齐 SQLyog 但把开关交给用户）；不显示 `information_schema` 之外的敏感变量值（如密码类变量在 MySQL 里本就不出现，仍加过滤）。
- **验收**：长跑查询时能看到 state/time/info 三列；只读模式可用；无任何 kill/终止入口；刷新可关。
- **成本**：中。

### N7 · 真实执行计划（受控 ANALYZE）【P2，完善 I3】

- **目标**：给出"估算 vs 实际"对照，同时不打开危险执行的大门。
- **现状**：拒绝 ANALYZE（[db-explain-tree.jsx:10](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/components/database/db-explain-tree.jsx#L10)）理由成立但过度。
- **实现要点**：新增**显式**"实测执行计划"开关，同时满足三个条件才允许：① 语句首关键词是 SELECT；② 非只读模式**且**二次确认（沿用 `confirmSqlRisk`）；③ 服务端加 `statement_timeout`/事务内 `ROLLBACK`（PG：`BEGIN; EXPLAIN ANALYZE ...; ROLLBACK`）。写语句一律拒绝，维持"保守双检"结论（[总览:432](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/doc/已完成/数据库功能总览-2026-10-21.md#L432)）。
- **验收**：`SELECT` 可实测；`EXPLAIN ANALYZE DELETE` 被拒；PG 实测后事务回滚不留副作用；MySQL 无事务时给明确提示。
- **成本**：中。**依赖 N8 的方言能力表**（`capabilities.explain_analyze`）。

### N8 · 方言声明化（能力位 + 类型改写 + DDL profile）【P2，D2 ⑥】

- **目标**：把"新增引擎只加一条记录"从**词表级**升级到**能力级**，为 N3/N7/N10 铺路。
- **现状**：[sql-dialects.js](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/client/common/sql-dialects.js)（311 行）已是"唯一真源"纪律的**正确起点**（文件头明确禁止组件另写关键字，`:1-11`），但内容只有关键字/引号/注释与类型建议，**缺能力位与类型改写**。
- **对标**：DBX `plugins/dialects/*.yaml` + `capabilities.rs` / `ddl_profile.rs` / `type_rewrite.rs`（Apache-2.0，可改编）。
- **实现要点**：每条方言记录扩三段——`capabilities`（多语句 / 跨库 / ANALYZE / 事务 / 游标 / 结构树深度 / 是否可暂存编辑）、`typeRewrite`（族间类型映射）、`ddlProfile`（ALTER 片段模板）。**前端按能力位显式降级 UI**（如 PG 的多语句开关灰掉并说明原因，直接解掉 §6 I8）。
- **验收**：单测断言"能力位驱动 UI 可见性"；新增一个假引擎记录即可跑通降级路径（不要求真连）。

### N9 · 大结果集与网格性能【P2，D2 ⑦+⑧，完善 I2/I7】

- **目标**：导出与浏览突破 LIMIT 分块的语义限制，虚拟滚动不再依赖高度测得。
- **实现要点**：① PG 服务端 cursor + fetch batch（pgAdmin 手法）或 `pg-query-stream`；MySQL 无 query-stream，维持 LIMIT 分块但记录快照口径。② 虚拟滚动改为"高度未知时也用虚拟列表 + ResizeObserver 回填"，与本仓库终端侧 `termBoxObserver` 同一套观察思路。③ 稳定行标识独立成 `db-row-identity.js` 纯函数，便于单测。

### 10.1 N1 · TLS 证书校验可配置（2026-11-06 已完成）

**口径收口**：新增 `src/app/lib/db-client/db-tls.js` 作为三引擎唯一的档位解析（`none` / `system` / `ca`），
mysql / postgres / redis 三个适配器只负责把解析结果封装成各自驱动的选项形状（`ssl` / `ssl` / `tls`），
池键标记统一由 `tlsSigTag` 给（档位 + CA 文件内容指纹，换 CA 即换新池）。

**实现要点（都是踩过才写下来的）**：

- `none` 是旧书签的缺省档：`resolveVerifyMode` 对缺省/空/非法值一律回落 `none`，表单侧用
  `isNew ? 'system' : 'none'`（`bookmark-form/config/database.js`）。默认成 `system` 会让升级当天
  所有自签内网盘连不上，且没人会怀疑到"打开过一次表单"。
- **CA 读不到不降级**：`resolveTlsProfile` 返回 `error`，适配器在建连点 `throw`，绝不静默退回不校验。
- **mysql2 独有的 `verifyIdentity`**：mysql2 只在 `ssl.verifyIdentity` 为真时才校验证书身份
  （它把 `checkServerIdentity` 默认置成永远通过），node 的 pg/ioredis 在 `rejectUnauthorized`
  为真时默认就验。严格档位不给这个键，MySQL 侧会出现"链过了、名不对也照连"，所以档位解析里带
  `verifyIdentity`，只在 mysql 适配器摊开。
- **ioredis 吞真因**：建连失败统一报 `Connection is closed.`，验收②要求的"报证书错误"取不到，
  新增 `connectClient`/`withRealCause` 在建连这一步把 `error` 事件上的真实原因取回来
  （不改命令级错误，`db-session.jsx` 的失效连接判定 `CONN_ERR_RE` 不受影响）。
- 表单：`dbSslVerify` 下拉 + `dbSslCa`（复用库文件选择器组件，只换 filters 与文案）+ 风险说明 Alert；
  CA 空路径用**提交时取值**的动态 rule 拦住（不靠 `showWhen` 联动显隐，那个只比较 `dbType`）。

**真正拍板的是四条口径**（不是行搬家）：

1. **预览文本 ≠ 可执行 SQL**。仓库里已经有两份"看起来能跑的 SQL"：导出/复制那套
   `buildCopyStatements`（按引擎引用标识符、值转义、能直接粘去执行）和 E1 危险确认那套
   `previewLiteral`（不引用、超长截断，只是给人核对的摘要）。变更面板**跟确认弹窗同源**，
   不跟导出同源 —— 否则同一格里"要改什么"在两处长得不一样，用户不知道该信哪个；而"能粘走的
   脚本"这件事已经由"复制为 INSERT"负责了。副作用是面板显示的是摘要不是脚本，这点写进了
   模块头注释。
2. **与 F2 事务清单分名**（本项最大设计风险，先把命名定死再写 UI）：
   变更集 = **暂存变更 / 应用**（前端内存，数据库一个字节都没动，关页面即丢）；
   F2 = **手动事务 / 提交 / 回滚**（已经执行进事务，服务端空闲会自动回滚）。
   叠加语义：手动事务开着时，"应用"就是把变更集当普通 op 发进去，于是这批语句同时出现在
   F2 的清单里，由用户决定何时 COMMIT —— 两套清单不是二选一，是一前一后两道。
3. **`planSubmit` 在事务内退化成逐格 `updateCell`**。主进程对手动事务里的 `updateCells`
   直接抛错（[index.js:622](file:///media/dp25/DATA/deb/fcitx5-deb/github/electerm/src/app/lib/db-client/index.js#L622)：
   它自管 `START TRANSACTION`，会把外层事务隐式提交）。所以"复用 F2 事务包裹"不是免费的：
   同一个变更集，事务外用 `updateCells` 合并成一条、事务内必须摊平成 N 条 `updateCell`。
   两种模式共用同一批 op 名与同一份参数形状，只是拆分粒度不同 —— 这条有单测钉着。
4. **删行与改格互斥**：暂存删除会撤掉同一行上尚未应用的单元格改动（返回 `droppedCells`
   给 UI 说明"有 N 条改动因删除作废"）；反过来往已暂存删除的行改格直接拒绝（`reason: 'deleted'`）。
   理由不是洁癖：留着会生成一条永远命中 0 行的 UPDATE，"影响 1 行"和实际 0 行对不上。

**顺带**：`db-session-const.js` 里 `from './db-engine-family'` 补成 `'./db-engine-family.js'`。
