## 二、分项七维度详析（仅风险≠零或需说明的项）

- ①正确性：纯改名，3 处 import + 导出名，逻辑零变化 ②③④：无涉 ⑥：正收益（名称与"通用会话壳"职责匹配）⑦：revert 单提交即回
- ⚠️ 唯一注意：styl 文件名同步改则 4 处注释引用一并改；保留旧名导出兜底可进一步降险（但最小实现原则下不建议双导出）

### S1 SessionBarActions（T2-1）
- ①正确性：**中**——telnet/web 为新增行为（现在整类缺失），动作提升为 props 后查找状态管理需与 store 单一来源对齐（session-control L54/287 已有 searchOpen 逻辑可搬）；telnet 从"关 bar"名单移出涉顶栏结构分支
- ②兼容：图标/token 全复用 ③一致性：**收益**（查找/全屏位三页对齐）④：tooltip+`:focus-visible` 必须随组件带走，否则新按钮裸焦点
- ⑥：动作单点 ⑦：组件独立文件，整体下线即回滚

### S2 高度 token（T2-2）——**本批最高风险主线项**
- ①正确性：**高**——session.jsx L244 `+ termControlHeight` 补偿与 CSS 高度强耦合，改错即复发"底部遮挡 33px"事故（10 月 12 日刚修，记忆有案）；标签栏 36/36/38 三数字收敛涉 tabs-wrapper 布局（曾有换行"自锁定"bug，`white-space: nowrap` 是根治防线不可动）
- ②③：token 化是收益 ④：无 ⑤：无
- ⑥：口径单点收益大 ⑦：**回滚中**——多文件联动（tokens/terminal.styl/db-session.styl/session.jsx/tabs.styl/store），revert 须整批
- 验收必须 CDP 六场景：终端/DB/分屏/全屏/web/rdp + DB 侧 `gapBelowBox === 0` 断言

### S6 db-code-font（T2-3）
- ①低 ②兼容：回落链 `tab.fontFamily → config.fontFamily → --font-mono` 必须三级兜底（浅色/无配置场景）③：收益 ④：`font-variant-ligatures: none` 对数据可读性正收益（防连字混淆 0/O、l/1）⑤：无 ⑥：+白名单 1 行 ⑦：低
- 待拍板随行项：树对象名是否同字体（建议一并，本次审计倾向直接做掉）

### P1-7 MySQL 元数据（T3-1）
- ①正确性：**中**——并发化后 pool 连接峰值升高，`SHOW TABLES × N 库`需限并发（≤4）；per-db try/catch 改失败语义（部分成功），树端需兼容"降级节点"（库名在、表列表标失败可重试）
- ②：无 ③：系统库过滤（information_schema/mysql/performance_schema/sys）改变树展示内容，建议做成可选开关（默认过滤）④：无
- ⑤：**正收益**（24 万行库实测场景的 N+1 串行是树加载慢主因）⑥：单函数内改造 ⑦：单函数级回滚
- 验证：真实库 192.168.115.67:13306（含 24 万行大表库）

### P2-19 超时区分（T3-2）
- ①中：阈值按操作类型映射（metadata 15s / query 60-120s / 导出类更长或不限），改动即改变慢库行为边界 ⑤：正收益（大表 SQL 不被 15s 误杀）⑦：常量表+单点引用，回滚易
- ⚠️ 需先 grep 所有超时引用点确认无隐式依赖

### xterm 稳定版升级（T4）——**全清单最高风险**
- 影响面：package.json 10 个 beta 包（含 fork 包 `@electerm/xterm@6.1.0-beta.292-electerm.2`）+ headless；渲染层 addon 全家桶（attach/fit/image/ligatures/search/serialize/unicode11/web-links/webgl）
- ①正确性：**最高**——reflow/alternate buffer/TUI 渲染行为全变；本项目深度耦合点：命令历史捕获（OSC 633 + manual 键入缓冲）、term-suggestions、search-bar 高亮、serialize 会话恢复、webgl 渲染器
- ②：终端主题 12 key 契约需复核 ④：光标样式/焦点环回归 ⑤：webgl 与 DOM 渲染器切换行为
- ⑦：回滚易（package.json revert+重装）但**回归面最大**——需独立专项：升级前先冻结回归清单（分屏/查找/历史/建议/TUI vim-htop/序列化恢复/拖宽 reflow 七项）
- 收益：根治 #4499 等 6 个渲染错乱 + TUI 丢帧（上游互证）；维持 beta 无升级路径，**晚做不如早做，但必须独立批次**

### 状态栏数据管线（T5-2）
- ①中：SSH 算法信息需从 ssh2 handshake 取，流量统计在 onData 高频路径聚合（本地计数+500ms 节流上报 IPC，**不可每包 IPC**）；zsh 版本走一次 exec
- ⑤：管好节流则无回归，管不好即新热点（这正是 FTP 节流项同类教训）⑦：UI 独立可下线

### ⌘R 录制（T5-4）
- ①中：onData 高频流直写文件需缓冲批量写（复用 T5-2 节流经验）；⌘R 快捷键与终端转义/浏览器刷新冲突需确认注册层
- ⑤：同上 ⑦：功能开关+文件落盘路径明确，可回滚

### 性能批次三 getter 签名缓存（T7-1）
- ①**中**：getter 签名变化即 re-render 语义变化，缓存失效边界错了是"界面不刷新"级静默 bug（本项目已有"静默失效"前科）
- ⑦：中——须全回归 + perf 守护单测反向验证

### 拆分标签会话 P0（T6）
- ①中：closeAllTabs/reopenClosedTab 涉 workspace 快照（恢复会话功能刚修过"本地标签 {type:'local'}"逻辑，交互面重叠）；原地拆分涉 Splitter 生命周期
- ⑦：功能增量、逐个提交可逐个回滚

## 三、重排逻辑与旧顺序差异

1. **微项聚合前置（T1 清扫批）**：原顺序把 P2-13/14/15、关键字 A 混在 DB 遗留大块里；这 5 项 + S0 + 2 个 XS 项全是 ≤1 提交、风险极低，聚成一个清扫批先清掉——一次打包验证，快速减表
2. **S0 提前进 T1**：原顺序 S0 是主线第一步，但它零行为变化，与微项同批不增加验证负担，还提前解锁 S1
3. **S2 风险标注升级**：原计划列为常规主线项；审计确认它是"底部遮挡"事故复发区，标注为本批最高风险主线项，CDP 六场景验收强制
4. **P1-7/P2-19 留 T3**：中风险 + 需真实库，不进清扫批
5. **xterm 位置不变（T4）但明确为专项**：风险最高、回归面最大，不与任何批混做；升级前先冻结七项回归清单
6. **UI 三条线内排序**：性能一-2（FTP 节流）提前到功能线首位（小改+为录制/状态栏的 onData 处理积累节流模式）；状态栏管线在 transfer/录制前（后两者部分复用其 IPC/节流模式）
7. **性能三/四殿后**：收益零散且批次三中风险，维持最后

## 四、一句话

**先清扫（S0+5 微项，7 个小提交一批打包）→ 主线 S1/S2/S6（S2 六场景验收盯紧补偿耦合）→ DB P1-7/P2-19 → xterm 独立专项（先冻结回归清单再动）→ UI 功能线（节流经验先行）→ 拆分标签/性能三/四殿后。**
