## 1A. 🔥 H1a · 网格可读性统一层（P0，第一优先）

> 触发：2026-10-28 用户反馈"SQL 结果页长内容列看不到——悬停无预览、列宽不能调"（`operation_log` 的 `parameter`/`detail`/`detail_en` 三列被切）。
> 复核结论：不是 SQL 页专属缺陷，**5 处网格同病**；4 个 SQL 引擎（mysql/postgres/tidb/oceanbase）共用同一 UI 层，一次投入全覆盖。

### 1A.1 根因（已回源码核验，行号基线 `master @ 806fe8e3`）

| 现象 | 根因 | 证据 |
|---|---|---|
| SQL 结果列宽不能调 | 列硬编码 `width: 220, ellipsis: true`，无 resizer 手柄、无 `onCell` | `db-session.jsx:3832-3839`（`sqlResultColumns`） |
| 长内容看不全、看不到结构、复制不出手 | **实测更正原判断**：原生 `title` 并非"恒空"——rc-table 在 `ellipsis` 下会给 children 是 string/number（或单层字符串元素）的单元格自动生成 title，内容就是格子里渲染出来的那段文本。真正的缺口是 ① 对象/JSON 列先被 `renderCell` 的 `JSON.stringify(v).slice(0, 200)` 截掉，title 只剩 200 字符；② 浏览器 tooltip 的出现延迟、配色、能否选中复制全部不可控，还和预览卡叠成两套浮层；③ 数据页 td 的 title 早被 `dbPreviewHint` 占用 | `@rc-component/table/es/Cell/index.js:10-27`、`db-session.jsx:3544-3568`；CDP 改前实测：纯字符串格 title 长达数千字符、`parameter` 对象格 title 只有 200 字符片段 |

### 1A.3 H1a-1 · 共用展示层（≈230 行）

> **2026-10-29 修订**：本节描述的悬停预览卡与"查看完整"弹窗已整体下线（组件删除、5 处网格的 `onCell` 只保留选中/编辑），现行方案见 §1A.12。保留下来的只有纯函数层（`fitColumnWidths` / `cellText`）与 `CELL_ELLIPSIS`（关掉 rc-table 自动生成的原生 title）。以下内容按历史记录保留。

**新增纯函数** `src/client/common/db-column-width.js`：
```
fitColumnWidths(rows, keys, { sample = 100, min = 90, max = 360, charW = 12, pad = 32 })
  → { [key]: width }          // 与数据页现有采样公式同构，数据页反向复用
cellText(v)                    // NULL→'NULL'、二进制信封→'<binary n bytes>'、
                               // 对象→完整 JSON（不截断）、其余 String(v)
```
- 数据页 `columnWidths`（`db-session.jsx:3573-3590`）改为调用 `fitColumnWidths`，公式与上下限不变 → 现网列宽观感零漂移。

**新增组件** `src/client/components/database/db-cell-preview.jsx`：
- **全站单例**受控 Popover（挂 `db-session` 顶层一次，非每格一个）：`trigger={[]}` + 受控 `open={!!state}`，锚点是跟随单元格左下角的 `position: fixed` 元素（`pointer-events none`、**1×1 而非 0×0**，见 §1A.8 踩坑 9），`state = {x, y, col, text}`。
  - 不设 hover 进延迟：卡片只在"真被截断"时出现，本身已是低频事件；再加 0.35s 只会让"看不全"的时候还要等。
  - 反向要有 200ms **关闭缓冲**（`scheduleHide`/`cancelHide`），否则指针从单元格移进卡片的路上就关了，选不中也复制不了。
- 内容：列名 + `N 字符` + 值（等宽 `--db-code-font`、`max-height 320px` 滚动、关键字高亮走 `highlightValue`）+ "复制"（复制的是全文，不是裁剪后的预览）；>4000 字符（`PREVIEW_MAX`）截断并提示"复制可取完整内容"，全文出口在 H1a-4 的"查看完整"。
- 只在**真被截断**时弹：`onMouseEnter` 读 `ev.currentTarget.scrollWidth > ev.currentTarget.clientWidth`；否则不 setState（避免 hover 风暴）。
- DOM 数不随行数增长：单例 + 每格只挂 `onMouseEnter/onMouseLeave` 两个 handler（antd Table 直接把 `onCell` 摊到 `td` 上，不额外包一层）。
- 关闭时机：Esc、任意滚动（capture 阶段）、指针离开且缓冲到期、**源单元格消失**（切页签/虚拟滚动回收，`watchCell` 用 ResizeObserver 盯住那一格：`isConnected` 为假或 `contentRect` 宽高归零即关卡）；组件卸载清定时器与 observer。
  - 最后一条是实测补的：切页签把网格整块 `display:none`，浏览器**不会**派发 `mouseout`，卡片会带着旧坐标浮在新页面上（锚点 `left` 停在上一格的像素值）。
- 浮层 `destroyOnHidden`（antd 6 里 `destroyTooltipOnHide` 已废弃）：关闭即卸载，DOM 里不留"藏起来的上一次长文本"，也让"卡片在不在 DOM"成为可信的测试判据。

**统一单元格契约**（5 处网格同一改法）：
```
column.ellipsis = CELL_ELLIPSIS               // { showTitle: false }：保留 overflow hidden（scrollWidth>clientWidth 才是"真截断"），关掉 rc-table 自动生成的原生 title
column.onCell   = row => ({ ...原有 handlers, ...previewProps(col, row) })
previewProps = useCallback((col, row) => ({ onMouseEnter, onMouseLeave }), [show, scheduleHide])
```
- **实施更正 1（不设 td 原生 `title`）**：原设计准备 `title: cellText(v)`，落地时取消。两个原因：
  1. 列 memo 的依赖里带 `editValue`（行内编辑每敲一个字符就重建一次列定义），给整页 200 行 × 每列算 `cellText` 会把 30KB JSON 的重复序列化挂在编辑热路径上；文本改到悬停时算一次（`show` 内），代价只有一次 hover。
  2. 原生 tooltip 与预览卡会在同一指针下叠出来（悬停 ~1s 后两套同时显示），互相遮挡。
- **实施更正 2（`ellipsis` 不能用布尔 `true`）**：原设计以为"`renderCell` 恒返回 `<span>` 树 → rc-table 不生成 title，写 `true` 即可"。CDP 实测推翻：`@rc-component/table/es/Cell/index.js:10-27` 里 title 的生成条件是"children 是 string/number，**或单层元素且其 `props.children` 是字符串**"，纯字符串列与浅层 span 都命中（`renderCell` 只在命中高亮关键字时才包多于一层的 span 树），改前实测那些没被包层的单元格挂着数千字符的长 title。因此 5 处网格的 12 个列统一改为共享常量 `CELL_ELLIPSIS = { showTitle: false }`（`ellipsis` 仍是真值 → `Table.js:419-433` 的 `layout: fixed` 判定不变，虚拟网格布局零漂移）；表头不受影响，rc-table 对 header 行无条件生成 title。

### 1A.4 H1a-2 · 列宽可控（设计 ≈150 行，实落 294 + 63 + 网格接线）

- **手柄与菜单全站只有一份实现**：新增 `src/client/components/database/db-col-resize.jsx`，导出 `useColWidths`（三源优先级 + 提交落点）、`useColMenu`（菜单状态与落点）、`ColHead`（列头 = 标题 + 拖拽提示 + 右边缘手柄）、`DbColMenu`（受控菜单）。4 处 memo 化网格（数据页 / SQL 结果 / 表结构 / Redis 键列表）的列头统一换成 `<ColHead>`，写死的 `width: 220 / 200` 全部下线。
- **三源优先级**（`pickColumnWidth`）：拖拽中 `live` > 手动宽 > 自适应宽 > `COL_W_FALLBACK`(90)。手动宽只在**抬起鼠标**那一次提交（`withManualWidth`）；拖拽的每一帧只更新 `live`，一次都不写盘 —— 否则一次拖拽放大成几十次落盘。
- **落点分两类（决策 11）**：数据页 → `patchViewColumns`，进 `db-grid-views.json`（切表回来还在）；SQL 结果 / 表结构 / Redis 键列表 → 各自的 `useState` 内存 map，一次都不碰视角（结果集的列随查询变，存进视角只会攒脏宽）。
- **上下限分两套**：自适应档 `COL_W_MIN 90 ~ COL_W_MAX 360`（"加宽"目标 `COL_W_WIDE 720`）与手动拖拽档 `COL_W_DRAG_MIN 60 ~ COL_W_DRAG_MAX 1200`（`clampDragWidth`）。自适应要"别把表格撑爆"，手动要"用户说了算"，一套上下限管两件事会两头不对。
- **菜单三项**：`自适应本列`（删掉这一列的手动宽）/ `加宽到 {n}`（标签里的数字就是实测目标宽 `wideColumnWidth`，点下去必得这个值，不是"再算一遍"）/ `自适应全部列`（清全部手动宽）。工具行的"自适应全部列"与菜单第三项同动作，且**只在有手动宽时可点**（没拖过时按下去不会有任何变化，禁用比"点了没反应"诚实）。
- **操作提示进列头**：`dbColResizeHint`（"拖动右边沿改宽，右键更多"）；数据页与预览提示拼成 `单击预览，双击编辑 · 拖动右边沿改宽，右键更多`。手柄本体默认不可见，hover 才显出 2px 竖线 —— 看不见等于没做。

### 1A.5 H1a-3 · 字段类型契约（≈120 行，跨引擎）

- **形状选择（工程判断，替代 TODO 里"只改 fields"的写法）**：`fields` 保持字符串数组不动，**新增并列** `columns: [{ name, type }]`。理由：现有 `fields` 消费方 3 处（列生成 `:3830`、CSV 头 `:2397`、Excel/JSON 导出）都按字符串用，改成对象会同时炸三处且需要兼容层；并列新增是纯增量、旧调用零风险。
- mysql：`toResult`（实落 `mysql.js:1051`）取 mysql2 `FieldPacket.columnType`，并把整只 `FieldPacket` 一并交给归一函数（`TEXT`/`BLOB` 同为 252，必须靠 `characterSet` 分流）；postgres：`executeSql`（实落 `postgres.js:1029`）取 `r.fields[].dataTypeID`。
- 新增纯函数 `src/app/common/db-type-normalize.js`（216 行）：`normalizeMysqlType(columnType, meta)` / `normalizePgType(dataTypeID)` / `toColumns(driverFields, normalize)` → 归一到 **数据页那套 `DATA_TYPE` 口径名**（`int`/`varchar`/`bigint`/`decimal`/`datetime`/`date`/`json`/`blob`/`bytea`/`timestamp`…），映射表逐码取自驱动常量，未知码、非整数、数组 OID 一律回落 `''`（当字符串处理，绝不猜）。
- 前端两处消费：`sqlColTypeMaps`（`db-session.jsx:3894`，每个结果集一张 name→type 小写表）喂给 `renderCell(v, '', dataType)`，从而启用数值右对齐（与 U2 重叠项归此批）、日期本地化、二进制 `<binary n bytes>` 呈现；右对齐判定收敛成 `cellAlignClass(dataType)`（`db-format-value.js:96`），数据页与 SQL 结果页共用同一条。
- **偏离设计的一处**：右对齐走 **td 级 class**（`.db-cell-num`）而不是 antd 的 `column.align='right'`，因为后者会连表头一起右对齐，而表头右边沿正是 H1a-2 的拖拽手柄热区（`right:0` + `z-index:2`）。理由写进了 `db-session.styl` 与 CSS 契约测试。
- Redis 不注册本 op；tidb/oceanbase 复用 mysql 适配器自动生效。
- **顺带清掉的真 bug**：SQL 结果列原先写 `render: renderCell`，antd 传的 `(值, 整行, 下标)` 把**行下标当成 dataType**，等于每格都在格式化一个不存在的类型名（"看起来没格式化"的根因）；改成显式 `render: v => renderCell(v, '', dataType)` 后，Redis/结构页那些无需类型的列也一并显式化。

**验收**（达成情况见 §1A.10）：`db-type-normalize.spec.js`（每个驱动码都要么进表要么进"刻意不映射"清单 + 未知回落 + `TEXT`/`BLOB` 分流 + 数组 OID）；适配器单测断言 `columns` 与 `fields` 等长同序、多结果集互不污染；CDP `self-test/db-sql-type-contract-demo.js` 用假 adapter 实测数据页与 SQL 结果页的对齐/本地化/二进制/多结果集隔离；真库 MySQL `tgfsom`（`SELECT id, amount, created_at, JSON_COLUMN, blob_col` 数值右对齐、日期本地化、JSON 可格式化预览）—— **待环境**（本机无容器运行时、无 mysqld/pg，`192.168.115.67:13306` 不可达）。

**踩坑（写下来防止重复）**：

1. **`npm run compile` 不同步 `src/app`**。词条加在 `src/app/common/locales-extra.js` 后，运行时读的是 `work/app/common/locales-extra.js`（由 `src/build/bin/prepare.js` 的 `cp -r 'src/app' 'work/'` 负责），compile 只做 vite 构建 + copy icons + pug。所以主进程侧改动要手工 `cp` 一次并重启 electron，否则界面上是 `DbCellChars` 这种 title-cased 裸 key —— 截图上很难看出来。
2. **CDP `Input.dispatchMouseEvent` 不带 `button: 'left'` 时不会合成 click**。默认值是 `"none"`，按下/抬起都发出去了、React 的 `onClick` 一次都不触发，"预览卡抢走了单击"这类回归判据会假失败。修好后同一坐标的 DOM `click()` 与真鼠标点击表现一致。
3. **切页签不会有 `mouseout`**：网格整块 `display:none` 时指针离开事件根本不派发，卡片带着旧坐标浮在新页面上。判据是锚点 `style.left` 停在上一格的像素值（`state ? x : -1`）—— 由此可区分"state 没清（逻辑问题）"与"state 清了但浮层没收（动画/portal 问题）"。
4. **虚拟滚动的行会被回收**：滚出可视区的目标格在 DOM 里消失，按文本前缀反查单元格的测试必须先把滚轮反向补回去（`deltaY: -120`）再重新量坐标；antd 6 的虚拟 Table 产物里没有 `.rc-virtual-list-holder` 类名，靠类名找滚动容器这条路不通。
5. **夹具行数会影响可测性**：只放 2 行时滚轮不产生滚动事件，"滚动关卡"这条测不到；补到 30 行才有真实滚动。
6. `destroyTooltipOnHide` 在 antd 6 已废弃，用 `destroyOnHidden`。
7. 测试里"前置条件"必须自证：指针一直在同一格上不会重新派发 `mouseover`，React 不会再触发 `onMouseEnter`，于是"切页签前卡片是开着的"假失败、而依赖它的下一条断言又**假通过**。改成先移开再移回来，并把前置条件 AND 进真正的断言里。
8. `assert/strict` 的 `deepEqual` 是 deepStrictEqual，跨 `vm` realm 比较对象会因原型不同而失败 —— 比字段、比 `Object.keys`、比 JSON 字符串，别比对象身份。
9. **`0×0` 的 fixed 锚点会让浮层永远停在屏幕外**（本轮最贵的一课，也是唯一靠截图才发现的 bug）：锚点原设计是"不占位的 0 尺寸 fixed 元素"，结果 `@rc-component/trigger/es/hooks/useAlign.js` 在定位前有一道 `isVisible(target)` 闸门（`@rc-component/util/es/Dom/isVisible.js`）—— 它依次看 `offsetParent`（**fixed 元素恒为 null**）、`getBBox`（HTML 元素没有）、`getBoundingClientRect()` 的宽高（**0×0 → 假**），三条全灭 → `onAlign` 直接 `return` → `useOffsetStyle.js` 把浮层停在初始的 `inset: -1000vh auto auto -1000vw`。表现是"卡片内容全对、`opacity: 1`、`display: block`、class 里带 `placement-bottomLeft`，但 rect 在 (-15990, -9990)"，**用户一个像素都看不到**，而所有基于 DOM 存在的断言全绿。改法：锚点 `width/height: 1px`（透明、`pointer-events none`，视觉等价 0）。
   → 由此立规矩：**浮层类组件的验收判据必须是"画在视口内 + `elementFromPoint` 命中自己"**（`__cardOnScreen`），"DOM 里有这个节点"只能当辅助信号；`destroyOnHidden` 让这条判据可信，但它管的是"关掉的卡不留 DOM"，管不了"开着的卡在屏幕外"。

**踩坑（写下来防止重复）**：

1. **可排序列的手柄必须整条落在裁剪框内且 `z-index ≥ 1`**（本轮唯一的产品级真 bug）。antd 6 可排序列头结构是 `th(relative, overflow:hidden) > .ant-table-column-sorters > [.ant-table-column-title(relative, z-index:1, overflow:hidden) > 我们的 .db-col-title] + .ant-table-column-sorter`，另有一层 `.ant-table-column-sorters::after{position:absolute; inset:0}` 盖在上面吃掉指针。原设计把 16px 热区居中放在列边界上（`right:-8px`）—— 外半条被 `overflow:hidden` 裁掉，`elementFromPoint(手柄中心)` 命中的是排序遮罩；再叠加 `z-index:auto` 被 `::after` 压住，**可排序列 100% 拖不动，而非排序列一切正常**（所以截图和"看起来没问题"都发现不了）。改法：`right:0` + `z-index:2`，并把它写进 CSS 契约测试（`right` 必须为 `0`、`z-index ≥ 1`、`width ≥ 12`、`cursor: col-resize`、必须有 `&:hover::after`）。
2. **手柄看不见 = 没人会去拖**。热区默认透明，只靠"右边沿能拖"这种隐性知识不成立，因此列头 `title` 里必须带 `dbColResizeHint` —— 这条也写成了测试（每个 `<ColHead>` 挂载点都要有 `hint`，数据页还必须有预览/编辑提示），否则下一次改提示文案就会把它丢掉。
3. **`colgroup` 里的宽度是布局后的宽度，不是配置宽度**。`scroll.x='max-content'` 使 `table-layout:fixed; min-width:100%`：当 `Σ配置宽 ≤ 容器` 时浏览器把剩余空间摊给各列（配置 360 实测 444），rc-table 又把实测值写回 `colgroup` → `used === specified === 布局后宽`。所以精确数字（360/720/60/90）只有两种可信断言处：**(a)** 先把 `Σ配置宽` 顶过容器（`stretch=0`）再量 DOM；**(b)** 读 `db-grid-views.json` 的落库值（配置的真值）。摊宽体制里只能断言 `used ≥ 配置宽` 与"没被撑爆"（`tableW ≤ wrapW + 2`）。
4. **CDP 输入的两条硬规矩**：`mousePressed` 落在视口外会被直接丢弃（拖宽列要先 `__scrollColIntoView` 把列横向滚进来，并把 `scrolled` 记进失败详情）；`mouseWheel` 在**上一次记录的指针位置**派发 —— 右键完列头之后指针在表头上，此时 wheel 不会滚表格体，`Cdp.wheel()` 必须先补一个 `mouseMoved`。
5. **CDP 冷启动的首次 hover 偶发不出卡**：同一份代码上一轮全绿、下一轮第一个格子不出卡（第二个起全绿），是外部 Chrome/Electron 指针冷启动抖动。处理是给 `hoverCard` 最多两次重试（先移回 (5,5) 再移回目标），**只补偿测试环境，不放宽"截断格必须出卡"这条判据**。
6. **antd 6 的三个类名/动画事实**：`Select` 没有 `.ant-select-selection-item`，选中文本在 `.ant-select-content`（读 `innerText` 最稳）；弹层入场首帧 class 是 `ant-zoom-big-appear-start` = `scale(0)`，矩形 0×0，必须**轮询到画在视口内**再量，不能采一次样；`destroyOnHidden` 才是不留隐藏节点的那个。
7. **虚拟网格的 DOM 行数 ≠ 每页行数**：拉到 200/页后 `.ant-table-row` 实测只有 46~67 行（只渲染视口 + buffer）。任何"设成功了没有"的判据都不能数行，要读下拉选中值；`.ant-table-tbody-virtual-holder` 是 `overflow:hidden` 且确实派发 `scroll`（`scrollHeight 7600 / clientHeight 298`），所以滚动探针要接受 `hidden`，否则报 `no-scroller`。
8. **落库要等防抖**：视角写入是 400ms 防抖，读 `__viewDump()` 前至少 sleep 600~700ms，否则"拖完落盘"假失败。
9. **探针一律返回 JSON 字符串**：`waitFor` 的表达式必须写成 `JSON.parse(window.__cardInfo()).open === 1`，直接 `.open` 取到 `undefined` 会等满预算再判假；把 DOM 判据拼成字符串正则时别用 `"\\b"`（模板吃掉一层退化成退格符），改前缀匹配，且 `20 / 页` 与 `200 / 页` 前缀冲突 —— 匹配串要带上数字后面的那个空格。
10. **产品根类是 `.db-session-wrap`，`.db-session` 不存在**：文档级 `querySelector` 会把同时挂载的多个 db-session 子树一起数进来（实测"锚点 2 个"假象）。所有探针按可见性 + 会话根作用域过滤。
11. **实测环境会污染开发者配置，检查必须自己钉前置条件**：带 `--remote-debugging-port` 的 dev 实例仍复用真实 `~/.config/electerm`（`HOME=` 隔离不生效），而且**端口被占时新进程 `bind() failed` 直接退出，harness 连上的是上一轮那台还活着的实例**。后果：上一轮把每页行数拉到 200 留在 config 里，这一轮 stub 的 200 行正好一页 →"下一页"按钮合法置灰 →"翻页保留列宽"失去可测对象。修法是让检查自己把页大小钉回 20 并把 `pageNext === 'ok'` AND 进判据（前置条件不成立就红），跑完再还原 config —— 而不是指望环境干净。
12. **`pkill -f "…work/app/app.js"` 会杀掉我自己的 bash 包装进程**（包装的 cmdline 含这段字面量，表现为 exit 143 且后续命令没跑）。正确姿势：`pgrep -f "app[.]js --remote-debugging-port"` 单独一步拿 PID、按 PID `kill`，启动放在另一次调用里。

**踩坑（写下来防止重复）**：

1. **`render: renderCell` 会把行下标当成 dataType**（本轮的真 bug）。antd 的 `render` 签名是 `(value, record, index)`，直接挂函数引用时第三个参数就是行号，`isNumberType(0)` 恒假、`isDateType(0)` 恒假 —— 表现是"这一列死活不格式化"，看起来像功能没做，实际是拿不存在的类型名格式化了一次。所以除了显式写 `render: v => renderCell(v, '', dataType)`，还加了一条契约测试：**`render: renderCell` 裸引用数量必须为 0**，否则下次新增列又会踩回去。
2. **右对齐不能用 `column.align`**。它连表头一起右对齐，而表头右边沿正是 H1a-2 的拖拽热区（`right:0` + `z-index:2`）；列名压过去后鼠标划过文字就变 `col-resize`，看着像坏了。改成 td 级 class，并把"表头不动"写进 CSS 契约 + CDP 两条判据（表头 `textAlign` 与手柄 `elementFromPoint`）。
3. **MySQL 有六个"一个码两种类型"**：249~254 文本与二进制共用类型码（`TEXT`/`BLOB` 都是 252），**分流判据只能用字符集 63**。`BLOB` 标志位（16）对 TEXT 列同样置位，拿它当判据会把文本列说成二进制列；因此 `allowFlag` 只对 253/254 开（那两个码的族里 TEXT/BLOB 位可信），249~252 一律不看标志位。另外 mysql2 的字段名是 `characterSet`（协议里叫 `charsetnr`），两种拼法都读，`encoding === 'binary'` 也认。
4. **pg 的数组 OID 不在 `pg-types/builtins` 表里**（`SELECT typname, oid FROM pg_type` 只含 `typelem = 0` 的基础类型），`int[]` 有自己独立的 OID → 回落 `''`。这是"未知不猜"的一条实例而不是漏项，写在模块头注释里并配了用例，防止后人"好心"补一个数组映射。
5. **词表必须与 `NUMBER_TYPES`/`DATE_TYPES` 同源，且用 pg 的全称**。归一表吐的名字就是数据页那套（`structure-v2.js` 的 `data_type`）；写成 `timestamptz` 而不是 `timestamp with time zone` 会静默不生效 —— 不报错、不红、只是"这一列没本地化"，最难查的那类。反向也对过：`vector`/`geometry`/`enum`/`set` 不进两个集合，所以左对齐、不格式化（符合预期）。
6. **时区类判据必须开子进程**。`TZ` 是进程级的，且 `Intl` 首次使用时就缓存了时区 —— 同进程 `process.env.TZ = ...` 改了没用。子进程里 `env.TZ` 才是真的跑那条分支。
7. **locale 类判据只能比数字序列**。`1,234` 在 `de` 下是 `1.234`、在 `en-IN` 下是 `1,234`；既有测试里硬编码分隔符的三断言本来就在别的 locale 下红。改判据用 `digits(s) = s.replace(/[^0-9]/g, '')`，不硬编码分隔符也不硬编码位值。
8. **CodeMirror 6 拒绝合成 `beforeinput`**。CDP 敲键、`dispatchEvent(new InputEvent('beforeinput'))` 都不改文档内容，`runSql` 拿到空串直接返回，表现是"结果区永远不出网格"。可写的路子是聚焦 `.db-sql-area .cm-content` 后用 `Input.insertText`（受信任的原生插入）。
9. **antd 6 虚拟表体没有 `<tbody>` 也没有 `.ant-table-body`**：行是 `div.ant-table-row`、格是 `div.ant-table-cell`。按 `tbody tr` 找行的探针会数出 0 行，进而让"列数一致"这类前提判据假通过 —— 每个探针都先自证表头/表体列数非零再比内容。
10. **隐藏的其他 db 页签仍在 DOM 里**：`.db-sql-results-tabs .ant-tabs-tab` 直接 `querySelectorAll` 数出 4 个（同一轮之前跑过双结果集），页签计数类判据必须按可见性过滤，harness 启动时再用 `store.delTab` 清掉 `dbName === 'demo_db'` 的老页签。
11. **测试夹具要让四条参考值互不相同**：`stamp` 原来写 `...T00:30:00Z`，在 UTC+8 本机"带时区串"与"无时区 datetime"两条分支算出的文本相同 → `refDt === refZ` 假失败。改成 `+05:00` 后，任何时区下"走错分支"都能被逐字比对抓到。
12. **vm 沙箱的 `require` 白名单是隐藏成本**。适配器新增一条顶部 `require` 会同时打挂 12 个用 vm 加载适配器的 spec（`unexpected require`），而且这类失败发生在"还没跑到被测函数"时，报错信息与本批语义无关。两处细节：白名单式要显式给真实模块；转交宿主的 `require(spec)` 会把 `'../../common/...'` 按**测试文件**目录解析而找不到。

**踩坑（写下来防止重复）**：

1. **渲染进程没有 `Buffer`**。上一批把二进制呈现做成 `<binary n bytes>` 信封时，值面板内部仍用了 `Buffer.alloc`/`Buffer.from`；类型契约那批的桩给的是字符串，走不到这一行，所以 56 条全绿也没发现。真库里点一个真 `BLOB` 格展开面板 → 页签整块消失、结果区清空。教训：**"崩溃类判据"必须是渲染层事件计数**（本轮 `X1` 那条），"UI 上没显示"这种判据会把崩溃误报成"元素没找到"。
2. **"半屏空气"是状态拆分拆出来的**。展开偏好与选中态是两个 state：重新执行清掉选中、偏好还留着，于是面板开着而内容没了，`bottom` 挂着半屏空白，网格被压成一小条（实测 `top 186 / bottom 503`，网格只剩 5 行）。修法是一个派生值 `sqlPaneShown`，而不是"重跑时顺手把偏好也清掉"（那样用户下次执行还得重新拖一次高度）。
3. **折叠态换树形会重挂网格**。第一版是"没展开就不渲染分区组件"，DOM 结构一变，虚拟滚动容器整块重建、滚动位置归零。改成始终渲染同一棵树、只用 class 表达折叠，并给探针加了"节点身份"读数（往网格节点与表体节点挂自定义属性，重挂后属性必然丢失）—— 比截图对比可靠得多。
4. **工具条的 × 要 `stopPropagation`**，否则一次点击先冒泡成"展开"、再执行"取消选中"，表现是"点关闭结果面板闪一下又没了"。
5. **悬停预览卡会盖住工具条**：真库脚本里选中格之后必须先把鼠标移出网格（`move(5,5)`）再取工具条坐标点击，否则点到的坐标上是卡片。
6. **"没渲染"与"值为空"要能区分**。字符数只在超过阈值（60）时才挂，短值的 `meta` 本来就是空串；判据如果只写"meta 为空即失败"，就会在选到短值那一格时假失败。
7. **Redis 的键区只在点了 `db0` 树节点之后才挂载**，且节点标签是 `db0` + 键数两行文本，不是库号 `0`；按等值匹配的探针找不到节点，要按前缀匹配并留连接等待。
8. **自测脚本自己也会错，而且会把缺陷伪装成偶发**。本轮最后一条红（"读回真实剪贴板"失败）查下来不是产品问题：探针里 `window.__fixture.big` 在真库页面上必然 `undefined`（真库测刻意不注入夹具），抛出的 `TypeError` 被 `catch` 成 `ok: 0`，于是加了个重试循环 —— 重试不会让判据变对，只会把 harness 缺陷拖成"偶发失败"。修法是给"没有可比对原文"一个显式取值（`same: -1`），等值判断一律走哈希。**规则：判据红了先分清 harness 与产品，再动手；靠重试变绿的判据等于没有判据。**
9. **本地化开关不是配置通道**（同 §1A.10 的修正）：外部 `setConfig` 改了 `dbFormatLocale` 界面不动，必须点产品自己的开关。

**这一轮补上的四条"判据前置"**（都是先被判据红过才写下来的，缺一条就会把环境问题读成产品缺陷）：

1. **夹具页签要先确认所有权**。页面重载后持久化的页签是**异步**恢复的：恢复完成前删页签，它会带着 `activeTabId` 一起回来。于是自建页签里的网格和判据读到的网格不是同一张（列名、字符数全对不上，红成一片假案）。公共探针新增 `clearDbTabs`（等页签列表稳定 → 多轮删除 → 确认真的删干净），并加一条判据"自己的页签确实是当前活动页签"，把"判据读别人的网格"这条路堵死。
2. **点击坐标必须落在网格可视区内**。虚拟表把视口外的缓冲行也留在 DOM 里，其坐标落在网格外；面板拖到 73% 高时网格只剩 ~150px，照着"第一条 DOM 行"的坐标点下去点到的是面板，选中态停在上一格 —— 于是"换选中格"的两条判据红得像是功能坏了。探针 `__cellXY` 现在返回 `inView`，`clickCell` 拿到 `inView: false` 直接报"out-of-view"而不是继续点；用例改成先滚回顶部（新增一条"表体已回顶"的前置判据）再点。
3. **翻页判据要先有"下一页"**。SQL 结果的每页行数是全局配置（`sqlResultPageSize`），上一轮遗留 200 时 200 行正好一页、分页器**合法地不渲染**，"翻页保留列宽"就没有实测对象。用例改为先用产品自己的下拉把它钉回 20（顺带多验一次"换结果页大小不丢手动宽"），跑完连同原值一起还原 —— 这条配置以前不在还原清单上。
4. **空口令是合法配置**。真库那套脚本的凭据守卫原先按真假值筛"缺哪个环境变量"，把没设密码的 root 报成凭据缺失、整轮直接不跑。改成按"变量是否定义"判漏配，口令可以显式给空串，而"脚本正文不得出现口令"的自检原样保留。

**Redis 详情这一轮再补上的五条判据前置**（同样都是先红过才写下来的）：

5. **连接失败渲染的不是 alert**。真库脚本的错误探针只读 `.ant-alert-message`，而 MySQL / Redis 建连失败时产品渲染的是整页 `.db-session-error`，于是判据红成"等树等超时 + 没有任何错误"，很容易往"页签没挂载"的方向追。现在错误 dump 同时采集可见的 `.db-session-error`，等待条件也改成"出现树 **或** 出现错误页"就放行，真库连不上时第一秒就把服务端原文（`Access denied for user ...`）报出来。
6. **环境阻塞要报成 SKIP，不许级联 FAIL**。真实 MariaDB 现在拒绝 `root` 从 `20.20.31.193` 空口令登录（同一份凭据当天 11:11 还连得上，是环境/凭据变了，不是产品缺陷；用裸 mysql2 脚本复现得到同一条报错才算确认）。处理方式不是把红改成绿：Redis 段整段挪到 MariaDB 段**之前**（否则一次环境阻塞会把 Redis 覆盖全部藏掉），依赖 MySQL 的判据统一记 `SKIP` 并附原因，汇总写成 `N/M PASS + K SKIP（环境阻塞：…）`，退出码仍是 1 —— 环境不达标不能报全绿。
7. **虚拟表的格子是 `div`，不是 `td`**。antd v6 的虚拟表体是 `.ant-table-tbody-virtual`，单元格类名 `div.ant-table-cell`（与列头同类名），表头另成一张 `.ant-table-header`。老的"找一格装不下的长内容"探针按 `td` 取格、再用 `scrollWidth > clientWidth` 当"截断"闸门，在 1208px 的宽列上永远不触发，于是对真 Redis 的 6 个键全部报"没有长内容"（假阴性，看着像产品没东西可预览）。改成"可见 + 不在 `thead` 里 + 落在网格视口内 + 取最长的一格 + 正文 ≥ 60 字符"（60 是产品挂字符数标注的同一阈值，不是测试自定的数），再补一步"重新选中同一格、复查哈希没变"，保证后面几条验的确实是量到长文的那一格。
8. **探针函数必须全返回**。`__colMeta` 找不到列时只回 `{ error }`，调用方读 `.align[0]` 抛 `TypeError`，一条判据红会把同一节剩下的全部带走。错误分支现在返回完整形状（`n/cls/align/texts` 都给出）；另外 helper 的 `eval` 是 `returnByValue`，返回对象字面量的表达式要用 `eval` 而不是 `jeval`（后者要 JSON 字符串，拿到 `[object Object]` 就解析失败）。
9. **每条 CDP 命令都要有超时**。协议封装原来只有 `resolve` 一条路，应答一旦丢失整套判据就停在半路：实测停在第 72 条之后 —— 进程 0% CPU、socket 仍是 ESTAB、渲染进程对另一条调试连接秒回，说明卡的是"没回话的那条命令"而不是产品。现在单条命令 45 秒超时（软件合成的 Xvfb 上截图确实慢，不能按毫秒级设），报错带上 method 名；socket 关闭/出错时把还在等的调用一次性判失败。补上之后同一套 125 条判据一口气跑绿，反证那一下只是丢了应答。

## 2. H1 · SQL 结果工作台增强（P0）



### 2.1 目标

把 SQL 结果从"能看"提升到"能筛、能排、能复制、能定位、能证明花了多久"。不改变执行与分页语义。

### 2.2 交互

结果集工具行（`.db-sql-result-tools`，左对齐）从左到右：

1. 分页器（已有，仅超过一页显示）
2. 页大小 Select（已有）
3. **过滤输入**：占位 "过滤当前结果"，匹配任意列；显示 `命中/总数`
4. **列显隐** Dropdown：每列 Checkbox；"全部显示"
5. **导出** Dropdown：CSV / JSON / TSV / JSONL / Markdown（整份结果，不受当前页限制）
6. 右侧状态：`{rows} 行 · {elapsed} ms`（多结果集显示各自耗时；总耗时显示在 tab 标题旁）
7. **单元格右键菜单**：复制值 / 复制字段名 / 复制整行（TSV/JSON）/ 按此值过滤 / 查看行详情
8. **行详情**：Modal（宽 720，内容滚动），逐字段展示，长文本/JSON 可展开，逐项复制

交互规则：
- 过滤/排序/列显隐只作用于**当前结果集**；切换结果 tab 各自独立。
- 重新执行 SQL 时重置过滤/排序/列显隐/页码；页大小保持 config。
- 过滤后分页总数按过滤结果计算；清空过滤恢复。
- 排序：点击表头循环 升序 → 降序 → 无排序；NULL 恒排最后；数字列按数值比较，其余按字符串 localeCompare。
- 过滤输入防抖 150ms；超过 5 万行时提示"仅对当前结果集排序"，不阻断。

### 2.3 技术设计

**状态**（`db-session.jsx`，与 `sqlPages` 同层）：
```
sqlViews[i] = { filter: '', sort: { key, order } | null, hidden: [] }
```
- 新 state `sqlViews`；`setSqlView(i, patch)`。
- `runSql` 成功时 `setSqlViews({})`、`setSqlPages({})`。

**派生链**（纯函数抽到 `src/client/common/db-sql-result.js`，便于单测）：
```
fullRows = results[i].rows
filtered = filterRows(fullRows, filter)
sorted   = sortRows(filtered, sort, { numericKeys })
pageRows = sorted.slice(start, start + pageSize) → 加 __rowKey
```
- 列顺序仍来自 `fields`（已有 `sqlResultColumns`）。
- 列定义加 `sorter: true`、`sortOrder` 由 `sqlViews` 控制；用受控排序（`onChange` 只改 `sqlViews`，不触发请求）。
- 列显隐：`hidden` 数组按列名过滤 `sqlResultColumns`；至少保留一列。
- 数值列判定：`inferNumericColumns(rows, keys)` 采样前 100 行；全为 number 或可转 number 的字符串 → 右对齐。

**执行耗时**（主进程）：
- `src/app/lib/db-client/mysql.js` / `postgres.js` 的 `executeSql`：`const started = Date.now()`；返回 `{ results, elapsedMs: Date.now() - started }`。
- 前端 `runSql` 把 `elapsedMs` 存到 `sqlResult`；多结果集共享总耗时，各结果 tab 显示 `总 {n} ms`。
- 兼容：旧调用方只读 `results`，新增字段不影响。

**导出**（前端，无新 op）：
- 在 `src/client/common/db-csv.js` 增加纯函数：`toTsv(headers, rows)`、`toJsonl(rows)`、`toMarkdownTable(headers, rows)`（转义 `|`、换行、反引号）。
- 复用 `downloadText`；CSV/JSON 保持现有 `exportSqlCsv/exportSqlJson` 行为。
- 不提供"SQL INSERT"：SQL 结果不知道源表名，避免生成错误表名；需要时去数据页导出。

**右键菜单**：
- 新增 `src/client/components/database/db-cell-menu.jsx`：受控菜单，props `{ open, x, y, items, onClose }`；`position: fixed`，点击外部/Escape/滚动关闭。
- 结果网格 `onCell` 返回 `onContextMenu`，设置 `{x,y,resultIndex,rowKey,col}`；菜单项按上下文生成。
- 不使用每格一个 antd Dropdown，避免 10k 行时创建大量浮层。

**行详情**：
- 新增 `src/client/components/database/db-row-detail.jsx`，props `{ columns, row, onCopy }`；渲染 `定义列表`（字段名 + 格式化值 + 复制按钮）。

**样式**：

- 过滤输入宽度 180~260px；结果网格边框保持现有 `--border` + `--radius-sm`。

1. **词条在主进程里，`npm run compile` 不会把它同步到 `work/app`**。`src/app/lib/locales.js` 在**主进程** require `locales-extra`，而 `npm run compile` 只做 vite 构建 + CM6 分块检查 + 图标复制 + pug —— `src/app` 原样不动。表现是 `translate('dbFilterResult')` 返回 key 本身、占位文案显示成 `DbFilterResult`，40 条判据里 29 条红，看起来像"过滤整个没做"。正确顺序是 `rsync -a src/app/ work/app/`（**不带 `--delete`**，否则会清掉生成的 `work/app/package.json`）→ 重启实例；`Page.reload` 不够，主进程已经在启动时把词条读进内存了。
2. **换词要把页码写回第 1 页（实测出来的真实缺陷）**。第一版只在"读页码"时夹住，于是：在第 6 页筛选到 2 行（分页器消失，看着像只有这一屏）→ 清空过滤 → 直接跳到第 1001 行，用户不知道自己是停在旧页码上。判据必须记在 `useRef` 里，不能读 `sqlViews`：防抖回调闭包里的 `sqlViews` 是注册那一次的旧值，拿它比"词变没变"会比出假结论。
3. **"命中/总数"和分页器必须同一口径**。命中数从 `view.matched` 出、分页器 `total` 也从它出，否则会出现"共 3 页"但筛完只剩 5 行。
4. **工具行显隐看 `total`，不看 `matched`**。否则零命中时页大小/导出/列宽一起消失，用户只能先清空输入框才能把按钮找回来。
5. **antd 分页只渲染首尾几个页码项**。1 万行 / 200 = 50 页，DOM 里只有 `1 2 3 4 5 … 50` 六项；判据写 `pages.length >= 50` 必假失败，要认"末页在列表里"。
6. **单行结果集里，多个词都命中同一行时防抖探针会假阴性**。合成查询只有 1 行，`null`/`hello`/`1234567.8912` 的命中提示字面都是「1/1」，而防抖探针是按"命中文本 + 行数"判变化的 → 测不出新词生效。改法是先敲"词 + 不存在后缀"把命中压到 0，再敲原词回到 1，用 0→1 反证。
7. **跨页判据的 needle 要由数据决定**。写死 `INFO` 在这份 5000 行样本里 0 命中 —— 而 SQL 参照也算出 0，"产品与参照一致"这条反而绿了，暴露问题的是"命中数 > 每页"那条。改为让数据库报当前样本里最常出现的 level 值（本轮 4741 行），并保留"能安全拼进 LIKE"的守卫。
8. **`window.__cellXY(...)` 返回的是 JSON 字符串**。`cdp.eval('window.__cellXY("id", 0).text')` 拿到的是 `undefined`（属性挂在字符串上），要用 `cdp.jeval(...)` 或先 `JSON.parse`；同一条脚本里两种写法混用会让一条判据永远红。

**与设计稿的差异**：§2.2 写"导出 Dropdown：CSV / JSON / TSV / JSONL / Markdown（整份结果，不受当前页限制）"，全部落地。设计稿没写的两个决定：① 导出菜单从默认 hover 触发改为 `trigger='click'` —— 同一工具行里列显隐菜单是点击展开，相邻两个菜单一只 hover 一只点击手感打架，点击展开对键盘操作也更明确；② 不提供"SQL INSERT"（§2.6 已声明）：SQL 结果不知道源表名，拼出来的是猜测表名，需要时去数据页导。

**实测结论**（同一构建）：

| 判据 | 数据 |
|---|---|
| 桩测 | **69/69 PASS**（1 万行 5 列；D1–D6 为本项新增）：CSV 回归（BOM 字节 `EF BB BF`、表头行、1 万行）与 JSON 回归（数组长度 1 万）；TSV 表头行 = 列名制表符连接、数据 1 万行；JSONL 1 万行逐行可 parse 且列序以 fields 为准；Markdown 表头 + 分隔行 + 1 万数据行；转义真样本（竖线 `\|`、换行 `<br>`、反引号、NULL 空单元格）全过 |
| 单元测试 | `db-csv.spec.js` **44/44**（新增 9 条）；全量随 §2.9 提交后复跑，另一会话进行中的 Redis 值面板改动所致的旧钉子红条目不计入本项 |
| 静态检查 | `npx standard` 对新增/修改文件干净 |

**踩坑（写下来防止重复）**：

1. **`Blob.text()` 会把 BOM 剥掉**。CSV 的 BOM 断言用 `text.charCodeAt(0) === 0xFEFF` 必假失败 —— `Blob.text()` 按 UTF-8 解码是"去 BOM"的规范行为。BOM 要从 `arrayBuffer()` 的前三个字节（`EF BB BF`）看。
2. **导出读的是"已加载的结果"，不是桩函数**。第一版 D6 换掉桩的返回函数就直接导出了，导出的还是那份 1 万行旧数据 —— 换桩函数后必须真的重新执行一次 SQL。
3. **antd Dropdown 默认 hover 触发，DOM `.click()` 打不开它**。探针点了按钮、菜单死活不出场，排查发现导出菜单从创建起就没设 `trigger`；顺手统一成 `trigger='click'`（见"与设计稿的差异"①）。

- 预览默认最多 2MB；超过提示"文件过大，仅预览前 2MB / 下载查看"。
- 二进制检测：NUL 字节比例 / 扩展名；图片走 base64（限 10MB），文本走 UTF-8（替换非法字节）。

### 9.2 预览面板

- SFTP 双击文件 → 右侧/弹层预览：
  - 文本：等宽、只读、行号、查找；超过 2MB 截断提示。
  - 图片：png/jpg/gif/webp/svg（svg 需 sanitize 或按文本）。
  - Markdown：源码 + 渲染切换（可选 P2）。
  - 其他：十六进制前 4KB + 下载按钮。
- 不做：远程编辑回传（既有设计未含）、PDF/Office 预览（依赖重库）。

### 9.3 验收

- 单测：分片读取参数、二进制判定、截断标记。
- 真 SFTP：本地 sshd 或测试服务器；10MB 日志/图片/二进制。
- 不改变现有下载/上传/编辑流程。

## 10. H3b · 只读 ER 图（P2）

### 10.2 后端

## 11. H4 · 属性级结构对比（P2）

### 11.1 范围

- 同连接、同库两张表（v1）；跨库/跨连接 P2+。
- 比较：列（名/类型/可空/默认/注释）、主键、索引（名/唯一/列顺序）、外键（列/引用）。
- 输出：并排差异列表（新增/删除/变更），字段级展开；复制 Markdown 报告。
- **不生成 ALTER/DDL**，不做同步。

### 11.2 技术设计

- 数据源：两边 `getTableStructure`；归一化 `normalizeStructure(struct, dialect)`。
- 纯函数 `diffTableStructure(a, b, { dialect })` → `{ columns: [...], indexes: [...], fks: [...], summary }`。
- 比较规则：
  - 名称：MySQL 大小写不敏感，PG 敏感；由 dialect 决定。
  - 类型：先比原始 `data_type`，再比归一化（大小写/空格）。
  - 默认值：`null` 与 `''` 区分；`CURRENT_TIMESTAMP` 归一化大小写。
  - 索引/FK：按名称匹配；列顺序参与比较。
- UI：`db-structure-diff.jsx` Modal；两个表选择器（当前库表列表来自 metadata）；差异用 tag 色（新增绿/删除红/变更黄）走 token。

### 11.3 验收

- 单测：增删改、大小写、默认值、索引列顺序、FK 引用变化。
- CDP：假结构对比；复制报告。
- 真库：同库两表（手工造差异）。

### 11.4 风险

- 不同引擎类型别名（`int` vs `integer`）→ 仅做保守归一化，避免误报；报告注明原始值。
- 结构缓存过期 → 打开对比时强制刷新两边结构。

## 12. H6a · 参数化查询（P2）

### 12.1 交互

- 编辑器工具栏"参数"开关（默认开）：执行时若检测到 `:name` 占位符，弹出参数面板。
- 面板：每个参数一行（名称 + 值 + NULL 勾选）；"执行" / "取消"；"记住本次值"仅当前 tab 内存。
- 执行前显示"将使用参数化执行"提示；不把值拼进 SQL 文本。
- 无参数时行为不变。

### 12.2 技术设计

- 纯函数 `extractSqlParams(sql, dialect)`：
  - 跳过字符串/注释/`::` 类型转换/PG `$1`；识别 `:name`（`[A-Za-z_][A-Za-z0-9_]*`）。
  - 返回 `{ names, toPositional(sql, dialect) }`：MySQL `?`，PG `$1..$n`。
- `executeSql` 增加可选 `params`：
  - mysql：`c.query(sqlWithQuestionMarks, params)`（驱动转义；多语句 + 参数不支持，检测到 `;` 多语句时禁用参数执行并提示）。
  - pg：`client.query({ text: sqlWithDollar, values: params })`。
- 风险分级：用原始 SQL（含 `:name`）做 `splitSqlStatementsForSafety`；确保解析器把 `:name` 当普通 token，不误判。
- 只读白名单：原始 SQL 先过 `checkReadonly`，参数不改变语句类型。
- 多语句：参数化模式只允许单条语句（简化 + 驱动限制）。

### 12.3 验收

- 单测：参数提取（字符串内 `:x`、注释、`::`、重复参数、PG `$1` 混用）、占位符转换、无参数回退。
- 假 adapter：断言 `query` 收到 params 而非拼接 SQL。
- 真库：MySQL/PG 各一条 `WHERE id = :id`；只读拦截仍生效。

### 12.4 风险

- 驱动差异 → 按方言分支，禁止手写转义。
- 用户误以为支持多语句 → UI 明确提示"参数化模式仅支持单条语句"。
- 风险门解析 → 加单测防止 `:name` 被当作语句分隔。

## 13. H7b · Redis 慢日志 / 批量删除 / Stream（P2）

### 13.1 慢日志

- `getRedisSlowlog(conn, { count })` → `SLOWLOG GET count`（默认 128，最大 512）。
- 表格：id、时间、耗时 μs、命令、参数（截断）；只读。
- 入口：H7a 的"服务器信息"弹层 → 慢日志 Tab。

### 13.2 批量删除

- 入口：键列表/键树工具栏"批量删除"。
- 流程：输入 pattern → "预览"（SCAN 统计数量，上限 1 万，显示前 20 个 key）→ 确认（输入 `DELETE` 或库名？按危险级别）→ 分批 `UNLINK`（每批 500）→ 进度/取消。
- 后端：`unlinkKeys(conn, { dbIndex, keys })`（校验数组长度 ≤1000、key 为字符串）；`scanKeysCount` 复用 `getPageData` keysOnly 循环（前端）。

### 13.3 Stream（只读）

- `getKeyDetail` 增加 `stream`：
  - `XINFO STREAM key` → 长度、最后 ID、消费者组。

- UI：键详情新增 Stream 视图（表格 + 刷新）；不做 XADD/XDEL。

### 13.4 验收

- 假 RESP server：慢日志/Stream/批量删除（SCAN+UNLINK 序列）。
- 单测：UNLINK 分批、key 校验、Stream 归一化。
