## 2. H1 · SQL 结果工作台增强（P0）

### 2.1 目标

把 SQL 结果从"能看"提升到"能筛、能排、能复制、能定位、能证明花了多久"。不改变执行与分页语义。

### 2.2 交互

结果集工具行（`.db-sql-result-tools`，左对齐）从左到右：

1. 分页器（已有，仅超过一页显示）
2. 页大小 Select（已有）
3. **过滤输入**：占位 "过滤当前结果"，匹配任意列；显示 `命中/总数`
4. **列显隐** Dropdown：每列 Checkbox；"全部显示"
5. **导出** Dropdown：CSV / JSON / TSV / JSONL / Markdown（整份结果，不受当前页限制）
6. 右侧状态：`{rows} 行 · {elapsed} ms`（多结果集显示各自耗时；总耗时显示在 tab 标题旁）
7. **单元格右键菜单**：复制值 / 复制字段名 / 复制整行（TSV/JSON）/ 按此值过滤 / 查看行详情
8. **行详情**：Modal（宽 720，内容滚动），逐字段展示，长文本/JSON 可展开，逐项复制

交互规则：
- 过滤/排序/列显隐只作用于**当前结果集**；切换结果 tab 各自独立。
- 重新执行 SQL 时重置过滤/排序/列显隐/页码；页大小保持 config。
- 过滤后分页总数按过滤结果计算；清空过滤恢复。
- 排序：点击表头循环 升序 → 降序 → 无排序；NULL 恒排最后；数字列按数值比较，其余按字符串 localeCompare。
- 过滤输入防抖 150ms；超过 5 万行时提示"仅对当前结果集排序"，不阻断。

### 2.3 技术设计

**状态**（`db-session.jsx`，与 `sqlPages` 同层）：
```
sqlViews[i] = { filter: '', sort: { key, order } | null, hidden: [] }
```
- 新 state `sqlViews`；`setSqlView(i, patch)`。
- `runSql` 成功时 `setSqlViews({})`、`setSqlPages({})`。

**派生链**（纯函数抽到 `src/client/common/db-sql-result.js`，便于单测）：
```
fullRows = results[i].rows
filtered = filterRows(fullRows, filter)
sorted   = sortRows(filtered, sort, { numericKeys })
pageRows = sorted.slice(start, start + pageSize) → 加 __rowKey
```
- 列顺序仍来自 `fields`（已有 `sqlResultColumns`）。
- 列定义加 `sorter: true`、`sortOrder` 由 `sqlViews` 控制；用受控排序（`onChange` 只改 `sqlViews`，不触发请求）。
- 列显隐：`hidden` 数组按列名过滤 `sqlResultColumns`；至少保留一列。
- 数值列判定：`inferNumericColumns(rows, keys)` 采样前 100 行；全为 number 或可转 number 的字符串 → 右对齐。

**执行耗时**（主进程）：
- `src/app/lib/db-client/mysql.js` / `postgres.js` 的 `executeSql`：`const started = Date.now()`；返回 `{ results, elapsedMs: Date.now() - started }`。
- 前端 `runSql` 把 `elapsedMs` 存到 `sqlResult`；多结果集共享总耗时，各结果 tab 显示 `总 {n} ms`。
- 兼容：旧调用方只读 `results`，新增字段不影响。

**导出**（前端，无新 op）：
- 在 `src/client/common/db-csv.js` 增加纯函数：`toTsv(headers, rows)`、`toJsonl(rows)`、`toMarkdownTable(headers, rows)`（转义 `|`、换行、反引号）。
- 复用 `downloadText`；CSV/JSON 保持现有 `exportSqlCsv/exportSqlJson` 行为。
- 不提供"SQL INSERT"：SQL 结果不知道源表名，避免生成错误表名；需要时去数据页导出。

**右键菜单**：
- 新增 `src/client/components/database/db-cell-menu.jsx`：受控菜单，props `{ open, x, y, items, onClose }`；`position: fixed`，点击外部/Escape/滚动关闭。
- 结果网格 `onCell` 返回 `onContextMenu`，设置 `{x,y,resultIndex,rowKey,col}`；菜单项按上下文生成。
- 不使用每格一个 antd Dropdown，避免 10k 行时创建大量浮层。

**行详情**：
- 新增 `src/client/components/database/db-row-detail.jsx`，props `{ columns, row, onCopy }`；渲染 `定义列表`（字段名 + 格式化值 + 复制按钮）。
- SQL 结果用 Modal；数据网格用底部页签（H2 复用同一组件）。
- 值格式化复用 `src/client/components/database/db-value-format.js` 的 `formatValue`/`detectFormats`；二进制只显示 `<binary N bytes>` + 复制 base64（如已有）。

**样式**：
- 工具行允许换行：`flex-wrap: wrap; row-gap: 6px`；状态文字用 `--text` 70% 透明度（token 派生 `color-mix`）。
- 过滤输入宽度 180~260px；结果网格边框保持现有 `--border` + `--radius-sm`。
- 全部走 token，禁止硬编码。

### 2.4 验收

- 单测：`src/test/unit-ci/db-sql-result.spec.js`（过滤大小写、NULL、数字/字符串排序、TSV/JSONL/Markdown 转义、隐藏列、多结果独立状态）。
- CDP：`self-test/sql-result-workbench-demo.js` 使用假数据（2 个结果集、1 万行），验证过滤/排序/列显隐/右键/行详情/导出/耗时。
- 性能：1 万行过滤 < 100ms，排序 < 200ms（CDP Performance 采样，允许 ±30%）。
- 双主题截图；无 CSS 契约新增失败；`npx standard` + `test-unit-ci` + `compile`。

### 2.5 风险 / 回滚

| 风险 | 缓解 |
|---|---|
| 大结果集排序卡顿 | 只对当前结果集排序；>5 万行提示；排序在 `useMemo` 内一次完成 |
| `sorter` 与分页冲突 | 受控排序，先排全量再切页；不调用 antd 远程排序 |
| 右键菜单遮挡/错位 | fixed 定位 + 边界翻转；ResizeObserver 关闭 |
| 耗时字段影响旧单测 | 新增字段可选；适配器单测补断言 |

### 2.6 不做

- 结果图表、结果比较、跨结果集合并、SQL INSERT 导出。
- 结果编辑（SQL 结果只读，保持现状）。

## 3. H2 · 数据网格交互补齐（P0）

### 3.1 目标

让数据网格具备"行视角 + 右键动作 + 数值可读性"，不改变现有编辑/选择/导出语义。

**现状（二轮复核）**：数据网格已有本页过滤、排序、列显隐/列序/列宽、汇总、批量改值、查找替换、行选择、双击编辑、值/关联页签；缺的只是右键菜单、按值过滤、行详情页签与数值/空值视觉。`DbRowDetail`/`DbCellMenu` 在 H1 新建后本批复用，不重写网格。

### 3.2 交互

1. **行详情页签**：底部面板现有"值 / 关联"两个页签，新增"行"页签（仅选中行时可用）。展示该行全部可见列，字段名 + 值 + 复制；长文本/JSON 可展开。
2. **单元格右键菜单**：
   - 复制值
   - 复制字段名
   - 复制整行（TSV）
   - 复制整行（JSON）
   - 按此值过滤（设置本页过滤）
   - 查看外键（该列有 FK 时，切到"关联"页签）
   - 编辑（可编辑单元格时，等同双击）
   - 打开值面板
3. **数值右对齐**：`describeTable` 的 `data_type` 命中数值集合（int/decimal/numeric/float/double/bigint/smallint/tinyint/real/money 等）→ 单元格加 `.db-cell-num`；表头同样右对齐。
4. **选中/悬停/焦点**：选中行 `.db-row-selected`（已有 Redis 用）；数据网格勾选行也加同款背景；单元格 `:focus-visible` 用 `--primary` 2px 外框；行悬停用 `--hover-bg`。
5. **空态**：无表选中时显示工作台空态（U1），不是空网格。

### 3.3 技术设计

- **行详情**：`DbRowDetail`（H1 新建）复用到 `refTabsEl`，第三个 Tab `row`：
  - 数据源：`selectedCell.rowKey` → `grid.rows[rowKey]`；列用 `visibleColumnNames`。
  - 页签高度沿用 `.db-pane-tabs`；内容 `overflow auto`。
- **右键菜单**：`DbCellMenu`（H1 新建）复用到数据网格；`onCell` 注入 `onContextMenu`，携带 `{rowKey, col}`。
  - 菜单项构建函数 `buildGridCellMenu(ctx)` 纯函数，便于测试。
  - 外键判定：`refInfo`/`colTypeByName` 已有外键映射；无则隐藏该项。
  - 编辑项：仅 `canEditCell(rowKey, col)` 为真；点击后调用现有 `startEdit`。
- **数值对齐**：新增纯函数 `isNumericType(dataType)`（`src/client/common/db-grid-view.js` 或 `db-value-format.js`）；`columns` 生成时加 `className`；CSS `.db-cell-num`。
- **状态**：不新增全局状态；右键菜单为单例受控组件；行详情复用 `selectedCell`。

### 3.4 验收

- 单测：`db-grid-cell-menu.spec.js`（菜单项生成、外键/编辑条件、数值类型判定）。
- CDP：`self-test/db-grid-interactions-demo.js`：右键复制、按值过滤、行详情、外键跳转、数值对齐截图。
- 回归：双击编辑、行选择、批量改值、删除、导出、查找替换不受影响。
- 双主题；CSS 契约零新增失败。

### 3.5 风险 / 回滚

| 风险 | 缓解 |
|---|---|
| 右键菜单与单元格编辑冲突 | 右键只读动作；编辑项显式触发，不改变双击行为 |
| 行详情页签挤压值面板 | 仅在选中行时显示；`DbSplitPane` 比例可拖拽 |
| 数值判定误判字符串 ID | 只按 `data_type` 判定，不按值推断；`varchar` 永不右对齐 |
| 选中行样式与勾选冲突 | 用同一 token，不覆盖 antd 勾选列 |

### 3.6 不做

- 冻结列、转置、行拖拽排序、单元格合并。
- 暂存编辑/变更清单（H9 待拍板）。

## 4. U1 · 工作台壳层视觉统一（P0）

### 4.1 目标

不重排布局，只做"信息层级 + 工具分组 + 空态"，让 DB 页看起来像一个工作台而不是一排按钮。

### 4.2 设计

1. **顶部 `.db-head`**：
   - 左侧：引擎徽标 + 目标 + 连接状态点（已有）。
   - 右侧按语义分组，组间 1px `--border` 分隔：
     `[生产/只读] | [系统库开关] | [刷新/重连] | [更多]`
   - 宽度不足时，"更多"收纳低频繁开关；不隐藏只读/生产标记。
2. **数据页 `.db-grid-head`**：
   - 第一行：表名 + 行数/精确行数 + 过滤 + 汇总 + 列显隐 + 导出/导入 + 事务状态。
   - 第二行（窄宽度自动换行）：分页 + 页大小 + 跳页。
   - 选中行时显示 `已选 n 行` + 批量操作（已有，统一成一组）。
3. **无表选中空态**（`dataArea` 的 `!sel` 分支）：
   - 新组件 `DbWorkspaceHome`：连接摘要（引擎/目标/只读/生产）、四个动作（刷新元数据、打开 SQL、快速打开 Ctrl+K、导入）、最近表（从 `sqlHistory` 推断或本地 config，最多 8 条）。
   - 不引入新持久化键；最近表先用当前 metadata 的前 8 张表，避免额外存储。
4. **结果状态行**：SQL 结果工具行右侧显示行数/耗时（H1），数据页显示"本页 n 行 / 近似总数"。
5. **加载态**：树/网格加载用骨架（已有 `Spin`），不新增全屏遮罩；错误用 `Alert` + 重试（已有 `DbConnError`）。

### 4.3 技术设计

- 只改 JSX 结构与 `.styl`，不新增数据请求。
- 分组容器 `.db-tool-group`、`.db-tool-sep`；窄宽度用 `@media (max-width: 1100px)` 折行。
- 空态组件 `db-workspace-home.jsx`；文案进 `locales-extra.js`。
- 所有颜色/圆角/阴影用 token；不引入新依赖。

### 4.4 验收

- CDP 三档宽度（900/1200/1600）截图；无表选中空态可见且动作可用。
- 双主题；键盘 Tab 顺序合理；`aria-label` 覆盖图标按钮。
- 不改变任何数据/执行逻辑；现有单测全绿。

### 4.5 风险

- 工具条折行导致网格高度计算变化 → `DbGridTable` 已用 ResizeObserver 测量 header/wrap/pager，需在 CDP 验证 `scroll.y` 仍正确。
- 空态动作与现有入口重复 → 只做快捷入口，不新增业务逻辑。

## 5. U2 · 网格可读性视觉统一（P0）

### 5.1 设计

| 项 | 规则 |
|---|---|
| 数值列 | 右对齐 + `font-variant-numeric: tabular-nums`；表头同 |
| NULL | 保留 `.db-cell-null`（50% 透明），tooltip 显示 "NULL" |
| 空字符串 | 显示 `''`（细体、低对比），与 NULL 区分 |
| 行悬停 | `--hover-bg`；不改变选中行 |
| 选中行 | `--active-bg`；勾选框列背景同步 |
| 焦点 | 单元格/按钮 `:focus-visible` 2px `--primary` 外框 |
| 表头 | 粘顶（已有）；排序列显示箭头 + 主色下划线 |
| 密度 | 默认 compact（antd `size='small'`）；**不新增全局密度开关**（避免 config 膨胀） |
| 斑马纹 | 不做（与主题色/选中态冲突，收益低） |

### 5.2 技术设计

- `.db-cell-num`、`.db-cell-empty`、`.db-row-selected td`、`.db-grid-table .ant-table-tbody > tr:hover > td` 使用 token。
- 空字符串判定在 `renderCell`：`v === ''` → `<span className='db-cell-empty'>''</span>`（保留复制原值）。
- 表头排序箭头由 antd 提供，覆盖颜色为 `--primary`。

### 5.3 验收

- 双主题截图（有 NULL/空串/数字/长文本的混合表）。
- 对比度：正文 ≥ 4.5:1（深/浅各测 3 个背景）。
- 现有网格交互（编辑/选择/汇总/查找）无回归。

## 11. H4 · 属性级结构对比（P2）

### 11.1 范围

- 同连接、同库两张表（v1）；跨库/跨连接 P2+。
- 比较：列（名/类型/可空/默认/注释）、主键、索引（名/唯一/列顺序）、外键（列/引用）。
- 输出：并排差异列表（新增/删除/变更），字段级展开；复制 Markdown 报告。
- **不生成 ALTER/DDL**，不做同步。

### 11.2 技术设计

- 数据源：两边 `getTableStructure`；归一化 `normalizeStructure(struct, dialect)`。
- 纯函数 `diffTableStructure(a, b, { dialect })` → `{ columns: [...], indexes: [...], fks: [...], summary }`。
- 比较规则：
  - 名称：MySQL 大小写不敏感，PG 敏感；由 dialect 决定。
  - 类型：先比原始 `data_type`，再比归一化（大小写/空格）。
  - 默认值：`null` 与 `''` 区分；`CURRENT_TIMESTAMP` 归一化大小写。
  - 索引/FK：按名称匹配；列顺序参与比较。
- UI：`db-structure-diff.jsx` Modal；两个表选择器（当前库表列表来自 metadata）；差异用 tag 色（新增绿/删除红/变更黄）走 token。

### 11.3 验收

- 单测：增删改、大小写、默认值、索引列顺序、FK 引用变化。
- CDP：假结构对比；复制报告。
- 真库：同库两表（手工造差异）。

### 11.4 风险

- 不同引擎类型别名（`int` vs `integer`）→ 仅做保守归一化，避免误报；报告注明原始值。
- 结构缓存过期 → 打开对比时强制刷新两边结构。

## 12. H6a · 参数化查询（P2）

### 12.1 交互

- 编辑器工具栏"参数"开关（默认开）：执行时若检测到 `:name` 占位符，弹出参数面板。
- 面板：每个参数一行（名称 + 值 + NULL 勾选）；"执行" / "取消"；"记住本次值"仅当前 tab 内存。
- 执行前显示"将使用参数化执行"提示；不把值拼进 SQL 文本。
- 无参数时行为不变。

### 12.2 技术设计

- 纯函数 `extractSqlParams(sql, dialect)`：
  - 跳过字符串/注释/`::` 类型转换/PG `$1`；识别 `:name`（`[A-Za-z_][A-Za-z0-9_]*`）。
  - 返回 `{ names, toPositional(sql, dialect) }`：MySQL `?`，PG `$1..$n`。
- `executeSql` 增加可选 `params`：
  - mysql：`c.query(sqlWithQuestionMarks, params)`（驱动转义；多语句 + 参数不支持，检测到 `;` 多语句时禁用参数执行并提示）。
  - pg：`client.query({ text: sqlWithDollar, values: params })`。
- 风险分级：用原始 SQL（含 `:name`）做 `splitSqlStatementsForSafety`；确保解析器把 `:name` 当普通 token，不误判。
- 只读白名单：原始 SQL 先过 `checkReadonly`，参数不改变语句类型。
- 多语句：参数化模式只允许单条语句（简化 + 驱动限制）。

### 12.3 验收

- 单测：参数提取（字符串内 `:x`、注释、`::`、重复参数、PG `$1` 混用）、占位符转换、无参数回退。
- 假 adapter：断言 `query` 收到 params 而非拼接 SQL。
- 真库：MySQL/PG 各一条 `WHERE id = :id`；只读拦截仍生效。

### 12.4 风险

- 驱动差异 → 按方言分支，禁止手写转义。
- 用户误以为支持多语句 → UI 明确提示"参数化模式仅支持单条语句"。
- 风险门解析 → 加单测防止 `:name` 被当作语句分隔。

- 技术：`src/app/server/ssh-tunnel.js` 的 `forwardLocalToRemote/forwardRemoteToLocal/dynamicForward` 返回 `{ close }` 句柄；`session-ssh.js` 保存句柄并暴露 stop；IPC 新 action `ssh-tunnel-stop/start`；前端状态同步。
- 风险：关闭隧道不能断开 SSH 会话；多 tab 共用连接时引用计数；错误重试不自动。
- 验收：本地 sshd 起一条 local/remote/dynamic，启停/断开重连；不影响现有连接。

## 18. 跨批次工程约束

   - 只用 `tokens.styl` 变量；新增变量需在 `tokens.styl` + `.theme-light` 双端定义，并过 `css-tokens`。
   - 不新增硬编码颜色/圆角/阴影；不引入 CSS 框架。
4. **i18n**
   - 所有文案进 `src/app/common/locales-extra.js`；`i18n-coverage` 必须绿。
5. **性能**
   - SQL 结果过滤/排序 memo 化；网格虚拟化不退化；Redis 树虚拟滚动；ER 节点上限。
   - 大结果/大键库必须有上限与取消。
6. **测试**
   - 纯函数优先单测；适配器用假 client；UI 用 CDP 脚本；写操作真库回归单列。

7. **文档**
