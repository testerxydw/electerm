## 1. 本版要解决的问题（一句话）

批次 D 把**数量**管住了（98 → 56），但留下了三笔明账：① structure 33 条超过 V2 的 ≤28 分项；
② "零命中删除"依据的是**冻结语料**，而 `git diff`、`ssh` 首连、`git log --oneline` 这三个高频场景
恰恰不在语料里——删掉的 6 个家族（冲突标记、diff 头、diff hunk、短 SHA、分支引用、SSH 指纹）
在实机上会表现为**整行素色**；③ `info` 色组删除后 `word-info` 并入 `debug`，INFO 与 DEBUG 同色。
批次 F 也没有开始：13 类真实输出的密度回归、终端实机截图、设置面板的家族归属展示与色板体检都还是空白。

本版按用户四项裁决收口（AskUserQuestion 记录，逐条实施）：

1. **盲区回表增补**：把 6 个被删家族按 KU 契约重新登记（rank + 色组 + 矩阵样本），
   而不是"临时塞规则"——signal 侧 +1（`conflict-marker`），structure 侧 +5
   （`git-ref`、`commit-sha`、`diff-header`、`diff-hunk`、`fingerprint`）。
2. **structure 分项修订为 ≤38**：用户接受存量 33 条并放宽分项；G 增补 5 条后实态 **38**，
   修订后的分项正好达标（33 存量 + 5 增补），总量 62 恰好触顶用户裁决的 ≤62。
3. **INFO/DEBUG 拆成两色**：`info` 色组（ANSI cyan）回补，`word-info` 从 `debug` 挂回 `info`；
   ANSI cyan 本就在面板可选手色里，不新增真彩色、不动结构色板几何。
4. **覆盖率闸豁免 marker 层与指纹**：回表后 35% 行级闸会把 diff 头（89%）、hunk（45%）、
   指纹（65%）整行丢弃——豁免 `rank === 0`（marker 层）与 `fingerprint`，
   不计入行染色占比、也不被闸丢弃；其余 rank ≥ 10 的胖路径/长 URL 照旧受闸。

一条贯穿的判据（V3 提出、V4 收紧颜色、V5 收紧词、V6 收紧形状、V7 收紧数量、本版补齐盲区与可见性）：

> 一个信号家族（family）→ 一种颜色 → 一个归属组 → 一条裁决优先级；
> 一个颜色 → 恰好一个色组 → 恰好一类语义，且这个颜色在屏幕上不能像别的色组的颜色；
> 一个关键字 → 恰好一个家族 → 恰好一个配置；
> 一个形状 → 恰好一个家族 → 整段被该家族吃掉，不许半个 token 一种色；
> 一条规则 → 必须在真实语料里命中过，或能说出它等哪个场景；
> **一条被删规则 → 必须在实机语料上复核过，盲区场景一旦出现就回表增补，不许用"语料没覆盖"当删除理由。**（本版新增）

### 2.1 用户点名的 IPv4 —— 一色现状（V3 病灶 + 批次 C 结果）

V3 记录的病灶：同一个地址的颜色取决于**后面跟的是 `/24` 还是 `:443`**，因为 `ipv4` 规则里写了
一句让位护栏 `(?!:\d)`，把 `ip:port` 整段让给了 HTTP / Docker 两组的 `host-port`（当时是 magenta）。
那不是调色板问题，是**归属不唯一**。批次 C 之后的实测（发布实现 `buildScan` + `collectMatches`，全量预设勾选）：

| 行内容 | V5 实态（批次 B 后，护栏仍在） | **V6 实态（批次 C 后，本版沿用）** |
|---|---|---|
| `connect to host 10.1.2.3 port 22` | `10.1.2.3` → `#FF9ECB` | `10.1.2.3` → **ip 组 `#FD9CCA`**；`port 22` → port 组 |
| `inet 10.1.2.3/24 scope global` | `10.1.2.3/24` → `#FF9ECB` | `10.1.2.3/24` → **同一个 ip 组色**（CIDR 前缀在同一段吃完） |
| `tcp ESTAB ... 10.1.2.3:443 93.184.216.34:80` | 两段整段 magenta（HTTP `host-port`） | `10.1.2.3` / `93.184.216.34` → **ip 组**；`:443` / `:80` → **port 组**（相邻两段、各色各色） |
| `upstream=10.1.2.3:8080` | 整段 magenta | `10.1.2.3` → ip 组；`:8080` → port 组 |
| `0.0.0.0:8080->80/tcp` | 整段 magenta（Docker `listen`） | `0.0.0.0` → ip 组；`:8080->80/tcp` → port 组（映射尾巴跟端口走） |
| `127.0.0.1:631` | 整段 magenta | `127.0.0.1` → ip 组；`:631` → port 组 |

结论：**IPv4 形状在全仓只剩一处声明**（`通用 · 地址与路径` 的 `ipv4` 规则），`host-port` 从家族登记表
里删除，`port` 作为独立族登记（rank 40、色组 `port` `#9CECB9`），`host`（带点域名）新建成族
（rank 57、色组 `ip`）。顺带修掉两处"半个 token 一种色"：`python3` 不再被镜像白名单切成
`python` + 裸 `3`，`Makefile:12` 的行号不再被端口族认领（见 §2.4 与 §6 批次 C 的连带修复表）。

### 2.3 字面词跨配置重复（V5 核心证据，本版复测未劣化）

探测口径（发布实现，`keyword-family.spec.js` 的 KU-4 闸就是这段逻辑）：

### 2.4 异色跨度竞争（裁决靠"取短"而非靠意图）—— 批次 C（V6）逐条收口，本版沿用

V2 口径在 15 行代表语料上实测：**8 个 span 存在异色竞争**，胜利者只由长度/原序决定。
下表保留 V2 的原始证据（左三列），右两列给出批次 A（rank 裁决）与批次 C（形状边界）的落点：

| 文本片段 | 实际胜出（V2） | 竞争方 | 批次 A 后 | **批次 C 后（D 未再改动形状）** |
|---|---|---|---|---|
| `java.lang.NullPointerException` | `red`（通用异常类） | `blue`（AppLog 包名） | rank 30/30 同层，exception-class 更长胜出 ✅ | 同左（本批未动） |
| `10.1.2.3/24` | `#FF9ECB`（ipv4） | `magenta`（Docker 镜像引用！） | 仍靠 registry 段的数字竞争 ⚠️ | **registry 主机段首字符限定字母**，纯数字段不再进镜像族；`10.1.2.3/24` 整段归 ipv4 ✅ |
| `aabb.ccdd.eeff`（交换机 MAC） | `#FF7BAC`（ipv6-mac） | `blue`（AppLog 包名） | rank 10 压 30 ✅ | 同左 |
| `registry.example.com:5000/nginx:1.20` | `blue`（包名） | `magenta`×2（host:port / 镜像） | 包名仍赢 ⚠️ | **整段归 image-ref**（registry 引用支）；裸 `api.example.com` 归新建的 `host` 族 ✅ |
| `45%` | `#79C0FF`（裸数字） | `cyan`（Build 百分比） | percent 独立成族 ✅ | **percent 从 Build 上收进 `通用 · 时间与数值`**，Build 副本删除，族仍一条；色组仍是 `number` `#6EBDFE`（拆族要的是**归属唯一**，不是换色——百分比与裸数字同属"数值"语义类，KU-6 允许同色组多族） |
| `5m` / `12m` | `#2DD4BF`（时长） | `#A5D6FF`（体积！）、`cyan`（Docker AGE） | 时长赢，但靠的是长度不是边界 ⚠️ | **单位表按形制分工**：`dur` 的裸单字母只跟整数、`unitSize` 的 `M` 只在小数/带 B 时成立；Docker AGE 复合形制上收通用 ✅ |

`5m` 被**体积规则**抢走是真 bug 的根因：规则以 `gi` 编译（`keyword-compile.js:110`、
`keyword-scan.js:80/91`），`[KMGTPE]` 在 `i` 标志下把 `m` 同时认成 megabyte 和 minute，
而 v4 §KU-3 设想的"size 只认大写单字母"**无法字面实现**——node 24 的 `(?-i:…)` 直接报
`Invalid group`（实测），大小写在正则内部不可判。批次 C 的替代是把裁决权交给**形制**而不是字母表：

| 输入 | 归族 | 依据 |
|---|---|---|
| `5m` / `5M` | `duration` | 整数 + 裸单字母：AGE 列的形制 |
| `1.5M` / `1.5m` | `size` | 小数 + 裸字母（`(?<=\.\d)M`，`i` 标志下 M/m 同形） |
| `100MB` / `1.2MiB` / `5Gi` | `size` | 带 `B`/`iB` 或 `[KGTPE]` 字母，时长表里没有这些字母 |
| `0.5s` / `3.5s` / `2h` / `3d` | `duration` | 时长长单位表 `[sdh]` 收小数（`0.5s` 是常态读数） |
| `12m30s` / `3d4h` | `duration` | `durAge` 复合形制（≥2 个单位），从 Docker 上收 |
| `45%` | `percent` | 独立族，rank 40 压 `number` rank 60 |
| `(0.01 sec)` | `duration` | `durParen`，从 Database 上收 |

**这条取舍必须写进契约**（不是实现细节）：整数 + 裸 `M`（`du -h` 的 `108M`）归 duration、

`python3 setup.py` 的 `python`（镜像白名单不含词尾锚 → 现在整词不成立，`python3` 不染，
`python:3.11-slim` 照染），`make: *** [Makefile:12]` 的 `:12`（端口族的主机 lookbehind

## 3. 契约：信号全局唯一（KU）

### KU-1 一色（family → 单一颜色）✅ 由构造保证

每条规则必须声明 `family: '<家族 id>'`。**同一 family 的全部规则，颜色必须一致**。
B-1 之后这条不再靠"约定"：规则的 `color` 字段**根本不写在预设里**，由
`FAMILY_COLOR[family] = COLOR_GROUPS[FAMILY_GROUP[family]].color` 派生，一族一色是恒等式。

例外：**分级族**（graded family）——家族的语义本身就是按级别分色的，家族 id 必须写到级别粒度，
使每个色档成为独立家族，从而仍然满足一色：

```
http-status.5xx / http-status.4xx / http-status.3xx / http-status.1xx2xx   （4 个家族，各 1 色）
syslog-sev.err / syslog-sev.warn / syslog-sev.info                         （3 个家族，各 1 色）
bracket-level.err / bracket-level.warn / bracket-level.info                （nginx [error] 形制，3 个家族）
```

判定：**只有当"级别"是该信号自身的语义维度时才允许分级**。`word-error` 不是分级族——它就是"报错词"这一个信号。
V4 时代它有 10 份完全同色的副本（`Networking`/`Syslog`/`Kernel`/`HTTP`/`Docker`/`Build`/`Git`/`Auth`/`Database`
各写一遍），属纯重复；**批次 B 已收口**：现在 `word-error`/`word-warn`/`word-info`/`word-debug`/`word-ok`
各只剩 `通用 · 级别与状态` 里的一份，`word-skip` 只剩 `Build & test output` 里的一份（它只在该领域出现，
按 KU-2 就近原则归领域组）。分级族保持原样：全仓 10 个（`http-status.*` 4 + `syslog-sev.*` 3 + `bracket-level.*` 3），
每档一个家族 id、各 1 色，仍然满足 KU-1。

### KU-2 一归属（family → 单一归属组）✅ 批次 C 收口，棘轮降级为硬断言

同一 family 的所有规则必须落在**同一个预设组**里。业务组不得声明通用家族。归属裁决顺序（就近原则 → 专属原则）：

1. 通用家族（时间/数值/地址/路径/级别）→ 一律归 `通用 · *` 三档，业务组**只允许引用、不允许重述**。
2. 领域专属家族（`interface-name`、`unit-name`、`sql-keyword`、`git-ref`…）→ 归该领域组。
3. 一个家族只有一个归属组，归属组由 `FAMILY_HOME`（派生：首个声明该家族的组即归属组）导出，供 CI 与设置面板共用。

V4 的 5 族违规，三条（`word-error`/`word-warn`/`word-ok`）由批次 B 收口，两条由批次 C 收口。
至此跨组复用家族 = **0**，`keyword-family.spec.js` 里的棘轮表（`CROSS_GROUP_FAMILIES`）已删除，
改成**硬断言**：任何新增的跨组家族直接失败，不再是"只降不升"的登记表。

批次 C 收口的最后两条：

| 家族 | 首属组之外的声明处 | 批次 C 处置 |
|---|---|---|
| `duration` | `Docker & Kubernetes`（复合 AGE `5m`/`12m30s`）、`Database & SQL`（`(0.01 sec)`） | 两处形状**上收进通用 `durAll`**（AGE 复合形制 + `(0.01 sec)` 括号形制），业务侧副本删除 |
| `host-port` | `Docker & Kubernetes`（`0.0.0.0:8080->80/tcp`）、`HTTP & web logs`（`host:port`） | 按 KU-3 **拆成 `host` + `port` 两族**，复合家族即消失；两处规则一并删除，`host`/`port` 上收通用地址档 |

### KU-3 不吞并（家族边界）✅ 批次 C 落地

**禁止**在别的家族的规则里内联该家族的形状片段。这条是"IP 只有一种颜色"的真正保证，
比 KU-1/KU-2 更强：即使 `host:port` 规则换了归属，只要它内部还写着 `\d{1,3}(\.\d{1,3}){3}`，
它就会把 IPv4 一起吞掉、改色。

改法：**一条染色 span 只承载一个家族**。把复合模式拆成相邻的、各归各族的段：

```js
// 拆前（HTTP 组，magenta 吞掉 IP）
'\\b(?:[a-z][a-z0-9.-]*|\\d{1,3}(?:\\.\\d{1,3}){3}):\\d{2,5}(?:->\\d{1,5}/(?:tcp|udp))?\\b'
// 拆后：端口成为独立家族，IP 段交回 ipv4
{ keyword: '\\b\\d{1,3}(?:\\.\\d{1,3}){3}\\b(?:/\\d{1,2})?', family: 'ipv4' }   // rank 10，归通用地址档，删 (?!:\d)
{ keyword: ':\\d{2,5}\\b(?:->\\d{1,5}/(?:tcp|udp))?', family: 'port' }          // rank 40，归通用地址档，单一色
```

扫描器按"最左起点 + rank"裁决：`ipv4` 先吃掉 `10.1.2.3`，游标前进到 `:`，`port` 再吃 `:443`。
**不需要变长后视，也不需要任何让位 lookahead**——两段相邻、各色各色、各有归属。

原型实测（`/tmp/kw-audit2/split3.mjs`，7~9 条玩具族 + rank 裁决，验证机制而非最终表）：

```
tcp ESTAB 10.1.2.3⟨ipv4⟩:443⟨port⟩ 93.184.216.34⟨ipv4⟩:80⟨port⟩
inet 10.1.2.3/24⟨ipv4⟩ dev eth0
upstream=10.1.2.3⟨ipv4⟩:8080⟨port⟩ 0.0.0.0⟨ipv4⟩:8080->80/tcp⟨port⟩
docker: 5m⟨duration⟩ 12m30s⟨duration⟩ 45%⟨percent⟩ 233G⟨size⟩ 4096 bytes⟨size⟩ 5MB⟨size⟩ 0x1f⟨hex⟩
host registry.example.com⟨host⟩:5000⟨port⟩      elapsed 1.2s⟨duration⟩ latency 300ms⟨duration⟩
```

同一 IPv4 在 4 种上下文里颜色恒定。原型同时暴露 **4 条必须一起满足的约束**（缺一条即退化成抢色，实施时逐条验证）：

| # | 约束 | 不满足的后果（原型复现） |
|---|---|---|
| a | `ipv4` 本体必须含 CIDR 段 `(/\d{1,2})?` | `10.1.2.3/24` 的前缀 `24` 漏给 `number` |
| b | `duration` 必须含**复合** AGE 形式 `\b\d+[dhms](\d+[dhms])*\b` 与 `\(\d+(\.\d+)? ?(sec\|ms\|min)\)` | `12m30s` 被拆成裸字符，`(0.01 sec)` 逃逸 |
| c | `size` 单位表**去掉 `i` 标志**，只认 `B`/`iB`/`bytes` 或**大写**单字母 | 带 `i` 时 `5m` 同时是"5 分钟"与"5MB"（§2.4）；完全去掉裸单字母则 `233G`（`df -h`）漏染 |
| d | `percent` 从 `number` 拆出并 rank 高于 `number` | `45%` 双色竞争（§2.4） |

批次 C 实际处理的吞并点（逐条已在实现里验证，最终形状见 §6 批次 C）：

| 吞并方 | 被吞信号 | 批次 C 处置（已落地） |
|---|---|---|
| Docker `image-ref` 的 `[a-z0-9-]+(\.[a-z0-9-]+)+(/\S+)?` | `ipv4`（`10.1.2.3/24`） | registry 主机段首字符限定字母：`[a-z][a-z0-9-]*(\.[a-z0-9-]+)+` |
| 镜像白名单名（`python` 等）半词 | `python3 setup.py` 只染 `python` | 词尾锚 `(?![\\w.])`：白名单名必须吃掉整个 token（这是**词尾锚**，属形状自身成立条件，不是让位护栏） |
| HTTP `host-port` 的 `\d{1,3}(\.\d{1,3}){3}` | `ipv4` | 拆成 `host` + `port` 两族，`ipv4` 交回通用地址档，删 `(?!:\d)` |
| 通用 `size` 的 `[KMGTPE]` + `i` 标志 | `duration`（`5m`、`3s`、`12m`） | 体积单位表去 `i` 语义（`[KGTPE]i?`，加 `(?<=\\.\\d)M` 收小数 MB）；裸 `5m/3s/1h` 唯一属于 `duration` |
| 通用 `number` 的 `\d+(\.\d+)?%?` | `percent`（`45%`） | `%` 后缀从 number 分支移除，`percent` 独立成族（颜色并入 `number` 色组：`45%` 与 `42` 同类） |
| 通用 `ts` 的 `(?!\.\d)` 等 5 处让位 lookahead | —— | 家族 rank 裁决取代，四处已删净，见 §7 |

**编译标志恒为 `gi`**（`keyword-compile.js:110`；`keyword-scan.js` `'gyi'`/`'gi'`）⇒ 正则内**不可判大小写**。
node 24 没有 `(?-i:…)`（实测 `Invalid group`），所以 `5m`（分钟）与 `1.5M`（兆字节）这种 `m`/`M`
**同一字母、两种单位**的冲突，只能按**形制**裁决，不能按大小写：

| 形制 | 归谁 | 依据 |
|---|---|---|
| 整数 + 裸单字母（`5m`、`100M`、`3s`） | `duration` | docker/k8s AGE 列的形制（`5m` = 5 分钟）；体积靠 `MB/MiB`、`bytes` 与小数形制认领 |
| 小数 + 裸单字母（`1.5M`、`4.0K`） | `size` | 体积习惯写小数（`df -h`），时长极少写 `1.5M` |
| 带 `B`/`iB`（`100MB`、`1.5M`） | `size` | `B` 只能指字节 |
| `(?<=\\.\\d)M` | `size` | 小数点后接 `M` 判定为兆字节 |

这是**已知取舍**，不是完满解：`100M` 会读成"100 分钟"而非"100 兆"。要在 `gi` 下真正按大小写区分
只能把两族各自的规则重写为自含大小写的分支（会成倍膨胀），或引入 engine 层的按字符匹配——超出治理范围（V6 提出，批次 D 仍未触碰 engine 层），
如实记为风险（§9）。`size` 与 `duration` 仍各自独立成族（KU-1 一族一色），只是**形制上有重叠区间**，
`FAMILY_RANK` 内 `duration` rank 40、`size` rank 40 同层，靠 `FAMILY_LAYERS` 下先到先得与原序裁决。

### KU-4 一词一族（词表家族）✅ 批次 B 落地

任意一个英文字面词（含多词短语）**只能整词命中一条信号规则**。跨组重叠的词必须：

- 同色 → **删除副本**，只保留归属组那一份（归属组吸收该词）。
- 异色 → **人工裁决一个颜色**，另一处的副本删除。

裁决原则（写进代码注释，供后续同类冲突复用）：**终态 > 过渡态**；同一词在两个组里语义不同 → 归更通用的那一档，
业务组若确需另一种语义，必须换一个词形（Networking 的 `down` 保留 red，Syslog 不能再用 `down` 表示别的含义）。

**批次 B 的实质交付不是"改了词表"，而是把这条判据变成了可机检的闸**（V2/V3/V4 只能靠人工审表）。
`keyword-family.spec.js` 里的 `literalCandidates()` + `matchesWholeWord()` + `wordTable()` 三步：

1. 从**全部 signal 规则**的源码剥掉环视、`\b \B \d \w \s` 等转义类与字符类，按 `|` 和括号切成候选，
   只留 1–4 个词的纯字面串（这是"词表"，形状族天然不贡献候选）。
2. 拿每个候选去**全部 signal 规则**上做整词命中探测：在 `" tok "` 上 `exec`，
   且**匹配文本必须恰好等于候选**——这样只统计真正的裸词，`[DROP]`、`Accepted password`、
   `reverse mapping checking .* successful` 这类上下文形状不会被误计成词表条目。
3. 按词聚合，断言 `同词多配置 = 0`、`同词异色 = 0`，并带规模下限 `table.size > 250` 防止探测器空跑假通过。

落地前后（同一探测器、同一口径）：

| 指标 | 批次 B 前 | 批次 B 后 |
|---|---|---|
| 字面词候选 | 327 | **331** |
| 同词命中 ≥2 条规则 | 65 | **0** |
| 同词跨 ≥2 个配置组 | 64 | **0** |
| 同词异色 | 5 | **0** |

本批的 5 处同词异色裁决：

| 词 | 冲突 | 裁决 |
|---|---|---|
| `listening` | 通用黄档 vs Syslog 绿档 | **yellow**（"正在监听"是过渡态，不是成功终态）；删 Syslog 绿档副本 |
| `ACCEPT` / `REJECT` / `DROP` | nft 日志语境（magenta）vs 通用红/绿档 | 两者都要留：`nft-target` 收紧为**语境锚**（`[DROP]` 方括号形制或 `policy/action/target/verdict/flags` 前缀），裸词归通用档 |
| `not permitted` | 通用 `NOT PERMITTED` vs  Networking 词表 | 整句并入通用红档，Networking 侧删除 |
| `SEGFAULT` | 通用红档裸词 vs `exception-class` 的 `XxxFault` 形状 | 判给**形状族** `exception-class`（同 rank、同色，观感不变），删词表里的副本 —— "一个词两个归属"就此消解 |

同一形状撞词的连带处理：`access denied` / `permission denied` 原散在 Networking / Auth / Database 三处，
已上收为通用红档的**整句**（词表与形状二选一时，选更具体的那个 span，避免 `access` 单独被染蓝）。
`up-to-date` 的连字符写法与 `disabled?` 的词形差异，也一并在通用档里用 `UP[ -]TO[ -]DATE`、
`DISABL(?:E|ED|ING)` 吸收，业务组不再各写一份。

### KU-5 裁决改为家族优先级（取代长短裁决）✅ 批次 A 落地

现行 `arbitrateAt` 是四级裁决（`keyword-scan.js` 的 `selectByRank`）：

```
1. 最左起点优先（combined 大正则天然给出）
2. 同起点 → family rank 小者胜（FAMILY_RANK 显式表，非隐式数组顺序）
3. rank 相同 → 跨度长者胜（同族/同层内合并优先，不再跨族抢色）
4. 仍相同 → 原序（保证确定性）
```

`FAMILY_RANK` 是**发布契约的一部分**，不是实现细节：改优先级必须改表并被 spec 锁定；
`rank` 已进入编译摘要（`keywordsSignature`），只改家族/档位必然重新编译。初始 rank 分层（`FAMILY_LAYERS`）：

| 层 | rank | 族数 | 家族（本版实态，由 `FAMILY_RANK` 直接枚举，合计 **62 族**；批次 D 的 56 族口径见 V7 §3 KU-5） |
|---|---|---|---|
| 边界 | 0 | 4 | `redis-type` + 批次 G 回表的 `conflict-marker`、`diff-header`、`diff-hunk`（marker 层同时是 KU-7 闸豁免族） |

### KU-6 一色一语义（色板收紧）✅ B-1 构造 + B-2 几何

**KU-1 管"一族不拆成多色"，KU-6 管"一色不混多种语义、且两色不撞"**。五条子契约，括号内是落地状态：

1. **ANSI 语义名只属于 signal 档**：`red`=错、`yellow`=警、`green`=成、`blue`=调试、
   `cyan`=信息、`magenta`=空值/杂项；`white` 预留给用户自定义规则。
   `cyan` 的轨迹：批次 D 因 `info` 色组无宿主而暂时空置 → **批次 G 按用户裁决回补给 `word-info`**
   （INFO 与 DEBUG 拆成两色）。（✅ B-1，棘轮 35 → 硬断言 0；批次 D 6 → 5 组，批次 G 5 → 6 组）
2. **结构档一律真彩色**，不得占用任何 ANSI 名。（✅ B-1；由 `COLOR_GROUPS` + `FAMILY_GROUP` 派生，
   预设里根本没有 `color` 字段可写）
3. **色的语义粒度 = 色组（color group），不是家族**。家族管**裁决**（rank、谁吞谁），色组管**观感**（这是什么类别的东西）。
   **一个色组只允许一个颜色，一个颜色不得跨两个色组。**（✅ 由构造保证，CI 断言"派生一致 + 无死色 + 取色器同步"）
4. **色位数由可辨性决定，不由家族数决定**：任意两个结构色必须拉开到"一眼是两个颜色"，且不得长得像 signal 的主题色。
   达不到就**并组**，不许硬造一个近似色——近似色正是"一个颜色两种语义"的另一种形态。（✅ V6 建立、本版沿用的四条闸，见 §5）
5. **老配置零迁移**：预设行在设置面板只读，配置里存的颜色只是旧色板快照 ⇒
   `ruleColorOf()` 在**读取时**按家族重派生预设规则的色（与 `ruleTierOf`/`ruleFamilyOf`/`ruleRankOf` 同一套口径），
   用户自定义规则的自选色不动。（✅ B-1）

> KU-6 之后颜色数 20（批次 C 时代 22；批次 D 随归属收缩到 19；批次 G 回补 `info` 到 20），
> **"一名多义" = 0、"两色难辨" 由闸控制**。这比"颜色少"更值钱——用户凭颜色就能反推类别。

### KU-7 覆盖率闸的豁免边界（批次 G 用户裁决）✅

行级覆盖率闸（`applyCoverageGate`）的规则是：**每行染色占比 > 35% 时丢弃该行全部 structure 命中，
signal 永不丢**。批次 G 回表后发现两个边界：

1. **marker 层（rank 0）天然是"短行上的整行命中"**：`diff --git a/x b/x` 的头部 + 路径占 ~89%、
   `@@ … @@` 占 ~45%、SSH 指纹占 ~65%。它们不是"花屏"，而是**边界记号**——丢掉等于整行素色，
   回表白做。
2. **`fingerprint` 是精确 token**：一屏最多出现一次，长度固定，不构成密度问题。

契约（用户裁决）：`rank === 0`（`redis-type`/`conflict-marker`/`diff-header`/`diff-hunk`）与
`family === 'fingerprint'` 是**闸豁免族**——`collectMatches` 下发 `family` 供闸认人，
`applyCoverageGate` 对豁免命中 `continue`（不计入行占比、也不被丢弃）。

边界（防止豁免扩散）：
- 豁免是**按命中**而不是按行：同一行上的胖路径（rank 20）照旧计入占比、照旧可能被闸（有单测反证）。
- 豁免名单是**发布契约**：新增豁免必须同时满足"边界记号/精确 token""长度固定或极低频""用户裁决"
  三条，并补一条 `keyword-density.spec.js` 用例；不得为"某行被闸丢了"临时开豁免。
- 35% 阈值本身未动；豁免只改变了参与占比计算的命中集合。

## 5. 色板几何闸（V6 核心交付，本版复核沿用）

数学唯一真源在 `src/client/common/keyword-color-math.js`（`srgbToLab` / `deltaE76` / `deltaE00`，
sRGB → CIELAB → ΔE(1976) / CIEDE2000），闸值、色相带、主题锚点与实测值在
`src/client/common/keyword-palette-health.js`；CI（`keyword-family.spec.js`）与设置面板「色板体检」
都从这两个模块取数，跑的都是 `COLOR_GROUPS` 全表。终端底色是深色，配色是否撞车只能靠**感知距离**
判断——肉眼在等宽字体上对色相+明度的差别远比对 RGB 差值敏感。

### 5.1 四条闸与实测最低值

| # | 闸 | 阈值 | 实测最低 | 撞车对（当前） | B-2 前（最低对） |
|---|---|---|---|---|---|
| G1 | 结构色两两 ΔE(1976) | ≥ **16** | **16.0** | `size ↔ path` | 6.2（`size ↔ path`） |
| G2 | 结构色两两 ΔE(2000) | ≥ **8** | **8.5** | `time ↔ path` | 4.5（`size ↔ path`） |
| G3 | 结构色 ↔ 内置主题 signal 色 ΔE(1976) | ≥ **11** | **11.6** | `number ↔ 主题 blue` | 7.4（`mac ↔ 主题 magenta`，几乎同色） |
| G4 | 每个结构色组留在登记的**色相带**内 | 硬约束 | 全通过 | —— | 无此闸 |

**批次 D 只动"删"、批次 G 只动"回补 signal 色"**：色组 22 → 19（signal 6 → 5、structure 16 → 14）
→ **20**（signal 5 → 6，回补 `info` cyan；structure 仍 14）。14 个结构色的色值逐字节不变。
四条闸的实测最低值因此**与批次 C/D 逐字相同**（G1 16.0、G2 8.5、G3 11.6、G4 违规 0）——
删色只会拉开结构色距离，回补的 cyan 是 signal 侧色组、不参与 G1/G2/G4 的结构色两两计算；
G3 的锚点集本来就含主题 cyan，回补不会降低任何结构色到锚点的距离。
**回调条件复核结果**（§5.5 末）：色组数 20 > 12，`GATES.pairDeltaE76` 维持 16 不上调。

次近对（批次 D 后重算，用于判断"下一次加色往哪儿塞"）：G1 序后 `size↔number`=16.7、`time↔path`=17.5、
`time↔number`=18.9、`ip↔mac`=19.7、`time↔size`=22.4；G2 序后 `size↔number`=8.9、`port↔loc`=9.0、
`flag↔artifact`=9.6；G3 序后 `artifact`=13.6、`duration`=14.9、`hexnum`=16.6。

**瓶颈集中在淡蓝簇**：G1 的前四名（16.0 / 16.7 / 17.5 / 18.9）全部落在 `time`/`size`/`number`/`path` 之间，
G2 的前两名同理。闸的余量因此很薄（G1 第二名只剩 0.7）——**这是刻意的**：余量厚就等于把颜色推得更远、
位移更大。下一次要往蓝簇里加第 5 个色组，正确动作不是调闸，而是并组（§5.5）。

### 5.2 为什么 ΔE(1976) 与 ΔE(2000) 一起用

ΔE(1976) 在蓝段**虚高**：同样"看得出不同"的距离，蓝段要报的数字比绿段大得多（经验比约 ΔE00 ≈ 0.7×ΔE76，
本板实测 `time↔path` 8.5/16.0、`size↔number` 8.9/16.7）。只按 ΔE(1976) 定闸会逼着蓝段颜色无谓地跑远，
只按 ΔE(2000) 定闸又放过了"明度差撑起来的假距离"。两把尺同时作闸，取的是交集。

### 5.3 G3 的锚点口径（重要，别误读成跨主题承诺）

ANSI 十六色由**主题**控制，用户换主题就是换一组锚点。G3 的对照集**不抄第二份表**，而是在用例里
`import('../../client/common/theme-defaults.js')` 现取：两套内置终端主题 × 六个 signal 语义名 = 12 个锚点
（`themeSignalColors()`），锚点为空或不是 `#rrggbb` 时先失败——否则这条闸会**静默假通过**。

只取 **normal** 变体（`red/yellow/green/blue/magenta/cyan`），不含 `bright*`：
`colorToCode` 发出的是 SGR 31–37，bright 需要加粗，而关键字高亮从不加粗（`highlight-addon.js` 里
没有任何 SGR 1）。因此这条闸的含义是"结构色不能长得像**我们自带主题的**信号色"，
不是"任意主题、任意亮度下都不撞"。用户自定义 ANSI 映射不在机检范围内
（那条只能靠 KU-6 第 1 条：结构档根本不写 ANSI 名，从源头避免撞）。

**已知越界、且故意不拦的一对**：`number`(#6EBDFE) 与深色主题 `brightBlue`(#6FC1FF) ΔE(1976)=**2.4**。
brightBlue 是别的程序加粗输出时的颜色（`ls`、`grep`、shell 提示符），不属于关键字高亮的语义空间；
把它纳入闸的唯一办法是让 `number` 离开蓝相——而"数值是蓝的"正是这一族的语义身份（G4）。
这条取舍写在 `keyword-presets.js` 的 KU-6 注释块里，未来若决定纳入，必须同时改 G4 的 `number` 色相带。

### 5.4 G4 色相带（语义身份）

色的**语义身份 = 色相**。体积不能变成黄色，标识符不能从绿相推成芥末金——那等于换了语义。
这张表就是每个结构色组允许住着的色相弧（`HUE_BANDS`，与 §4 表的 h 列一致，各留约 25°–35° 余量）：

```
time 215–250 / duration 165–200 / size 245–280 / number 250–285 / hexnum 295–330
flag 75–100 / ip 335–360 / mac 0–25 / url 30–60 / port 140–170 / ident 110–140
artifact 60–85 / path 215–245 / loc 130–160
（diffmark 100–130 / action 150–175 两条随色组删除一并撤登记，见 §5.5 批次 D 复核）
```

G4 的另一个作用：它让"并组"成为**显式决策**。想给某个家族换成别的色族，必须先删掉它的色相带登记
——而删色相带的唯一正当理由是"这个家族并进了别的色组"，CI 会在这里把决定摊到台面上。

### 5.5 容量结论：为什么"全局 ≥ 18"做不到（诚实记录）

求解口径（B-2 期间的一次性脚本：模拟退火 + **违反量平方和**作为平滑目标 + 只重算被扰动索引的增量代价）：

- 域：`L* ∈ [70,87]`、`C* ∈ [26,67]`、色相偏移 ≤ 16°、sRGB 内、避开 G3 的主题邻域；
- 两阶段：先找可行解（位移惩罚 = 0、多 restart），再在可行解中**最小化总位移 ΔE(2000)**
  （避免"为了拉开距离把整板重画"）。

**同一目标函数下测到的天花板**（每一行是不同口径，别混着读）：

| 口径 | 16 色可达的全局最小 ΔE(1976) | 说明 |
|---|---|---|
| 交付域、且要求位移最小 | **16.0** | V6 落地值，闸 G1 钉在 16（本版批次 D 复测仍 16.0） |
| 交付域、纯可行性（不管位移） | 多 restart 最好 **17.5**，从未越过 18 | 说明 18 不是"求解器没使劲"，是域本身的限制 |
| 更窄的淡蓝带 `L80–93 / C40–58` | ≈ 16.0；把主题邻域一起算进去只剩 **13.2** | B-1 那批色的观感口径，正是它产出了 6.2 的撞车对 |
| 放宽到中色带 `L72–94 / C36–66` | ≈ **19.4** | 能过 18，但一板色的明度/彩度跨度拉大，不再是"一排亮色字"的整齐观感 |
| 同淡色带但只放 12 色 | ≥ 18 | 要砍掉 4 个色组 ⇒ 并组 |

**16 个色 + 淡亮色观感 + 每色守色相身份**三者不可同时成立：淡蓝簇（`path` 229°、`time` 235°、
`number` 261°、`size` 263°）天然挤在 229°–263° 这 34° 弧上，第四对只能到 16.0。要到 18 只有三条路：

1. **并组**——`size` 并入 `number`（体积与数值同色，15 色）。语义上站得住（都是"量"），
   代价是丢掉"体积 vs 数值"这一层视觉区分，且批次 C 之后 `percent`/`size`/`number` 三族的区分全部下沉到 rank。
2. **放弃色相身份**——允许淡蓝簇里的颜色跨到青/紫相（G4 就得删登记）。代价是 KU-6 的"凭颜色反推类别"失效，
   等价于回到 B-1 之前那种"一片蓝说不清是谁"。
3. **接受明度/彩度不再整齐**（中色带，实测 19.4）。代价是终端上一排高亮字有的发白有的发沉，
   这是"审美一致性"换"距离"，比第 1/2 条更容易被用户感知为"配色脏"。

本批选**第四条：把闸钉在实测值（16 / 8.5 / 11.6）、保留当时的 22 组语义粒度**，并把 18 记为未达成的口头目标。
理由：16→17.5 的收益是肉眼几乎不可见的差别，而三条路径的损失都是语义级或观感级的。
**回调条件**：批次 C 拆完形状、批次 D 收完数量之后，如果色组数自然收缩到 ≤ 12，
本闸上调到 18 并重开这条结论（写进 §6 批次 C 的接口条款）。

> **批次 D 复核结果**：色组收缩到 **19**（5 signal + 14 structure），19 > 12 ⇒ **回调不触发**，
> G1 维持 16。收缩来自"删零命中家族后色组自然失去宿主"（`info`/`diffmark`/`action`），不是走上面
> 第 1 条的并组决策——所以"保留语义粒度"的选择没有被推翻，反而被批次 D 白捡了 3 个色位。
> 14 色口径下的可达上限没重算（求解器结论对删色单调：14 色的天花板 ≥ 16 色的 17.5）。
>
> **批次 G 复核结果（本版）**：色组 **20**（6 signal + 14 structure），20 > 12 ⇒ **仍不触发**。
> G 回补的 `info` 是 ANSI cyan（signal 侧），5 个新 structure 家族全部复用既有色组，
> 结构色集合与批次 D 完全相同 ⇒ G1/G2/G3/G4 实测值逐字不变（16.0 / 8.5 / 11.6 / 0）。
> **加**结构色或**并**组之前才需要重开容量结论（`HUE_BANDS` 仍只有 14 条登记，见 §5.4）。

> **这组上限数字怎么复核**：求解脚本（`/tmp/kw-b2-*.mjs`）是一次性的，批次收尾即删。
> 复核路径固定为：把位移惩罚设为 0、以 G1/G2/G3 当前阈值为硬约束、在同一域内多 restart 扫，
> 看能否稳定拿到全局最小 > 18 的可行解（本轮从未拿到）。距离一律用
> `src/client/common/keyword-color-math.js` 的 `srgbToLab` / `deltaE76` / `deltaE00`
> （批次 F 起从 spec 搬出为 SSOT，CI 与面板「色板体检」共用），不要另写近似实现。

## 7. 让位护栏清单与删除条件

V2 §4 曾断言"裁决同源后 5 处护栏可删"，落地时因"原用例不翻色"硬指标而全部保留
（`keyword-scan.js` 文件头 §15-20 行记录了这次改口）。**V3 推翻该保留结论**：
护栏不是为了"取短"而存在，是为了补偿"家族不唯一"。家族唯一 + rank 裁决之后，它们失去存在理由。

| # | 位置 | 护栏 | 删除条件 | 状态 |
|---|---|---|---|---|
| 1 | 通用地址 `ipv4` | `(?!:\d)` | `port` 成为独立族后必删——保留它等于继续让 IP 变色 | ✅ 批次 C 删除 |
| 2 | 通用时间 `ts` | `(?!\.\d)` | `timestamp` rank 40 < `number` rank 60，靠 rank 让位 | ✅ 批次 C 删除 |
| 3 | 通用级别 `lvlError` | `DOES NOT(?: (?:EXIST\|MATCH))?` | 批次 B 复查判定：这是**词表形态**（一个词族的多种写法合并），不是让位护栏，无删除条件 | ✅ 批次 B 复核后保留（终态） |
| 4 | Docker `image` | `(?![\w.-])` | `image-ref` rank 30 与 `file-line` rank 20 分层后可删；需先验证 `nginx:1.20` 不被 `file-line` 抢 | ✅ 批次 C 删除（`nginx.conf` 由 path rank 20 赢，验证通过） |
| 5 | 通用数值 `num` | `(?<!status[=:]\s{0,2})` | `http-status.*` rank 55 < `number` rank 60，必删（V2 已实证冗余） | ✅ 批次 C 删除 |

**批次 C 之后的环视实态**：五处让位护栏四处删净、一处退化为同族可选后缀；
剩余的环视**全部是正形约束**——`port` 的 `addrBefore` 语境 lookbehind（没有它裸 `:8080` 通吃）、
镜像白名单的词尾锚 `(?![\w.])`（没有它 `python3` 半词染色）、`srcLoc` 的起始 `(?<![\w./-])`
（没有它绝对路径半截）。判据：删掉它形状本身就不成立 = 正形约束，允许存在；
删掉它只是把颜色让给另一个家族 = 护栏，禁止。

**硬指标不变**：删护栏必须逐条改、逐条跑 `npm run test-unit-ci`，一次删除导致翻色的用例
要在 KU 契约下判定"新色才对"还是"改错了"，**不允许为了过测试把护栏加回来**。

> 历史措辞校准：`keyword-scan.js` 文件头保留了批次 0 的"实测代价 2 行"记录，里面写的色名
> （`#79C0FF`、`cyan`、`magenta`）是**批次 A 当时的色板**。批次 E 之后 `percent` 归 `number` 色组、
> `ipv6` 归 `mac` 色组，形状结论不变、色名过期。该处已加限定语，避免后来者按旧色名核对当前色板。

## 9. 风险与取舍

| 风险 | 说明 | 处置 |
|---|---|---|
| 已固化用例翻色 | `highlight-equivalence.spec.js`、`keyword-presets.spec.js`、`keyword-groups.spec.js` 里硬编码的颜色断言会随批次失效 | 这些 oracle 的**前提**（取短裁决 + 组内自治词表）正是 KU 要废除的。逐条按 §8.3 判定新色是否更正确再重定基线；**禁止为过测试回滚家族化**（B-1/B-2 已按此执行两轮） |
| 期望值抄多份 | 换一次色要改预设/取色器/TC 快照/密度用例 4 处，漏一处就是"测试说对、屏幕说错" | §5.7 派生化 + 同源守护用例先报错（B-2 已收口；新增色组时**只改 `COLOR_GROUPS`**） |
| 闸变成"不可动的数字" | 三条阈值是**当前容量结论**（16 / 8.5 / 11.6），不是设计理想值 | 数字旁边必须写实测值与撞车对；批次 C/D 后色组数变化 ⇒ 按 §5.5 回调条件重算，**不许只改闸不改结论** |
| ΔE(1976) 单尺误导 | 蓝段虚高会让"看起来拉开了一倍"实际几乎没变 | G2 用 ΔE(2000) 交叉校验（§5.2） |
| ANSI 主题邻域假设 | G3 只锚内置两套主题 | §5.3 已限定口径；真正的保障来自 KU-6 第 1 条（结构档根本不写 ANSI 名），G3 是补充 |
| 领域组"变空" | Networking/Build 批次 B 后可能只剩 2~3 条专属规则 | 接受。组的意义是"用户可勾选的信号集合"，不是词表仓库；`requires` 机制保证勾业务组自动带上通用档 |
| 通用红档变巨型 | 吸收各领域词后单条 alternation 变长 | 单条 alternation 编译一次、扫一遍，比 10 条规则分别扫更省；可读性由代码里的分域注释块维持。批次 B 实测：`lvlError` 从 8 组分散词表合成一条，全量用例耗时无可观测变化（性能闸见 §8 第 7 条，仍绿） |
| 上收词表把 `requires` 拖进业务组 | Networking/Syslog/Kernel/Git 现在必须依赖 `通用 · 级别与状态` 才有红黄绿 | 这是 KU-2 的预期代价：勾业务组自动带通用档（`requires` 机制），面板上表现为"该组依赖 2 个通用组"。**副作用要记着**：一旦通用档改了词形，所有依赖组同时变——见本批的 JSON 键名事件（§6 批次 B 连带修复表第 1 行） |
| 临时探针的统计口径被当成事实 | 按 `group / family` 聚合的脚本会让同名跨组族互相覆盖，据此误删了 `Query OK` 与 `restart` | 结论一律以 **CI 版 `wordTable()`（按规则对象聚合）** 复算为准；临时脚本只用于定位，不用于裁决（§6 批次 B 连带修复表第 3 行） |
| rank 表成为隐性配置 | 改 rank 即改归属 | `FAMILY_RANK` 显式导出 + spec 锁定全表；新增家族不登记 rank ⇒ CI 失败 |
| 变长后视兼容性 | KU-3 拆段可能被误读为需要后视 | 拆段本身**不依赖后视**（靠 rank 与游标推进）；批次 C 引入的 `port` 语境 lookbehind（`addrBefore`）与 `(?<=\.\d)M` 是**正形约束**而非让位，node 24 的 V8 已支持变长 lookbehind（实测可用）；代码评审禁止再引入 `(?<=…)` 表达**让位** |
| `NAME:NNNN` 歧义 | `redis:6379` 在 compose 语境读作"镜像:tag"，在服务语境读作"主机:端口"，两者都合法 | 按白名单优先裁决：白名单镜像名（rank 30 `image-ref`）赢过端口语境（rank 40 `port`）；`db:5432` 这类非白名单名归 `port`。两条取舍均有矩阵样本存档；若实机出现误判案例，回批次 C 的裁决表增补，不许临时加护栏 |
| `m`/`M` 大小写不可判 | 编译标志恒为 `gi`（两端共用），node 24 无 `(?-i:…)`（实测 `Invalid group`） | 按形制裁决：整数裸字母 = duration，小数/带 B = size；`100M` 被读作"100 分钟"是**已记录取舍**（§3 KU-3）。要真解需 engine 层按字符匹配或自含大小写分支（成本不成比例） |
| 为凑 ΔE 砸语义 | 优化器天然倾向把颜色推到"空着的色相" | G4 色相带把这件事变成显式违规；换色族必须先删色相带登记（§5.4） |
| **零命中判据的语料盲区**（批次 D） | "语料 0 命中"不等于"世界 0 命中"：diff 头、冲突标记、SSH 指纹、短 SHA 在冻结语料外的高频场景（`git diff` 满屏、`ssh` 首连、`git log --oneline`）里其实是常客，删掉后这些行回归素色 | 用户裁决"删零命中"时已把这条摆上台面（§6 批次 D 判据段）。回补路径固定：批次 F 实机 13 类语料截图复核，出现误判/缺失场景 ⇒ 按 KU 契约**回表增补**（新家族登记 rank + 色组 + 矩阵样本），不许临时塞规则 |
| **domain 三片段成为第二真相**（批次 D） | 18 条领域词表并进三条通用 alternation 后，"某词归谁"要看片段内部注释，家族级可追溯性下降（词不再有独立 family 登记） | 片段内保留分域注释（网络/systemd/内核/认证/SQL/Redis/git/k8s 一段一注释）；KU-4 整词探测仍走**生效规则**，词的归属唯一性不因宿主合并而放松——两词撞色会在 CI 现形。若某域词表需要独立开关，恢复路径是拆回带 family 的规则，代价是规则数回升 |
| ~~**INFO/DEBUG 同色**（批次 D 的连带）~~ | 批次 D 后 `word-info` 挂 `debug`（blue），INFO 与 DEBUG 同色 | **已按用户裁决在批次 G 解决**：回补 `info`（ANSI cyan）给 `word-info`；未新增结构真彩色，几何闸不受影响 |
| **闸豁免掩盖密度**（批次 G） | 豁免命中不计入 35% 占比，理论上"一行全是豁免族"会表现为高密度着色 | 豁免边界写入 KU-7：只有 4 个 rank 0 marker 家族 + `fingerprint`；都是边界记号/精确 token；新增豁免须用户裁决 + 单测；同行的非豁免命中照常计入（有反证用例） |
| **短 sha 启发式**（批次 G） | 行首 7–10 位"数字+hex 字母混排"是短 sha 的近似判据，会漏掉纯数字短 sha，也可能误认形如 `abc1234` 的行首词 | docker 12 位 ID 用长度排除、`ED25519`（7 位混排）用黑名单挡住；矩阵里存了反例样本。若实机出现新的误伤，按 KU 契约补黑名单/样本，不加宽判据 |
| **62 条触顶**（批次 G） | 总量 62 是用户裁决的硬上限，G 的 6 条增补已把额度用满 | 下一次增补必须先删一条（零命中或同色可并）或再次请用户裁决；计数用例钉死 `= 62`，任何新增直接失败 |
| **实机与 CI 的构建产物不同步**（批次 F） | electron 主进程读 `work/app/`，前端读 vite 产物；只改 `src/` 时面板文案可能仍是旧值 | 实机验收前必须 `npm run vite-build` + 同步 `work/app/common/locales-extra.js`；F2 已踩过一次（locale 回退显示键名） |

## 11. 落地顺序建议（一次一句话）

A 建机制（family + rank 裁决，不改表）✅ → B 治词表（KU-4）✅ → C 治形状（KU-3，IP 在这一批解决）✅
→ D 收数量（≤62 口径，56 落地）✅ → E 收颜色（KU-6）✅（B-1 + B-2 均已落地）→
F 实机与面板可见化 ✅（F1–F4）→ **G 盲区回表 + 拆色 + 闸豁免 ✅（62 触顶，治理序列收口）**。

每批独立提交、独立跑 `npm run test-unit-ci`；C 与 D 之间不设依赖，可并行但不得合并成一个提交，
否则"删了一条规则导致另一条抢色"无法归因。

> **实际执行顺序的偏差与现状（2026-11-07）**：用户在看完成语料后直接问"颜色是不是太多"，
> 于是 **E 提到 A 之后先做**（B-1、B-2 各一个提交）。批次 D 兑现了这个代价的可接受那一半：
> 删掉的 42 族里有 3 个色组随宿主消失，**在用色的色值一个没动**，四条闸实测值逐字不变。
> 批次 F 复核出 D 的"语料盲区"并实证了 INFO/DEBUG 同色；用户四项裁决（回表增补 / 接受 33 并放宽分项 /
> 拆 INFO、DEBUG / 豁免 marker 层与指纹）构成批次 G，G 只动**归属与豁免**、不动任何在用色与结构色值，
> 因此 F 与 G 可以在同一提交序列内收口。
>
> **现状**：0/A/B/C/D/E/F/G 全部落地；总量 62 触顶、structure 38（修订口径 ≤38）、signal 24、
> 20 色组、53 条家族样本矩阵、keyword 域 114/114。**后续任何增补都必须删一补一，或再次请用户裁决放宽。**
