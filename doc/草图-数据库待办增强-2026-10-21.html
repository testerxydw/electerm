设计取舍与实施顺序

  • T1 / T2 已实施：纯前端、无 IPC、无后端协议变化，已解决“当前页/树里找不到”的高频问题。
  • T7 / T8 已实施：`hasMore` 改为 pageSize+1 探测；数据库页文案统一走 translate。
  • T5 / T3 / T4 已实施：PG 先补主键检测与参数化 updateCell，再补 schema 层级与跨库连接入口。
  • T11 已实施：默认仍用 `TABLE_ROWS` 估算，点击「精确」才执行 COUNT(*)；切换表/排序/页大小/刷新后失效。
  • T9 已实施：docker compose + `npm run test-db-e2e`，默认不进日常单测；本机无服务时自动 skipped。
  • T6 / T10 / T12 本轮不做：WHERE 下沉、国产数据库批次、Redis 类型化写操作按用户决定暂缓。
  • 不改变现有布局：新增控件只占用网格头/树顶部已有空隙，不调整 padding、圆角与 32px 条高。
  • 可访问性：输入框、清除按钮、连接按钮均需键盘可达，焦点环使用现有 `:focus-visible` 规范。
