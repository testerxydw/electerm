一、现状诊断：为什么"粗糙、简陋、不好看"

6 类根因

基于《UI-美化设计规范》《美化实施七维度审计报告》与实测代码（见 `similar` 审计）。

设计 token 太薄 体验

全库仅 15 个颜色变量，没有分隔线/悬停底/遮罩/阴影/圆角/间距/字号/动效/焦点环变量。

圆角 / 阴影不成体系 体验

12 种圆角值 / 45 处；22 种阴影写法，甚至"用背景色假装阴影"。

4 个变量静默失效 缺陷

--border / --hover-bg / --text-color-2 / --text-color-secondary 被引用但从未定义。

darker() 产生非法颜色 缺陷

缺上界钳制，#121214 → #0，导致 29 处声明整条失效。

几乎零动效 体验

67 个 .styl 中仅 8 个有 transition，界面"死板、无反馈"。

浅色对比度不达标 无障碍

--success 在 #ededed 上仅 1.61:1；且无全局键盘焦点可视化。

另有：33 处硬编码颜色、46 处 !important、默认主题 3 份副本不一致、antd 桥接不完整（圆角硬编码 / 动效被关）。

二、目标与设计原则

为什么要改

目标

  • 观感：从"工具"到"产品"——分层、留白、统一节奏、品牌克制点缀；
  • 一致性：圆角 4 档 / 阴影 3 档 / 动效 2 档，全库统一；
  • 可维护：token 化 + 契约单测，杜绝"未定义变量"回归；
  • 结构现代化：命令面板、状态栏、页签化右栏、两级左栏（允许改 DOM）。

原则（红线）

  • 颜色只从既有 12 基色派生（color-mix），不新增必填主题变量（否则主题编辑器保存失败）；
  • 主色面积 ≤10%；分隔用 1px 或 inset box-shadow（避免布局位移）；
  • 正文对比度 ≥4.5:1；全局 :focus-visible；支持 prefers-reduced-motion；
  • 结构可改，但功能零回归、快捷键习惯尽量保留（或给迁移说明）。

三、设计体系（要落地的 token）

全部 color-mix 派生

色阶 4 层 + 交互色

--s0--s1--s2--s3 --hov--act

底→内容→浮起→更高浮起；hover / 激活底。品牌光晕 --glow 用于选中/焦点。

圆角 4 档 / 阴影 3 档

--r-xs 4px--r-sm 8px
--r 10px--r-lg 14px
--sh1--sh2--sh3

动效 2 档 + 缓动

--dur 120ms（微交互）/ --dur2 200ms（浮层）；统一 --ease cubic-bezier(.4,0,.2,1)；只动 background/color/transform/box-shadow/opacity。

字体与栅格

UI：系统栈 + CJK 回退；终端：等宽栈（含 CJK 等宽）。间距 4px 栅格，行高 20/24/28。

六、验收标准

Definition of Done
主题正确：12 主题 × 亮/暗 无颜色错乱，正文对比度 ≥4.5:1
语言统一：圆角 ≤4 档、阴影 ≤3 档；除主题定义外无硬编码颜色
可访问：全局键盘焦点可见；prefers-reduced-motion 生效
零回归：连接 / 终端 / SFTP / AI / RDP / 串口 全功能正常
契约安全：未新增必填主题变量，主题编辑器可正常保存
结构可用：快捷键与交互习惯不退化（或提供迁移说明）
