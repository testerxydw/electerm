## 一、导出与基线（M10 的 T03 部分）

### T03-01（M17）具名导出落地
**通过标准**：`agent.js` 出现 `export function buildAgentSystemPrompt`（零行为变更）。
**【v2 修改】路径自证改源码文本判定**：golden spec 加断言——当 spec 源码文本命中
`/export function buildAgentSystemPrompt/` 时，本轮 `via` **必须**是 `export`，否则红，
失败信息写明「导出存在但 spec 走了抽取，说明模块求值抛错，先修那个错」。理由：v1 的
`loadViaExport()` 返 null 无法区分「没导出」和「导出存在但模块求值失败」，后者会静默
回落抽取，恰好掩盖签名被改坏。
**变异**：把导出改回私有 → spec 的路径自证断言红。

### T03-02（M18）M10 硬门（hasExternal=false）
**通过标准**：未配置任何 server 时，run 开始处 `runTools.length === 36`（F1），且 system prompt
与现基线**逐字符相等**（1824 / `19da66c3…`）。若签名改为 `buildAgentSystemPrompt(config, hasExternal)`，
则 `hasExternal=false` 必须逐字节复现现基线。
**【v2 增补】**缺省参数必须等效 false：现有 golden spec 调用 `buildAgentSystemPrompt(config)`
（单参）就是现成探针——单参调用结果必须与 `(config, false)` 逐字节相同。
**变异**：任意往 prompt 追加一个字符 → 红（golden spec 现成）。

### T03-03（M19）hasExternal=true 新基线冻结
**通过标准**：T03 落地同一提交里，冻结「有外部工具」时的 prompt 新基线（长度 + sha256 + 附录
全文），双路径与 T03-01 同规。基线文本必须含 S4 的**不可信边界声明**（设计 `:43`）。
**【v2 增补】**① 判据文档明写这是**新增输入域**、不是重新冻结旧基线（T03-02 钉旧的不变，
两条并存）；② 边界声明断言用具名常量 + `includes`，变异（删那一段）才精确命中，
避免「随便改个词也红」的过宽断言。
**变异**：删掉边界声明那一段 → 红。

## 二、别名与合并（M5 的 agent 面）

### T03-04（M20）runTools 中的别名契约
**通过标准**：注入 1 个假 server（2 个工具，其一名字含非法字符/超长/重复）后，run 的
`runTools` 里外部项的名称逐条满足 §2.5 规则（`mcp__<7位id>__<清洗名>`、小写、不折叠 `_`、
64 上限走短哈希、同 server 撞名 `_2` 按原始名字典序），且每条违反都产生 warn。
**【v2 增补】**warn 取证点写死：`manager.warnings` 或 `meta.degradationNotes` **二选一，
选定后写进判据文档**，不许实现时再挑（两个取证点并存会让断言两头落空）。
**变异**：把清洗改成「折叠连续 `_`」→ 两个不同工具变同名 → 去重断言红。

### T03-05（M21）内置优先（M5 核心）
**通过标准**：外部 server 提供 `db_insert_sql`（内置同名）与 `DB_INSERT_SQL`（大小写变体）→
两者都不覆盖内置：内置实现行为不变、外部项被跳过、warn 各一条（含 alias）；
`runTools` 里内置 `db_insert_sql` 的 `function` 定义与无外部时**逐字符相同**
（`Function.prototype.toString()` 可行——本仓不做压缩构建）。
**变异**：删掉内置优先分支（builtin.has 检查）→ 外部覆盖内置 → 红两条。

### T03-06（M22）run 级冻结
**通过标准**：run 开始时 `runTools` 冻结为「内置 36 + 外部 N」快照；run 进行中保存设置
（syncConfig 增删 server）**不得**改变本次 run 的工具集。测试层：假 client + 手动触发 syncConfig。
**【v2 增补】provider 视角断言**：第二次请求携带的 `tools` 数组与第一次相同——
「矛盾工具列表」的后果在 provider 侧，只断言 runTools 快照测不到它。
**变异**：把 getTools 调用移进循环体 → 第二轮出现新工具 → 红断言「两轮 runTools 相同」。

## 三、上下文与调用路由（M4/M8 的 agent 面）

### T03-07（M23）toolsTokens 随外部工具增长
**【v2 修改】公式化**（v1「显著增长且单调相关」不可判定，本仓纪律不留"显著"）：
**通过标准**：注入 K 个工具、描述总字节 B → `toolsTokens_after − toolsTokens_before
>= Math.floor(B / 4)`（估算系数 `B/4` 也 **import 常量或与实现共用同一常量**，禁字面量）。
**变异**：合并时漏掉 `openaiTools` 拼接 → 增长 0 → 红。

### T03-08（M24）调用路由与零网络校验
**通过标准**：`executeToolCall('mcp__xxx__echo', …)` 走 `mcpClientCallTool`；
`validateArgs` 失败返回 `{error:{code:'invalid_tool_arguments'}}` 且 **tools/call 往返为 0**
（scripted transport 的 `received` 计数，可判定）；8KiB 降级 schema 放行一切入参（M4-④，显式钉住）。
**变异**：路由分支漏掉外部别名 → 走内置 case 落空 → 红。

### T03-09（M25）M8 循环不 hang
**通过标准**：外部工具永不返回（`--hang`）→ agent 循环在 `timeoutMs+1s` 内拿到结构化错误
作为 tool 结果继续下一轮；主流程总耗时有上界（与 M8 同口径）；错误文案含 server 名。
**【v2 增补】实现注意**：`config-validate` 把 `timeoutMs` 钳在 ≥5000——spec 必须走
per-call 覆盖（实测 `opts.timeoutMs` 可绕过钳制），否则这条用例 ≥5s。
**变异**：错误直接 throw 出 executeToolCall → run 崩或 hang → 红。

### T03-10（M26）tools/list 触发条件（v2 重写版）
**【v2 驳回重写】**v1 的「60s stale 缓存」机制不存在（F6 更正），按真实机制重写：
**通过标准**：`tools/list` 仅在①会话建立②`opts.force` 时发起；签名不变的 `getTools`
不得产生新的 `tools/list` 请求（scripted transport 计数器不变）；run 内多次调用只拉一次。
**变异**：把 `refreshTools()` 从 `if (opts.force)` 分支挪到无条件 → 计数器增长 → 红。
（v1 变异「缓存判断写反」无对象可反。）

## 四、边界与上限

### T03-11（M27）不可信边界包装
**通过标准**：外部 tool 结果一律包进 `<untrusted-tool-result server="<name>">…</untrusted-tool-result>`
（包装在 T03，消毒在 T04）；无外部 server 时包装函数**一次都不执行**（M10 第 7 条）；
server `name` 含 `<>` 的在配置校验已被拒（`config-validate.js:145` regex / `:153` 文案），
包装层不做二次转义（那是 T04 SEC-1 的事，别提前做一半）。
**【v2 增补】取值来源判据**：`server` 属性的取值来源写死——直通 `serverInfo.name` 是
QA-1 之前报过的直通面，判据必须钉住「取值经过哪一层、哪一层负责拒绝危险字符」。
**变异**：包装函数对内置结果也生效 → 破 M10 → 红。

### T03-12（M28）两层上限各司其职
**通过标准**：假 client 提供 200 个外部工具 → `runTools` 外部部分 **≤ 100**（注册层
`schema-slim.LIMITS`，import 常量）且截断元数据（perServer/global）暴露给 UI；协议层
5 页/200 只体现在 `toolsTruncated`，不影响本断言。**两条上限都 import 常量，禁止字面量**。
**【v2 修正】变异方向**：把 `LIMITS.globalTools` 改 20 → **写死 100 的实现红、跟随常量的
实现仍绿**（v1 原文「断言跟随常量变红变绿」方向反了，会被读成断言自己会红）。

### T03-13（M29）历史回放降级
**通过标准**：历史消息里存在引用**已消失别名**的 tool_calls（server 被删/工具被删/改名）
→ 回放时替换为占位 tool 结果（如 `tool no longer available: <alias>`），provider 不收到
未声明的工具名、不 400、agent 不崩。
**变异**：原样透传 → 假 provider 断言「收到未声明工具名」→ 红。

## 五、新增：run 中途取消（M30）

### T03-14（M30）run 中途取消收敛
**通过标准**：run 进行中用户点停止 → 外部 in-flight 请求全部收敛
（`mcp_aborted` / `peer.pendingCount` 归零）、不遗留 dangling promise/timer、
run 结束后不得再发起新请求（计数器冻结）。停止时正挂着外部工具是最常见的真实时序，
T03-09 只测超时，本条测「人主动停」。
**变异**：stop 只置位标志不 abort in-flight 请求 → `pendingCount > 0` → 红。
