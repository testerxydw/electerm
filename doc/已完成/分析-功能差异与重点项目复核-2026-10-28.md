## 1. 调研对象与方法

### 1.1 方法

1. **先核验自己**：以源码为准逐项确认"已有 / 部分 / 缺失"，不沿用旧文档的完成标记（旧文档存在滞后，已发现多处"文档写未做、代码已落地"）。
2. **再对标别人**：同代开源项目看**代码与交互形态**；商业工具只看**功能面与交互流程**，不复制资源与文案。
3. **只保留最终判断**：被推翻的方案、重复的功能清单不写入本文；结论按"价值 × 成本 × 与定位契合度"排序。
4. **许可证纪律**：既有文档已确认的许可证继续有效；本轮新增对象**在核验许可证前一律按"仅参考交互"处理**，不拷贝代码。

## 5. 差距结论与优先级

### 5.1 P0：每天都会用到，成本低，先做

| ID | 内容 | 为什么现在做 |
|---|---|---|
| **H1** | SQL 结果工作台：本地过滤/排序/列显隐、单元格右键、行详情、执行耗时、导出补齐（TSV/JSONL/Markdown） | 最近刚把结果分页/页大小/边框做好，**只差最后一段"能用的结果集"**；DataGrip/TablePlus 的日常手感主要来自这里 |
| **H2** | 数据网格交互：行详情、单元格右键（复制/按值过滤/外键）、数值右对齐 | 值面板已存在，补"行视角"与"右键动作"即可，复用现有 `renderCell`/`formatValue` |
| **U1** | 工作台壳层：工具条分组/溢出、无表选中空态、结果状态行 | 纯前端与 CSS token，风险最低，直接改善"专业感" |
| **U2** | 网格可读性：数值对齐、悬停/选中/焦点、密度选项 | 与 H1/H2 同批做，避免二次改同一批 DOM |

### 5.2 P1：高价值，需新增后端 op 或面板

| ID | 内容 | 说明 |
|---|---|---|
| **H3a** | 数据字典导出（当前表 → Markdown/CSV） | 结构页已能看列；导出复用 `getTableStructure` 的 v2 数据，无新 op；数据库级导出放 P2 |
| **H7a** | Redis 键树 + INFO 汇总 | 键树需全量 SCAN（默认上限 1 万 + 进度/取消）；INFO 只读；db 节点/keyspace 计数已有 |
| **G3** | SFTP 文件预览 | 文本编辑/代码对比已有；**前置**：`readRemoteFile` 加分片与二进制判定，新增只读预览面板 |

> **H5 已撤销（二轮复核）**：`remote-monitor` 已提供 SSH 主机级服务器概览 + 进程列表 + kill，覆盖了 H5 的实际使用场景；数据库引擎级 `SHOW PROCESSLIST/pg_stat_activity` 与主机进程功能重叠且属高危低频，本轮不立项（如需，单列 P3）。

### 5.3 P2：有明确价值，但成本/风险上升

| ID | 内容 | 说明 |
|---|---|---|
| **H3b** | 只读 ER 图 | 需要库级 FK 列表 op + 自写分层布局；不做正向工程 |
| **H4** | 属性级结构对比 | 只比较、不生成 DDL；先同连接两表，跨连接后置 |
| **H6a** | 参数化查询 | 用驱动原生占位符（mysql2 `?` / pg `$n`），不做字符串拼接 |
| **H7b** | Redis 慢日志 / 批量删除 / Stream | 批量删除走 SCAN + UNLINK + 确认；Stream 只读 |
| **G2/G4/G7** | 回放（录制已有） / 远程归档 / known_hosts UI + 密钥生成（后端已有） | 既有设计 §14；只补缺失层，不重做录制与校验 |
| **U3/U4** | SQL 工作区视觉 / 树与 Redis 视觉 | 依赖 H1/H7a 的 DOM 稳定后再收口 |

### 5.4 P3 / 待拍板

| ID | 内容 | 建议 |
|---|---|---|
| **H6b** | AI 生成/修复/优化 SQL | 复用现有 AI 面板，只加提示词与入口；需产品确认"是否允许 AI 直接改编辑器" |
| **H6c** | 查询文件（.sql 保存/打开） | 与收藏并存，不替代；P3 |
| **H8a** | SQLite 引擎 | `node:sqlite` 可用，但同步 API 会阻塞主进程；需评估 worker 化 |
| **H8b** | KingbaseES | PG 协议同源，成本低；信创场景有价值 |
| **H8c** | 达梦 | 原生驱动与平台限制，建议暂缓 |
| **H9** | 表设计器 / 暂存编辑 | **建议不做全量设计器**；若做，只做"索引/注释编辑 + ALTER 预览"，不做建表向导 |
| **G5/G6/G8** | 目录镜像 / Vault / 审计 | 既有设计；G6 风险最高，最后做 |
| **G9** | 隧道运行时管理 | 新增候选：列表 + 启停 + 状态；复用 `ssh-tunnel.js`；现有 tab 列表仅展示 |

### 5.5 明确不做（本轮维持）

| 项 | 理由 |
|---|---|
| 数据/结构同步套件、跨库传输、备份还原 | 需要常驻调度与差异引擎，超出"SSH 客户端 + 轻量 DB 面板"定位 |
| ERD 正向工程（图 → DDL） | 等于第二套建表逻辑，与"不做全量设计器"冲突 |
| 结果图表 / BI / 条件格式 | 依赖图表库与规则模型，收益低于维护成本 |
| SQL Server / Oracle / ClickHouse / Mongo | 驱动、方言、类型系统成本高；本轮不扩 |
| Redis Cluster / Sentinel / Pub/Sub | 连接模型与 UI 复杂度高；先做单机键树/INFO/慢日志 |
| 用户/权限管理 | 高危 + 低频；维持不做 |
| 数据库引擎级会话管理（`SHOW PROCESSLIST` / `pg_stat_activity` + kill） | 主机级进程列表/终止已有 `remote-monitor`，功能重叠；KILL 高危低频；本轮不立项 |
| 事务保存点/嵌套/跨 tab | 与连接池模型冲突；维持不做 |
| 断线续跑 / 会话共享 / 插件市场 / Web 自托管 | 需要服务端或沙箱；维持不做 |

## 6. 风险与工程约束

1. **SQL 结果内存**：结果行已全量留在 `sqlResult.results`，本地过滤/排序是内存操作；超过 5 万行时给出提示并只对当前结果集排序（不做跨结果集），避免误以为全库排序。
2. **执行耗时**：必须在主进程测量（IPC 往返不含网络/渲染误差），返回体新增 `elapsedMs`，旧字段不变；Redis 不适用。
3. **服务器运维边界**：本轮不新增数据库引擎级 processlist/KILL；已有 `remote-monitor` 是 SSH 主机级采集 + 单进程 kill，不涉及数据库会话。若后续立项，必须走 E1 风险门 + 二次确认 + 只读禁用。
4. **Redis 键树**：全量 SCAN 可能很慢；默认上限 1 万、可配置、带进度与取消；不得阻塞主进程事件循环（分块 IPC）。
5. **SQLite**：`node:sqlite` 为同步 API，长查询会阻塞主进程；需限制返回行数/语句时长，或放 worker；无 SSH 隧道。
6. **结构对比**：只做属性级比较，不生成 DDL；跨连接比较需要两边 tab 上下文，先做同连接。
7. **CSS 契约**：只能用 token（`--border/--radius-*/--main/--primary/--hover-bg` 等），不得硬编码颜色/圆角/阴影；`css-hardcoded-colors` / `css-radius-shadow` / `css-tokens` 既有 3 个基线失败不得增加。
8. **i18n**：所有新文案进 `locales-extra.js`，跑 `i18n-coverage`；不得在 JSX 写死中文/英文。
9. **性能**：网格保持虚拟化；SQL 结果过滤/排序用 memo + 防抖；Redis 键树用虚拟列表。
10. **测试**：每批 `npx standard` + `npm run test-unit-ci` + `npm run compile` + CDP 实测（独立端口/profile/DATA_PATH），双主题截图；写操作必须真库回归。
