## 一、批准矩阵（M6）

### T04-01（M6）`decideToolApproval` 6 格决策表
**通过标准**：在 `src/client/common/external-tool-guard.js` 实现纯函数
`decideToolApproval({ meta, trust })`（**签名不含 `tainted`**，F9），并用 spec 对 6 格**逐格**断言：
| trust | `readOnlyHint === true` | requireApproval | reason |
|---|---|---|---|
| readonly | true | false（放行） | — |
| readonly | false/缺失 | **true** | `trust-readonly-blocks-write` |
| ask | true | false | — |
| ask | false/缺失 | **true** | `no-readonly-hint` |
| auto | true | false | — |
| auto | false/缺失 | **false**（用户显式承担） | — |
外加两条最易被「顺手改安全」的钉子：① `trust=readonly` + 无 hint → 弹窗**只给取消、不得有放行按钮**（断言唯一路径）；② `trust=auto` + 无 hint → **`requireApproval === false`**（断言，不是只靠返回值文案）。
**变异**：把 `auto` 无 hint 那格改成 `true`（实现者常「为安全顺手改」）→ 该格断言红。把 `readonly` 无 hint 的 reason 改成非 `trust-readonly-blocks-write` → 断言红。删 `reason` 字段 → 断言红。

### T04-02（M6）审批接线（计数 0 / 恰好 1 次）
**通过标准**：`store/mcp-client.js` 在调外部 server 工具前调用 `decideToolApproval`，并据此弹
`mcp-tool-approval.jsx`（复用 `mcp-transfer-approval.jsx:59-112` 形态，新建）的 `Modal.confirm`：
① `trust=ask` + 无 `readOnlyHint` → 用户**未确认**时**不调 server**（假 client 调用计数 `=== 0`，不只断言弹窗文案），返回 `{cancelled:true}`；
② 用户**确认后恰好调 1 次**（计数 `=== 1`，抓「重复弹窗/重复执行」——只测 0 次抓不到）。
**变异**：把「未确认不调」改成「未确认也调一次（默认放行）」→ 计数断言红。把确认后调用写成循环/二次 `await` → 「恰好 1 次」断言红。

## 二、污染门（M6b）

### T04-03（M6b）`requiresTaintApproval` + taint 生命周期
**通过标准**：在 `external-tool-guard.js` 实现 `requiresTaintApproval(toolName, tainted)` 与常量
`TAINT_GATED_BUILTIN_TOOLS = ['sftp_upload','sftp_download','sftp_del','db_insert_sql']`（F9）。
spec 覆盖：① `taint=true` → 4 个内置写工具**各弹一次确认、未确认不执行**；
② **`taint=false` → 4 个都不弹**（反向断言，防「恒弹窗」蒙过）；
③ `taint` **不跨轮**：新 run 开始时必须为 `false`；
④ 非 `TAINT_GATED` 的内置工具（如 `list_tabs`）在 `taint=true` 时也**不**弹（防「tainted 后所有工具都问」让 agent 不可用）。
**变异**：把 `taint=false` 分支也返回 `true` → ② 反向断言红。把 `list_tabs` 误列入 `TAINT_GATED` → ④ 断言红。把「新 run 不清零」→ ③ 断言红。
