一、现状：为什么"没有画质设置"这句话只对了一半

入口有没有证据
书签表单两个 0-9 数字框有，一直有src/client/components/bookmark-form/config/vnc.js:38-39（qualityLevel / compressionLevel）
会话顶栏没有src/client/components/vnc/vnc-session.jsx:757 renderDisplayItems = 选屏 + 缩放 + 挂起策略
⋮ 菜单没有src/client/components/vnc/vnc-session.jsx:853 只传重连 / 全屏 / Ctrl+Alt+Del
首连读值有，但只读一次src/client/components/vnc/vnc-session.jsx:252（解构默认 3/1）、:450-451（rfb.qualityLevel =）
  • 所以现在的路径是：改书签 → 重连 才见效。顶栏加一颗档位 Select 的本质，是把"必须重连"换成"当场发 SetEncodings"。
  • 顶栏先例已经有了：RDP 左栏就是 Select（分辨率）+ ✎（自定义）+ Switch（缩放）（src/client/components/rdp/rdp-session.jsx:980-1011），VNC 加画质走同一套视觉语言，不需要新控件形态。
  • 按 host 记忆也已有先例：vnc-session.jsx:56 的 vnc-scale-view-${host} + src/client/common/remote-adapt.js:87 的 resolveScaleViewport(本机记忆, 书签值)。

二、三个方案

方案形态占宽能力问题
A（推荐）左栏一颗档位 Select，「自定义…」弹两条 0-9 滑杆约 +96px预设覆盖 95% 场景，滑杆保住精确控制多一个 Popover 锚点（这块踩过 rc/dom-align 的坑，见风险表）
B左栏一个图标，点一下三档循环约 +24px只有 3 档可发现性差：看不出当前是哪档，还得配 Tooltip
C收进 ⋮ 菜单0同 A与已定口径冲突：P-7 拍板"显示控件留左栏、⋮ 只放动作项"（doc/分析-远程会话顶栏差异与统一-2026-10-30.md §5）

三、档位映射（待拍板）

点一行即切到该档，上面顶栏与读数区跟着走。两个轴的语义：Q 越高越清晰但数据量越大；C 越高越省带宽但越耗 CPU，C=0 编码最省 CPU。

档位QC意图对照
流畅26高延迟 / 弱网：画面糊但响应快比现默认更低质量、更高压缩
平衡31桌面日常= 现书签默认（fix-bookmark-default.js:36），行为零变化
清晰62文字、截图、远程办公主流用法= noVNC 出厂默认（rfb.js:304-305）
精细82看图 / 设计稿，局域网带宽明显上去
省带宽59弱网但要能读字：CPU 换带宽压缩拉满，CPU 占用最高

四、数据口径（优先级与写入面）

  • 首连：本机记忆(按 host) > 书签字段 > 出厂默认 3/1。做法与缩放开关完全同构：在 remote-adapt.js 加一个 resolveQuality(local, tabQ, tabC)，vnc-session.jsx:85-97 的 constructor state 里决策一次。
  • 首连接线必须改：vnc-session.jsx:450-451 现在喂的是 tab 解构值；记忆生效后要改成喂 this.state 的决策值，否则"栏内记忆只在重连后生效、首连又读书签"——缩放开关当年的注释（vnc-session.jsx:306-308）写的就是这个坑。
  • 运行中改：写 rfb.qualityLevel/compressionLevel + 写 ls 记忆；不回写 tab / 书签（与 handleScaleViewChange 同口径：vnc-session.jsx:737-742 只 setState + ls）。
  • 重连 / 挂起恢复：handleReInit（vnc-session.jsx:748）新建 RFB 后走同一条 remoteInit，值来自 state，天然一致；这条要写成单测判据。
  • 未连接（loading / error）：Select 置灰，别让人点了没反应。

五、风险与边界

风险事实设计上的处理
点了画面没变Q/C 是伪编码提示，只对 Tight / JPEG / H264 有意义；server 走 raw / ZRLE / zlib 直接忽略面板底部一句常驻说明（草图里有）+ 可选"当前编码"回显（见下条）
没有生效证据noVNC 1.7 没有 stats / 带宽回显 API：本轮 grep 过 getStats / encNames / kbytesPerSec 在 rfb.js 与 display.js 里全零命中三档力度：① 只读回 rfb.qualityLevel；② 假 ws 解 SetEncodings 报文（实机判据，草图右卡）；③ monkey-patch 记 rfb._FBU.encoding（解码分派在 rfb.js:2977，_decoders 表在 rfb.js:177-258，名字现成可用 core/encodings.js:40 encodingName()）—— 只有 ③ 能区分"收了但没用"
改完不动画面看不出来SetEncodings 只影响后续帧面板文案直说"动一下远端鼠标才有变化"，不做假动画
Popover 定位rc/dom-align 沿 offsetParent 链量坐标；顶栏是 position: relative（session-shell.styl:22），页签色卡那次改成 fixed 直接把弹层甩到 -19178,-10778自定义面板锚在 Select 自身（保持在栏的绝对定位体系里），不新建 fixed 层；实机加一条"卡片矩形落在栏内"的判据
顶栏变挤 / 换行条高单点 --session-bar-h 32px（tokens.styl:92），栏 flex-wrap: wrap（session-shell.styl:25）窄窗切到 2 行 = 64px 是既有行为；草图右上「窄窗」按钮可看效果，实机补一条"换行后条目不丢"
词条新 key 落 src/app/common/locales-extra.js，中英各一条（qualityLevel 已有，vncQualityPreset 等要新加）改 src/app 后必须 cp -r src/app/. work/app/ 再跑 CDP，否则界面回退成首字母大写的 key（本轮 clearTabColor 刚踩过）；判据用 window.__hasKey 直查语言包表
不做的事—不动分辨率（VNC 远端尺寸由 server 决定，那条是 doc/TODO 的 P-6 / V3，另案）；不动 VNC 中继（src/app/server/session-vnc.js:48 的 width/height 只记账，与本方案无关）

七、验收判据（草案）

  • 单测：预设映射与 Q/C 常量一致；remoteInit 里喂给 rfb 的必须来自 state 决策值（正则钉 rfb.qualityLevel = this.state）。
  • 实机：① 未连接时 Select 不可点；② 选"清晰"后 ws 出口报文含 -26 / -254；③ 拖滑杆到 8/3 后连续两次改动只发一帧 SetEncodings（setter 判等）；④ 断开重连后读回 rfb.qualityLevel === 8；⑤ 全程零未捕获异常；⑥ 书签 qualityLevel 字段全程不变（不回写）。

证据均来自本轮对码：noVNC 1.7.0（node_modules/@novnc/novnc/core/rfb.js / encodings.js）与 electerm HEAD b093109a。
