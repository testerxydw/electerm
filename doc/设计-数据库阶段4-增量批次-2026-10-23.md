## 1. 范围与结论

1. **先补地基，再加功能**。`describeTable` 只有 4 个字段（无注释/索引/外键）、对象树无视图、二进制列导出即丢数据——数据字典、结构对比、外键导航、ER 图、表头注释全部卡在这份契约上。补齐契约后，这几项成本同步下降。
2. 数据库线 9 批：**A（编辑器+补全）→ F0（元数据契约）→ E1（安全带）→ E2（视角）→ F1+F3（外键/值呈现）→ C（导入导出）→ B（收藏模板）→ D（EXPLAIN+Redis 写）→ F2（事务）**。
3. 非数据库线 8 批（G1~G8）与数据库线**无代码依赖**，可交错实施。唯一交叉点是 `production` 语义（E1 定义，G1/G5/G6 复用）。
4. P2 保留项（数据字典、结构对比、ER 图、服务器概览、参数查询、AI SQL、暂存编辑）在本轮之外，但地基补齐后其成本已可估算。

**排布理由**：

- **F0 紧跟 A**：纯主进程、无 UI、可独立验证；放前面让 E2 表头注释、F1 外键、P2 数据字典全部就绪
- **E1 在 E2 前**：安全网先于写入口扩张
- **E2 在 C 前**：E2 改 `getPageData` 契约，C 的"所见即所导"依赖它，倒序会二次改造
- **F1+F3 在 C 前**：二者只读、风险低；F3 修掉二进制导出缺陷，C 才不会带 bug 上线
- **F2 最后**：唯一改连接生命周期的批次，出问题面最大

**G 批顺序**：`G1 → G2 → G3 → G4 → G5 → G7 → G8 → G6`

## 4. A 批：SQL 编辑器 + 三层补全

### 4.1 选型：CodeMirror 6

| 维度     | CM6（选）                                    | Ace（备选）           | 保持 textarea |
| ------ | ----------------------------------------- | ----------------- | ----------- |
| 构建链    | 原生 ESM，vite 直接 tree-shake                 | UMD，需兼容垫片         | 无           |
| 补全 API | `CompletionSource` promise 式，适配"异步懒加载列信息" | callback 式        | 自研浮层        |

### 4.3 后端契约

扩既有 `dbClientOp` 的 `OP_MAP`（**不新增 IPC 通道**）：

```
listColumns({ database, schema? }) → { tables: [{ table, columns: [{ name, type, pk }] }] }
```

- MySQL 走 `information_schema.COLUMNS` 单库一次查询按表分组；PG 走 `information_schema.columns` 带 `table_schema`
- 主进程 `instances[tabId]` 挂 `columnsCache`，切库/刷新失效；超时归入 default 15s
- Redis 不注册（无表概念，前端隐藏入口）

### 4.4 引擎：三层架构（`src/client/common/db-sql-complete.js`，零依赖）

单层 token 扫描（dbgate 式）不够：CTE 列无来源、场景判定缺失、字符串/注释内乱弹。但也不必做 7008 行。取中间路线：**结构照 DBeaver，分层照 DBX，只做必要子集**。

| 层      | 职责                                    | 关键函数                                                                                                                                                  | 估算     |
| ------ | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| L1 词法  | 去注释/字符串掩码、语句区间切分、尾随标识符解析              | `maskSqlLiterals(text)`→`{masked, literals[]}`；`statementSpanAt(text, cursor)`；`parseTrailingIdentifier(before)`→`{prefix, qualifier, start, quoted}` | ≈250 行 |
| L2 源解析 | CTE 定义、FROM/JOIN 源与别名、子查询别名、INSERT 目标 | `scanCtes(stmt)`；`extractSources(masked)`→`[{name, alias, kind:'table'\|'cte'\|'subquery', columns?}]`；`detectInsertTarget(before)`                   | ≈350 行 |
| L3 场景  | 判定该出什么，产出并排序                          | `buildCompletionContext(text, cursor, opts)`；`buildCompletions(ctx, meta)`                                                                            | ≈450 行 |

**降级原则**：任何一层解析失败都不抛错，该层判定退化为 `unknown`，最终退化为"关键字 + 表 + 已引用源列"全量候选。**绝不允许因解析失败而"不弹补全"**——那比不准确更差。

### 4.5 上下文判定表（L3 规则）

| 光标前形态                                                         | 只补                             | exclusive |
| ------------------------------------------------------------- | ------------------------------ | --------- |
| `FROM` / `JOIN` / `UPDATE` / `DELETE FROM` / `INSERT INTO` 之后 | 表 + schema                     | ✅         |
| `alias.` / `table.` / `schema.table.`                         | 该源列（源不存在时退化为全库列并标注）            | ✅         |
| `INSERT INTO t (`                                             | `t` 的列（未命中 `listColumns` 退化全量） | ✅         |
| `ON <expr> =` 且已引用 ≥2 源                                       | 另一侧源的列（成对建议 `b.user_id`）       | ✅         |
| `ORDER BY` / `GROUP BY` 后                                     | SELECT 别名（优先）+ 已引用源列           | ❌         |
| `CREATE TABLE ... (` / `ADD COLUMN` 类型位                       | 数据类型名（按引擎过滤）                   | ✅         |
| `CALL` / `EXEC` 后                                             | 过程（本期退化为表 + 提示"过程列表暂不可用"）      | ✅         |
| 字符串 / 注释内                                                     | **不弹**                         | —         |
| 其余                                                            | 关键字 + 表 + schema + 已引用源列       | ❌         |

**评分表**（采纳 DBeaver kind→priority，两处 electerm 扩展）：

| 类型                                | priority |   | 类型                    | priority  |
| --------------------------------- | -------- | - | --------------------- | --------- |
| `joinCondition`                   | 0        |   | `variable`（扩展，本期不产出）  | 225       |
| `column`                          | 100      |   | `schema` / `database` | 250 / 275 |
| `selectAlias`（扩展）                 | 120      |   | `type`（DDL 类型位）      | 300       |
| `relatedTable`（本期并入 table）        | 150      |   | `function`（扩展，内置函数）   | 350       |
| `table` / `cte` / `subqueryAlias` | 200      |   | `keyword`             | 400       |
| `pseudoColumn`（本期不产出）           | 500      |   |                       |           |

同 priority 内排序：前缀命中（`startsWith` > `contains` > 子序列）→ 名称长度 → 字典序。总上限 50（CM6 `maxRenderedOptions`）。

### 4.6 补全项模型与 CM6 接线

```js
{ label:'user_id', apply:'b.user_id', type:'property', kind:'column', priority:100,
  detail:'bigint · NOT NULL', replaceFrom:12, replaceTo:15, filterMode:'quote-aware' }
```

接线六条，逐条必须落到代码：

1. `autocompletion({ override:[source], activateOnTyping:true, maxRenderedOptions:50 })`，不用默认 `completeFromList`
2. 每个 option 提供自定义 `apply`，用 `replaceFrom/replaceTo` 替换，**不依赖** `from`+`label` 默认插入
3. **引号前缀坑**：光标在 `` `test_ `` 内时若 `from` 落在反引号上，CM6 会用含反引号的文档文本匹配不含反引号的 label，**候选全被过滤、菜单空白**（DBX #12008）。
   落地时改用**治根因**的解法：`from` 直接跳过开引号（`parseTrailingIdentifier` 返回 `from` 不含引号、`tokenFrom` 含引号），文档片段因此只剩 `test_`，与 label 天然可比；插入时若引号未闭合再补一个引号字符。
   比 `filter:false` 更稳——后者会让**所有**候选无条件通过过滤，等于把匹配交给用户的眼睛
4. 片段（INSERT/SELECT 骨架、函数签名）用 `snippetCompletion`，占位符 `${1:table}`，apply 后光标落第一个占位符
5. `validFor` 只给纯标识符前缀的候选；带 `alias.` 或引号的**不要**用 `validFor`（光标一动结果即失效）
6. 补全**不发任何请求**，只读 `columnsCache`

### 4.7 实现纪律

1. **方言表驱动**：`src/client/common/sql-dialects.js` 导出 `{keywords, builtin, types, quote, hashComment, dollarQuote}`；`SQLDialect.define()` 由其生成，用 `Compartment` 挂载，切连接时 `dispatch({effects: compartment.reconfigure(...)})` **不重建编辑器**（别把关键字写死在 `db-highlight.jsx` 里）

### 4.9 验收

1. `SELECT * FROM us` → `users`；`FROM users u WHERE u.` → `u.` 的列；`DELETE FROM` 后不出列
2. `WITH recent AS (SELECT id,user_id FROM orders) ... FROM recent r WHERE r.` → 补出 CTE 两列
3. `SELECT * FROM (SELECT id FROM t) x WHERE x.` → 补出 `id`
4. `INSERT INTO users (` → 只出该表列
5. `... JOIN users u ON o.user_id = u.` → 只出 `u` 列，候选排在 `user_id` 附近
6. `WHERE name = 'ord` → **不弹**；`-- from us` 注释内 → 不弹
7. ``SELECT * FROM `us`` → 弹且**候选非空**
8. 多语句 `SELECT 1; SELECT * FROM us` 光标在第二条 → 只按第二条解析
9. mysql/pgsql 方言分别高亮；主题切换无残留色值
10. 页面查找在编辑器内定位命中；只读模式可选中复制不可编辑
11. 单测：L1 ≥15、L2 ≥18、L3 ≥25、外壳契约 ≥8；`npm run compile` 通过，dist 增量 ≤150KB

### 4.10.3 SQL 历史单条删除：悬浮 X / Delete 键（`test.259`）

## 5. F0：元数据契约 v2

**目标**：一次查询拿全"可展示 + 可对比 + 可导航"的结构信息，供 F1/F3/E2/P2 复用。**纯主进程，无 UI，可独立提交与回滚。**

### 5.1 契约（超集，旧字段不变，老前端零改动可跑）

```js
{
  columns: [{
    name, dataType, nullable, defaultValue, isPrimaryKey,   // 既有，保持兼容
    ordinal,                    // 列顺序（结构对比用）
    comment: string | null,
    maxLength: number | null,
    isBinary: boolean,          // 供 F3 判定
  }],
  indexes: [{ name, unique, primary, columns:[name], method }],
  foreignKeys: [{ name, columns:[local], refSchema, refTable, refColumns:[ref],
                 onDelete, onUpdate }],
  comment: string | null,       // 表注释
  estimatedRows: number | null,
}
```

`getMetadata` 增视图（与表并列，`type:'view'`）：PG 走 `pg_views`，MySQL 走 `information_schema.VIEWS`；视图在 UI 上只读（E1 安全带同样生效）。

### 5.2 实现要点

- **PG**：列注释 `col_description()`；索引 `pg_index`+`pg_attribute`（`indisunique/indisprimary`）；外键 `pg_constraint(contype='f')` + `confupdtype/confdeltype`；表注释 `obj_description()`
- **MySQL**：`information_schema.COLUMNS(COLUMN_COMMENT, COLUMN_TYPE, ORDINAL_POSITION)`；`STATISTICS`（`NON_UNIQUE/INDEX_NAME/SEQ_IN_INDEX`）；`KEY_COLUMN_USAGE` + `REFERENTIAL_CONSTRAINTS`（`DELETE_RULE/UPDATE_RULE`）；`TABLES(TABLE_COMMENT, TABLE_ROWS)`
- **Redis**：`describeTable` 不适用，`dbClientOp` 层保持"op 不存在即报清晰错误"
- **不做全库预取**：按需加载（点表才查）+ 结果缓存 60s（大库数千表时三条 SQL 串行会慢）


### 5.3 验收

1. 同一张含注释/复合索引/外键的表，PG 与 MySQL 返回结构一致（字段名一致，值按引擎实际）
2. 空表/无注释/无索引/无外键不抛错，返回空数组而非 `undefined`
3. 视图节点带 `type:'view'`，点击不进入编辑态
4. 两引擎各一份 mock fixture + 映射函数纯函数测试（不打真库）

### 5.4 实施记录（`4d52f128`，`test.260`）

**落地形态：新开 op，不动 `describeTable`。** 老 `describeTable` 返回的是引擎原始行数组
（MySQL `Field/Type/Key/Extra`、PG `column_name/is_primary_key/...`），前端有 4 处直接吃这个形状
（插入行表单归一化、行定位列判定、结构面板）。把它的返回值改成契约对象会同时打破"老前端零改动"和
"两引擎字段名不同"这两条现有假设，所以新增 `getTableStructure` 返回契约对象，旧 op 留到 E2/F1 迁完再删。

| 层 | 文件 | 职责 |
|---|---|---|
| 映射（纯函数） | `src/app/lib/db-client/structure-v2.js` | 两引擎原始行 → 同一份契约；所有归一化（'YES'/'NO'、-1、单字符 FK 码、'' 注释）只在这写一次 |
| 适配器 | `mysql.js` / `postgres.js` 的 `getTableStructure` | 各 4 条 catalog 查询，**并行发**；映射层**惰性 require** |
| 分发 | `index.js` | op 注册（仅两 SQL 引擎）+ 60s 缓存 + 失效 |

契约（`finalizeStructure` 保证这 6 个键永远存在，缺的就是 `[]`/`null`）：

```js
{ type: 'table'|'view', columns: [...], indexes: [...], foreignKeys: [...],
  comment: string|null, estimatedRows: number|null }
// 列：name dataType columnType nullable defaultValue isPrimaryKey ordinal comment maxLength isBinary
// 索引：name unique primary columns[] method      外键：name columns[] refSchema refTable refColumns[] onDelete onUpdate
```

**几处非显然的决定**：

| 决定 | 原因 |
|---|---|
| 映射层在函数内 `require` | 放顶层后，所有用 `vm` + `require` 白名单加载适配器的单测（4 个 spec）都要跟着加桩——一个纯映射模块不该改变别人的测试装配 |
| 主键双写（列级 + 索引级） | 列级标记是补全/行定位在读，索引级是 F1 侧栏在读；PG 列查询里拿不到列级 pk 时从 `primary` 索引反推补上，避免两处判断不一致 |
| 表达式索引保留（`columns: []`） | `CREATE INDEX ON t (lower(x))` 没有列名但确实是索引，滤掉会让结构面板少一条 |
| 无名索引/外键丢弃，不补 `index_1` | catalog 里缺名的是脏数据；编造名字会把垃圾混进契约 |
| `maxLength`：字符长度优先、二进制列退字节长度 | utf8mb4 下 `OCTET_LENGTH` 是字符数的 4 倍，直接展示会误导；PG 的 `bytea` 本来就没有长度 → `null` |
| 行数估算 `-1 → null`、`0` 保留 | PG `reltuples` 未 analyze 时是 -1；真空表的 0 是事实不是未知 |
| 结构缓存 60s + 同键并发去重 + 过期回退 | 每次点表 4 条查询；补全/表头会反复触发。过期后重查失败时返回旧值——表头整块变空比显示 60s 前的结构更糟 |
| `executeSql` 后清结构缓存 | 用户可能刚跑过 ALTER，60s 内还拿旧列会让表头与真实表对不上 |

**视图带来的连带修复（必须同批做，否则是回归）**：
`getMetadata` 开始返回 `type:'view'` 后，前端三处树分支（过滤 / 搜索展开 / 渲染）原来只认
`node.type === 'table'` 判叶子 —— 视图会被当成 schema 画成带 `S` 标记的空节点、点不开。
统一提成 `isLeafNode(node) = table || view`；SQL 补全的 `flattenTables` 也一并收视图（`FROM view` 很常见）。
视图的"只读"由既有机制兜底：视图无主键 → 行定位列为空 → 单元格编辑入口天然关闭；
插入行入口的显式禁用归 E1 安全带（`test.260` 只保证能选、能看、不误判成 schema）。

**验收对照**：

| 验收项 | 结论 |
|---|---|
| 1. 同一张表 PG/MySQL 结构一致 | 同一份 fixture 分别喂 `fromPg`/`fromMysql`，断言根键与列/索引/外键键集合**完全相等**（值按引擎实际：如 `columnType` 一处 `character varying(64)`、一处 `varchar(64)`） |
| 2. 空表/无注释/无索引/无外键不抛错 | `finalizeStructure()` 空入参返回完整空结构；`-1`/`''`/非数字各自降级为 `null`/`0` |
| 3. 视图节点 `type:'view'` | MySQL `information_schema.TABLES.TABLE_TYPE`、PG `pg_class.relkind in ('v','m')`；适配器与树两级断言 |
| 4. 两引擎 fixture + 纯函数测试 | 新增 `db-structure-v2.spec.js` 23 条：同构、边界、vm 假驱动适配器（含"表不存在要报错"）、视图节点、op 注册与缓存接线 |

## 6. E1：危险 SQL 分级 + 连接级安全带

**目标**：在"会改数据/结构"的执行前加一道**可解释**的闸门，防 `DELETE`/`UPDATE` 忘写 `WHERE`。

### 6.1 分级器（`src/client/common/db-sql-risk.js`，零依赖 ≈350 行）

```js
splitStatements(sql, dialect)     // 引号/转义感知切分 → [{text, start, end}]
classifyStatement(stmt, dialect)  // → { level, firstKeyword, reasons[] }
classifySql(sql, dialect)         // 多条取最高级别 → { level, statements[], reasons[] }
```

分级规则（先 `maskSqlLiterals` 去注释/字符串，防"注释藏语句"）：

| 语句                                                                | level               |
| ----------------------------------------------------------------- | ------------------- |
| `SELECT` / `EXPLAIN` / `SHOW` / `DESC` / `WITH ... SELECT`        | read                |
| `INSERT` / `REPLACE`                                              | write               |
| `UPDATE` / `DELETE` 且 WHERE 非空、非 `1=1`/`true`                     | write               |
| `UPDATE` / `DELETE` 无 WHERE 或 WHERE 恒真                            | **dangerous**       |
| `CREATE` / `ALTER` / `RENAME`                                     | ddl                 |
| `DROP` / `TRUNCATE` / `GRANT` / `REVOKE` / `FLUSH` / `SET GLOBAL` | **dangerous**       |
| `BEGIN` / `COMMIT` / `ROLLBACK` / `SAVEPOINT`                     | transaction         |
| 解析失败 / 其他                                                         | unknown（按需确认处理，不阻断） |

### 6.2 确认策略

| level              | 行为                            |
| ------------------ | ----------------------------- |
| read / transaction | 不弹                            |
| write              | 首次弹；可勾"本会话该连接不再提示低风险写"（仅内存）   |
| ddl                | 每次弹                           |
| dangerous          | 每次弹；production 连接额外要求**输入库名** |
| unknown            | 弹，文案说明"无法识别语句类型"              |

**防"确认疲劳"**：只对 dangerous 每次弹；弹窗必须展示**判定理由**（"第 1 条 DELETE 无 WHERE"），不是只有"确定/取消"。一批多目标只问一次（按 scope 记忆，上限 50）。

### 6.3 连接级安全带（`dbBookmark.production`）

执行时分级之外，加**连接维度**的开关（TablePlus Safe mode 的等价物）——挂在连接上才可持续，不会每次弹窗致盲：

- 书签新增 `dbBookmark.production: boolean`（默认 false，连接编辑弹窗一个勾选 + 说明）
- production 连接下：非 read 语句 → 弹确认且**需输入库名**；`updateCell/insertRow/deleteRows` → 二次确认（带表名与影响行数）
- 会话内"临时解除"有效 5 分钟，到期自动恢复，工具条常驻提醒
- 非 production 连接 → 走 6.2 的两级确认

### 6.4 UI

单个 `DangerConfirmDialog`：头部 = 级别徽标 + 环境徽标 + "将执行 N 条语句"；体部 = 语句折叠列表（每条首 2 行，可展开，等宽字体）+ `reasons` 要点；底部 = production+dangerous 时出现库名输入框，按钮 `取消` / `仍要执行`（危险态红色）。

**契约**：不改 IPC；在现有执行入口（`dbClientOp('query')` 调用点）前插一道 gate，返回真值才继续。

### 6.5 验收

1. 12 类语句分类正确；`WHERE 1=1` / `WHERE true` 判 dangerous
2. 注释里的 `DROP` 不算；`SELECT 'DROP TABLE x'` 判 read；多语句取最高级
3. production 连接下 dangerous 语句必须输对库名才放行；取消则零执行
4. 临时解除 5 分钟后自动恢复（假时钟测试）
5. 只读模式下执行入口本已禁用（不弹）
6. 单测 ≥24 例（MySQL 反斜杠转义、PG `E'...'`、`$tag$`、Windows 换行）

## 7. E2：结果集视角

**目标**：把"翻页看数据"升级为"按条件看数据"，并让"看到的"可复用到导出。

### 7.1 模型（`src/client/common/db-grid-view.js`，零依赖 ≈320 行）

```js
FILTER_OPS = ['eq','ne','gt','gte','lt','lte','contains','startsWith','endsWith','in','isNull','notNull']
normalizeView(view)                    // 兜底/裁剪/去空条件
buildWhere(view, columns, dialect)     // → { clause, params, rejected[] }
buildOrderBy(view, columns, dialect)   // → 'id DESC, name ASC' | null
viewKey({connectionId, dbName, schema, table})
```

- **列白名单**：`columns` 来自 `describeTable`；不在白名单的条件丢弃并计入 `rejected`（UI 提示"2 个条件引用了不存在的列"）
- **值一律绑定**：`?`（mysql）/ `$n`（pg）；`contains/startsWith/endsWith` 走 `LIKE` 且转义 `%_\`
- `in` 按元素个数展开占位符，上限 200；`isNull/notNull` 无值
- 排序多列，列名走白名单 + 引用符

### 7.2 双模式入口（构建器 ⇄ SQL）

多数用户不会写 WHERE。正确形态是**默认构建器 ⇄ 一键切原始 SQL**，两者共用同一个 `whereDraft` 字符串——构建器只是"字符串生成器"，契约不变：

```
[视角条] [漏斗 条件 N] [WHERE 输入] [排序 chips] [页大小] [SQL] [重置]
  构建器模式：列▾ 算子▾ 值__ [＋条件]  → 生成片段追加到 whereDraft
  SQL 模式：whereDraft 原文可直接编辑
  切回构建器：解析失败则保留 SQL 模式并提示"条件含手写表达式，无法结构化"（不静默丢条件）
```

算子按类型裁剪：数值（= ≠ > ≥ < ≤ BETWEEN IN）、字符串（= ≠ LIKE 前缀/包含/结尾、IN）、日期（区间）、布尔、NULL。

### 7.3 后端契约（扩 `getPageData`，不新增通道）

```js
getPageData({
  database, table, page, pageSize,
  orderBy?, order?,                  // 既有：单列 + 方向（保留兼容）
  where?: string,                    // 新增：条件体（不含 'WHERE'）
  whereParams?: any[],               // 新增：与占位符顺序一致
  orderClauses?: [{column, desc}],   // 新增：多列排序
  count?: boolean                    // 新增：true 时只回 total
}) → { rows, total?, columns? }
```

**主进程二次校验 `assertSafeClause(clause, columns, dialect)`（不信任渲染层）**：

1. 长度 ≤ 4000
2. 掩码字符串字面量后不得出现 `;`、`--`、`/*`、`#`
3. 标识符 token 必须在"列白名单 ∪ 函数白名单（count/sum/avg/min/max/coalesce/cast/ifnull/now/date/lower/upper/round/abs）"内
4. 括号配平；禁 `SELECT/INSERT/UPDATE/DELETE/DROP` 等语句关键字出现在子句
5. 失败 → 抛可读错误，**不执行**

### 7.4 持久化

- 通道 `dbGridViewOp('get'|'save'|'remove'|'list')`，文件 `userData/db-grid-views.json`
- **不能存 localStorage**：本项目 UI server 动态端口导致 origin 漂移，跨启动会丢（`db-sql-history.js` 头注释已记录）
- 结构 `{version:1, views:{'<conn>|<db>|<schema>|<table>': view & {updatedAt}}}`，键上限 200，按 `updatedAt` LRU 淘汰
- 只存条件/排序/页大小/隐藏列/列宽/列序，**不存结果、不存凭据**；表不存在时静默丢弃

### 7.5 附带三个小改

| 改动               | 做法                                                                            | 成本    |
| ---------------- | ----------------------------------------------------------------------------- | ----- |
| 表头两行（列名 + 注释）    | `describeTable.comment` → 表头第二行小字，无注释时不占高度                                    | ≈60 行 |
| 数值/日期 locale 格式化 | 仅渲染层 `Intl.NumberFormat/DateTimeFormat`，编辑时用原值；`dbFormatLocale: 'none'\|'os'` | ≈80 行 |
| 列宽/列序记忆          | 复用视角存储结构，加 `columnWidths/columnOrder`                                         | ≈60 行 |

**命令面板**（`Ctrl/Cmd+K`，`Ctrl/Cmd+P` 不抢占）：四类来源 = 数据库对象 / 动作（执行·格式化·解释·导出·新建查询·切只读·刷新·收藏）/ 历史前 20 / 当前表相关。打分 = 前缀 100 / 子串 60 / 子序列 30 + 类型权重（动作 20 > 对象 10 > 历史 5），上限 30 分组展示。`db-quick-open.js` 纯函数 ≈180 行 + 组件 ≈220 行。

### 7.6 验收

1. 两列条件 AND + 两列排序 + 翻页，结果与手写 SQL 一致
2. 值含 `' OR 1=1 --` 时按字面值匹配，不劫持分页
3. 手写 WHERE 含 `;`/注释/`DROP` → "应用"禁用并提示；主进程直接调用同参数也拒绝
4. 隐藏列不影响导出列集（导出按当前可见列 + 当前条件）
5. 重启后视角恢复；"重置"清除并删键；列被删后旧视角静默降级
6. 条件变更不闪烁空表（先 `count` 再取页）
7. 单测：`buildWhere` ≥16、`buildOrderBy` ≥6、`assertSafeClause` ≥14（注入样本）、LRU ≥5、命令面板 ≥12

## 8. F1：外键引用侧栏

**交互**：选中单元格 → 值面板旁出现「关联」页签。两个方向必须分开命名，避免"谁引用谁"的歧义：

- **被引用（父行）**：当前列是外键 → 父表对应行（`WHERE refPk = value`）
- **引用（子记录）**：其他表以此为外键指向本行 → 每个外键一条分组（`WHERE fkCol = value`）

**契约**：复用 E2 扩参后的 `getPageData`（不新增 op）。唯一前置是反向查询"哪些表指向本表"：

```js
getReferences({ database, schema, table, columns }) →
  [{ schema, table, fkName, columns:[...], refTable, refColumns:[...] }]
```

PG 用 `pg_constraint` 反查，MySQL 用 `KEY_COLUMN_USAGE`。

**边界**（写清以免膨胀）：只读列表，不在侧栏里编辑父行；单页 50 行 + "在标签页打开"；无外键时页签隐藏；复合外键只支持全列等值匹配。

**成本**：op ≈120 行 + 侧栏 ≈180 行。  
**验收**：单条/复合/无外键三态；MySQL 只读账号无 `information_schema` 权限时页签降级隐藏 + 一行提示，不影响主流程。

## 9. F3：值呈现器注册表 + 二进制传输修复

**先修传输，再谈视图。** 现状 `safeCell()` 把 `Uint8Array` 转成 `<binary N bytes>` 字符串，导出走同一份 rows → **BLOB 列导出即数据丢失**。

### 9.1 信封

```js
// 之前：return `<binary ${v.length} bytes>`
// 之后：
{ __bin: { size: v.length, b64: base64OfPrefix, truncated: v.length > INLINE_LIMIT } }
// INLINE_LIMIT = 64KB；超限只带前 4KB 供预览
```

- `toCsv` 遇 `__bin`：`truncated` → 按导出选项 Base64 导出或提示"含二进制列，请用 SQL 模式导出"
- 大字段全量取回走独立 op `getCellBinary({table, pk, column})`，**不进 `getPageData`**（一页 400 行大字段会卡死渲染进程）

### 9.2 注册表

```js
// src/client/components/database/value-renderers/index.js
register({ key, label, readonly, maxBytes, detect(value, column), Component })
// 内置：raw / json / xml / python / url / hex / base64 / image / blob-info
```

- 重构 `db-value-pane.jsx`，复用 `db-value-format.js` 的 `detectFormats`/`formatValue`
- 判定顺序：`column.isBinary` → image/hex/base64；否则文本嗅探
- `readonly:true` 的渲染器**禁用保存按钮**（BLOB 写回会破坏数据）
- `maxBytes` 超限只给"前 N 字节 + 复制/另存"

**成本**：≈250 行（其中 60 行是修 bug）。  
**验收**：小/大/空二进制的信封单测；"BLOB 只读"断言；注册表选择逻辑测试。

## 10. C 批：流式导出 + CSV 导入

### 10.1 导出

```
startExport({database, schema?, table, format, columns?, targetPath, where?, whereParams?})
  → { exportId }        // 创建任务；LIMIT 分块循环（块 1000）；按块追加 createWriteStream
dbExportStatus(exportId) → { status, rowsWritten, bytes, filePath, error, etaMs }
cancelExport(exportId)   → 置取消位，块间检查，收尾关闭流
```

- 格式：`csv / tsv / json / jsonl / sql / markdown`；`sql` 带头尾（`SET FOREIGN_KEY_CHECKS=0` … 恢复）
- 分块复用 `getPageData` 同款参数化查询（**不拼接值**），`ORDER BY pk` 保稳定；无主键表退化为无序 + UI 提示
- 进度**轮询 `dbExportStatus`（500ms）**，不新增事件通道（保持 IPC 白名单最小化）；任务 Map 上限 4，完成后清理
- 导出 op **不设超时**（长任务），块间检查取消位；单块失败即整体失败并保留已写文件
- 路径由主进程 `dialog.showSaveDialog` 取得（渲染层不碰 fs）

### 10.2 导入

```
文件选择 → 主进程流式解析（4KB 块 + 引号状态机 + 进度 + 取消）
  → { columns, sampleRows(前50), totalRows? }
  → 前端列映射（文件列 → 表列/忽略/常量表达式）+ 类型预览
  → startImport({映射, 目标表, batchSize:500})
  → 分批 multi-row INSERT（参数化，每批一个事务）
  → dbImportStatus(importId) 轮询 { committedRows, failedBatches, errors[] }
```

- 解析器 `src/app/lib/db-importer.js`：零依赖，RFC4180 子集（引号、双引号转义、CRLF/LF），UTF-8 BOM，编码固定 UTF-8
- 写入：`insertRows` op 扩 multi-row VALUES（≤500 行/批，SQL 长度上限 1MB）；每批独立事务；失败批次记录行号与错误样本，**已提交批次保留**
- **取消 = 止步，非回滚**，UI 必须明示此语义
- 列映射不一致不阻塞（按映射写入，缺列走默认/NULL）；只读模式导入入口禁用 + 主进程 `checkWritable` 兜底

### 10.3 增量能力

| #    | 能力     | 说明                                                                     |
| ---- | ------ | ---------------------------------------------------------------------- |
| C-8  | 列转换器   | `constant`（固定值，走参数绑定）/ `expression`（SQL 片段，如 `NOW()`）/ `null`          |
| C-9  | 写入模式   | `append`（默认）/ `overwrite`（先清空）/ `upsert`（按主键）/ `rebuild`（重建表）；后三种需二次确认 |
| C-10 | 前/后置脚本 | 导出文件头尾可追加自定义语句（默认给 `SET FOREIGN_KEY_CHECKS=0`）                         |
| C-11 | 并行上限   | 多表导出并发 `min(4, 表数)`，默认 1（串行），`dbExportConcurrency`                     |
| C-12 | 所见即所导  | 导出接受 E2 的 `where/whereParams/orderBy`，导出的就是网格里看到的                      |

**约束**：

- `upsert` 仅当目标表**主键完整且映射覆盖全部主键列**时可用，否则选项禁用并给原因（避免"以为 upsert 其实是重复插入"）
- `overwrite/rebuild` 走 E1 同一套确认（production 需输库名）
- `expression` **不参与参数化**（是 SQL 片段），必须过 `assertSafeClause` 同款校验
- 并行只用于"多表"维度；单表内部仍串行分块（避免 ORDER BY 分页错位）
- 导出对话框步骤固定：`格式选择（=处理器）→ 参数配置 → 输出选项 → 执行`，可回退不丢参数

### 10.4 验收

1. 10 万行 × 10 列导出：渲染进程内存增量 ≤50MB，进度可见可取消（取消后文件完整到块边界）
2. `sql` 格式可直接 `source` 执行；`jsonl` 每行一个 JSON
3. 导入：带引号/逗号/换行/空值的 CSV 正确解析；映射忽略列生效；最后不足一批正确处理；中途取消报告已提交行数
4. `constant`/`null` 转换器值经绑定（含 `'` 不破 SQL）；`expression` 含 `;` 被拒绝
5. `overwrite` 在 production 连接上需输库名，取消则零写入
6. 网格设过滤后导出 → 导出语句与原查询 WHERE 一致（快照对比）
7. 二进制列按 Base64 导出，不再出现 `<binary N bytes>`
8. 只读模式导出可用、导入禁用；主进程拒绝伪造 `readOnly:false`
9. 单测：解析器 ≥20、SQL 头尾 ≥6、分批切分 ≥6、状态机 ≥8
10. 真库冒烟：mysql 1 万行导出 → 改 → 导入往返，行数一致

## 12. D 批：EXPLAIN 可视化 + Redis 类型化写

### 12.1 EXPLAIN

- 入口：结果区「解释」按钮（对最后执行的 SELECT）；编辑器选区右键「解释所选」
- `explainQuery({database, schema?, sql})`：mysql 走 `EXPLAIN FORMAT=JSON` 解析 `query_block` 嵌套树；pg 走 `EXPLAIN (FORMAT JSON)` 解析 `Plan` 递归树；redis 不注册

- **明确"拒绝 ANALYZE ⇒ 无实际行数据"**：`extractActualRows` 只在真正执行过的计划里取值，不把预估值当实际值
- 成本：mysql 解析 ≈120 + pg ≈80 + 渲染 ≈200


### 12.2 Redis 类型化写（T12）

- 范围严格按总览 §3.3 T12：hash `HSET/HDEL`、set `SADD/SREM`、zset `ZADD/ZREM`、list `LPUSH/RPUSH/LSET/LREM`、key `RENAMENX`（+ 既有 string/TTL/删除）

- **不做**：通用命令控制台、`FLUSHDB/FLUSHALL`、`KEYS` 全量、集群命令、二进制编辑

**验收**：mysql/pg 各一条真实查询出树；`ANALYZE` 被后端拒绝；树字段与原文一致（抽样 3 节点）；Redis 各类型读写冒烟；只读全拦截；`RENAMENX` 目标存在不覆盖；写失败刷新详情而非本地假状态。单测：EXPLAIN 解析 ≥15、redis 白名单与只读分支 ≥12。

## 13. F2：事务安全带（最后一批，风险最高）

**目标**：把"逐语句自动提交"变成可选事务，提交前给出变更清单。

### 13.1 连接钉住模型（核心难点）

```
inst.pinned = { client, since, statements: [] }        // 每 tab 至多一个
beginTransaction → 从 pool 取专用 client，autocommit=0，记 pinned
所有 op（executeSql/getPageData/updateCell/...）→ 若 pinned 则走 pinned.client
commit / rollback → 执行后 release，清 pinned
closeDbTab → 若 pinned 存在，先 rollback 再 release（禁止静默提交）
```

- **空闲超时**：pinned 超 10 分钟无操作 → 主动 rollback 并通知（避免占连接、阻塞其他 tab）
- **并行限制**：pinned 期间该 tab op 串行；**手动事务上限 2 个 tab**（pool 4 条连接），超出禁用开关并提示
- **只读切换**：`setDbReadOnly(true)` 时若有 pinned → 先 rollback 再切
- **变更清单**：`pinned.statements` 记 `{at, ms, sql, affectedRows}`，面板列 = 时间/时长/影响行数/语句
- **UI**：工具条「自动提交/手动」开关 + `N 条待提交` + 提交/回滚按钮；未提交时关 tab 必须弹确认

**明确不做**：SAVEPOINT、嵌套事务、跨 tab 共享事务、分布式事务。

**验收**：pinned 生命周期五条路径（begin→op→commit/rollback/close/timeout）用 mock client 测试；第 3 个 tab 开启手动事务被禁用；未提交关窗强制 rollback + 确认。

### 14.2 G1 广播输入 · P0（≈230 行）

```js
store.broadcast = { on:false, sourceTabId:null,
  targets:[{tabId, title, isProduction}], blocked:'password'|'confirm'|null }
```

扇出在唯一入口：

```js
sendToServer = (data) => {
  if (broadcast.on && broadcast.sourceTabId === this.tab.id &&
      !broadcast.blocked && !this._passwordPromptDetected && !isOscResponse(data)) {
    for (const id of broadcast.targets) {
      const t = getTab(id); if (!t?.session?.connected) continue
      t._broadcastDepth = (t._broadcastDepth || 0) + 1        // 防环
      try { t.sendToServer(data) } finally { t._broadcastDepth-- }
    }
  }
  if (this._broadcastDepth > 0) return
  ...原有逻辑
}
```

**三道闸**：① **密码期不镜像**（复用 `_passwordPromptDetected`，否则 sudo 密码会打到所有机器）② **OSC 应答不镜像**（`\x1b]` 开头的应答只对本地有意义）③ **生产机确认**（任一 target `production` → 开启时弹确认并列出主机名，红条常驻）。

**交互**：会话右键 + 状态栏按钮 + `Ctrl/Cmd+Shift+B`；目标弹层多选（默认全选非生产）；顶部 28px 红条「广播中 · N 台 · 点击退出」，**点任意处或 Esc 退出**（照 Tabby）；目标断连自动移出 + toast。

**不做**：命令结果聚合表、执行顺序编排、按角色分批（`batch-op` 的领域）。

**验收**：3 台（含 1 台 production）输入 `ls` 三台同时执行且 production 先确认；广播态触发 sudo 密码提示 → **targets 收不到**（断言 `sendToServer` 调用 0 次）；target 断连自动移出；退出后再输入只有主控收到。

### 14.3 G2 录制回放 · P0（≈380 行）

格式沿用 asciinema v2（首行 header `{version:2,width,height,timestamp}`，其后 `[相对秒, "o"|"i", "数据"]`），**不改录制端**。

```
cast-parser.js     // 流式按行解析 → {header, events}；坏行跳过并计数
cast-player.jsx    // 只读 xterm + 虚拟时钟
recording-list.jsx // 扫目录 + 列表 + 打开/删除/定位
```

- 虚拟时钟 `requestAnimationFrame` 累积 `dt*speed`，按事件 `t` 顺序 `term.write`；`i` 事件**不写终端**，改底部输入徽标（`⌨ abc⏎`）
- 控制条：播放/暂停、`0.5/1/2/4x`、可拖进度、时间、复制命令
- 尺寸按 header 的 `width/height` 定初始 `cols/rows`，窗口变化**不重排**（保持录制原貌，避免行错位）
- 列表扫 `settings.sessionLogPath`，列 = 文件名/大小/时长/首条命令/修改时间

**不做**：云分享链接（需服务端）、GIF 导出（需 ffmpeg）、编辑裁剪。

**验收**：60s 录制 1x 回放误差 <1s；4x 不丢事件（计数一致）；header 损坏给"不是有效 asciinema 录制"而非白屏；空录制可打开。

### 14.4 G3 SFTP 预览 · P0（≈300 行）

**第一步修读文件能力**（`server/sftp-file.js`）：

```js
readRemoteFileChunk({ sftp, path, maxBytes = 2*1024*1024 })
  → { b64, size, truncated, headText }   // headText = 前 512B 尽力 utf8 解码，供嗅探
// 实现：sftp.createReadStream(path, {start:0, end:maxBytes-1})；size 先由 stat() 取
```

**第二步分派**（`sftp/file-preview.jsx`）：

| 类型                          | 判定              | 渲染                                              |
| --------------------------- | --------------- | ----------------------------------------------- |
| 图片 png/jpg/gif/webp/bmp/svg | 扩展名 + 魔数        | `data:` base64；>2MB 提示"仅预览前 2MB"（svg 走文本）       |
| Markdown                    | `.md/.markdown` | 只读文本（有现成渲染器才复用，无则不引依赖）                          |
| CSV/TSV                     | 扩展名 + 首行分隔符计数   | 表格前 200 行 × 20 列                                |
| 文本/代码                       | 无 NUL 字节        | 复用 `text-editor` 只读模式                           |
| 其它二进制                       | 有 NUL           | HEX 前 4KB（16 字节/行 + 偏移 + ASCII 列）               |
| PDF                         | `.pdf`          | **不内嵌**（Electron 内置 viewer 引入安全面与体积）→ 只给"下载后打开" |

**交互**：单击 → 右侧抽屉（复用 `side-panel-r`）；`空格` 快速预览；`Esc` 关闭；顶部「下载/用文本编辑器打开/复制路径」。

**验收**：10MB 图片内存增量 <100MB（只读 2MB）；1GB 日志秒开；二进制不出现乱码刷屏；无 NUL 的 UTF-8 判为文本。

### 14.5 G4 远程归档 · P1（≈250 行）

```js
archiveCreate({sessionId, kind:'tar.gz'|'zip', sources:[path], dest})
archiveExtract({sessionId, archivePath, destDir}) → { ok, stderrTail, producedPath }
```

- `tar.gz`：`tar -czf <dest> -C <dir> -- <names…>`；`zip` 优先 `zip -r`，失败回退 tar.gz 并**明示**"远端无 zip，已用 tar.gz"
- 解压按扩展名分流，**先列目录**（`tar -tzf` / `unzip -l`）让用户确认再解
- **注入防护**：所有路径过 `shellQuote()`，拒绝含 `\n`/`\r`，`--` 终止选项解析
- 进度：解析 stderr 不可靠 → 两段式（`du -sb` 估算总量 → 轮询 `du -sb dest` 报百分比，仅大目录）

**验收**：含空格/中文/`-` 开头文件名的目录正确打包；无 zip 时降级提示准确；解压前可见清单。

### 14.6 G5 目录镜像 · P1（≈350 行）

**单向、手动，不做常驻监视**（WinSCP 的 keep-up-to-date 事故率高且需 watcher）。流程：选目录 → **差异预演** → 确认 → 执行。

```js
diffTrees(local, remote, {mode:'size-mtime'|'size-only', deleteExtra:false})
  → { create, overwrite, skip, deleteCandidates }
```

- 默认 `size-mtime`：大小不同 → 覆盖；大小同且 mtime 差 <2s → 跳过（FAT/SFTP 时间精度差异）
- `deleteExtra` 默认 **false**；勾选后才列删除项且默认不勾
- 预演面板：四组计数 + 明细 + 预估字节；执行走现有传输队列（复用冲突处理与并发）

**验收**：1000 文件预演 <300ms；跳过判定的假阴性可接受（UI 说明"按元信息快速判定，需严格校验请勾逐字节"）；中断后已传文件不回滚（明示）。

### 14.7 G6 主密码 Vault · P1（≈600 行，风险最高）

**密钥层次**（保留 GCM，不降级 CBC）：

```
主密码 --scrypt(N=2^15,r=8,p=1,salt)--> KEK(32B)
随机 DEK(32B) --AES-256-GCM(KEK)--> wrappedDEK   // 存 config
每条凭据 --AES-256-GCM(DEK, per-record iv)--> ciphertext
```

- `config.vault = { v:1, salt, wrappedDek, verifier, autoLockMin }`
- **主密码永不落盘**，KEK/DEK 只在**主进程内存**；渲染进程只调 `vault.encrypt/decrypt`
- 解锁：启动时若 `vault.enabled` 且存在加密凭据 → 弹解锁；`verifier` 用于错误口令快速判定
- 自动锁定：闲置 15 分钟 / 退出。锁定后**已打开会话不受影响**（内存中已解密），新建连接需重新解锁
- **迁移**：`vault.enable(masterPass)` → 遍历书签敏感字段逐条重加密（进度条 + 可中断；中断则回滚旧格式，用 `vault.migrating` 标记）
- **恢复码**：启用时生成 32 字节恢复码（Base32，仅显示一次），用于忘记主密码时解 wrappedDEK；未保存则明确警告

**分两阶段**：① **只读解锁**（能解锁/校验/自动锁，凭据仍走旧路径）→ 可独立验证不破坏现有用户；② **切换写入**（新凭据写 vault + 旧凭据批量迁移）+ 回滚开关 `vault.legacyWrite`。

**验收**：错误主密码不产生解密泄漏；迁移中断后重启仍是旧格式且能连接；恢复码可解出 DEK；锁定后新连接提示解锁而非报错。

### 14.8 G7 密钥生成 + known_hosts 面板 · P1（≈320 行）

**A. 生成向导**：ed25519（默认）/ rsa-4096 / ecdsa-384；passphrase 可选；落盘 `~/.ssh/electerm_<type>_<yyyymmdd>`，私钥 `600` 公钥 `644`，**已存在则拒绝覆盖**；生成后三步引导（复制公钥 → 安装到服务器 `mkdir -p ~/.ssh && cat >> authorized_keys` 带确认 → 写回书签）。用 `crypto.generateKeyPairSync`，OpenSSH 公钥格式自拼，无需 `ssh-keygen` 依赖。

**B. known_hosts 面板**：解析 `~/.ssh/known_hosts`，hashed 主机名显示 `|1|hash` 前缀并标注"哈希条目，仅可按指纹删除"；列 = 主机/端口/算法/指纹/首次记录；操作 = 删除单条（二次确认）+ 复制指纹；**不提供"全部清空"**。

**验收**：生成的 ed25519 能被 `ssh -i` 直接使用（用测试容器验证）；已有文件不覆盖；删除条目后下次连接重新提示信任。

### 14.9 G8 审计中心 · P2（≈300 行，依赖 G2）

数据源 = `sessionLogPath` 下 `*.log` + `*.cast` + 连接/传输历史。三栏（时间线/主机/类型过滤），每行 = `时间 · 主机 · 用户 · 时长 · 类型 · 产物`；点开 → 回放或日志尾部 500 行；导出 Markdown/CSV 用于交接与合规留档。

**边界**：**纯本机**，不做服务端集中采集；**不做命令级解析**（日志是原始字节流，逐条解析不可靠）。

## 15. 贯穿性约束

1. **不引入重依赖**：补全/导入解析/导出生成/结构对比均零依赖自写（对齐 `db-sql-format.js`/`db-csv.js` 先例）；唯一新依赖是 CodeMirror 6（ESM，手动 chunk，dist 增量 ≤150KB）
2. **IPC 纪律**：新增通道仅 `dbSqlFavoriteOp`、`dbGridViewOp`；其余扩既有 `dbClientOp` 的 `OP_MAP`；入参一律 `clone`；长任务用轮询状态而非事件通道
3. **只读权威在主进程**：`checkWritable` 前置；渲染层传 `readOnly:false` 无效
4. **写操作两道闸**：前端分级（E1）→ 主进程 `assertSafeClause` 二次校验（手写 WHERE / 转换器表达式均过）
5. **F0 向后兼容**：`describeTable` 只增字段不改语义；视图 `type:'view'` 在主进程与渲染层**双重禁写**
6. **二进制**：`safeCell` 输出 `{__bin:{size,b64,truncated}}` 信封，**禁止**再转 `<binary N bytes>` 字符串；全量取走 `getCellBinary`
7. **F2 连接纪律**：手动事务上限 2 tab、空闲 10 分钟自动回滚、关 tab/关窗强制回滚、pinned 期间 op 串行
8. **G1 三闸**：密码期不镜像、OSC 不镜像、生产机手输主机名确认、`_broadcastDepth` 防环
9. **G3 读上限**：预览必须用 `readRemoteFileChunk`（默认 2MB），**禁止**用 `readRemoteFile` 全量读
10. **G4/G5 路径安全**：`shellQuote` + 拒绝换行 + `--` 终止；镜像"删除多余"默认不勾
11. **G6 密钥层次**：保留 AES-256-GCM，主密码 → KEK → 包裹随机 DEK，密钥只在主进程内存
12. **CSS 契约**：新控件圆角用 `var(--radius-xs)`，行高/工具条高度沿用现有 token（先例 6f4b12ec、98c87d92）
13. **验证门槛**：每批 `npm run test-unit-ci`（当前基线 1484 个）只增不减；`npm run compile` 通过
14. **提交粒度**：`feat(db): xxx (阶段4-X)` / `feat(core): xxx (阶段4-GX)`，附单测数量，不混批

## 18. 不做清单

**数据库侧**：数据同步（行级差异）、结构同步套件（双向脚本/依赖图/回滚对比）、跨库传输、备份还原、自动运行/计划任务、BI 仪表板、数据生成/脱敏、模型套件、重构与用法追踪、ERD 正向工程、条件格式/色阶、事务保存点/嵌套/跨 tab、谓词下推的智能 JOIN 过滤、通用 Redis 命令控制台、`FLUSH*`、`KEYS` 全量、表设计器（P2）、可编程对象浏览（P2）、服务器概览（P2）、SSH 连接的 SSL/TLS（P2）

**非数据库侧**：断线续跑（需目标机 helper）、会话共享协作（需服务端）、插件市场（无分发/沙箱，以 widget 模板库替代）、Web 自托管（等于另做产品）、容器/PaaS 面板、命令结果聚合视图（与 `batch-op` 冲突且易误判）、块式工作区（Wave block 是重写级架构）

**统一判定口径**：需要常驻调度器、独立解析器或独立产品面的功能，与"SSH 客户端 + 轻量数据库面板"的定位不匹配；P2 中已保留其中收益最高、边界最窄的切片。
