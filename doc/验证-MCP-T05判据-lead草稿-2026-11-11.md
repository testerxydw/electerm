## 一、配置 UI（M1）

### T05-01（M1 UI 面）增删改 8 server + 非法字段就地报错
**通过标准**：`mcp-server-config.jsx`（T05 新建）提供 server 列表的**增 / 删 / 改**，至少支持 8 个 server 实例；
每个 server 的字段（`name`/`transport`/`command`/`args`/`url`/`trust`/`timeoutMs`/`enabled`）违反 `config-validate.js`
规则时，在表单**就地报错**（不依赖提交后才弹错），报错文案与 `config-validate.js` 的 `errorOf` 文案一致。
组件级 spec 构造非法输入（如空 name、`transport` 非枚举、`trust` 非三态、超时越界）断言对应 `Form.Item` 显示错误态。
**变异**：把「就地校验」改成「提交后才校验」→ 就地报错断言红。把非法 `transport` 放行 → 校验断言红。

### T05-02（M1 / Refresh）Refresh tools 集成
**通过标准**：UI 提供「Refresh tools」按钮，点击调 `mcpClientRefreshTools({ force: true })`（F3 后端已透传 force）；
刷新后状态徽章与工具计数正确反映当前 server 工具集（与 `mcpClientGetState` 的 `toolCount` 一致）。
契约 spec：注入假 client → 点击 Refresh → 断言后端 `refreshTools()` 被调用且状态徽章更新。
**变异**：把按钮调用改成 `refreshTools()` 不带 force（即 `opts.force` 缺失）→ 后端「恰好重拉」断言红（复用 T03 M26 的 force 透传判据）。把徽章绑定到错误字段 → 计数一致性断言红。

### T05-04（M12 实机）实机步骤写回 + 放行门对齐
**通过标准**：把设计 §7.3 的 7 步（或复核后对齐的放行条数）**写实进验证文档 §4.3 表格**，并逐条人工核验：
1. 产物同步：`npm run compile && node src/build/bin/prepare`；
2. 新增 stdio server（filesystem）→ 状态徽章「已就绪（N 个工具）」且 N ≥ 1；
3. 提问触发 → 工具卡片名 `mcp__<id>__list_directory` + 弹审批（trust=ask）+ 确认后结果以 `<untrusted-tool-result …>` 包裹 + 未确认收到 `cancelled`；
4. 失败隔离：command 改 `sleep 999` → ≤ timeoutMs+5s 返回 `mcp_timeout`，面板可用、循环不卡死；
5. 资源：禁用 server → `ps aux | grep -c "server-filesystem"` 归零；
6. HTTP：错误 token → 401「鉴权失败」、不重试刷屏、状态徽章「失败」+ 重试按钮可用；
7. 回归：清空列表 → 重跑 #3 原问题（走内置工具）行为与上线前一致。
**放行门（F5 已拍板 A）**：§4.3 保留「6 条全过」，并注明「步骤 1 为环境前置、不计入放行」；#2–#7 恰好 6 条，与 §7.3 完整 7 步描述（含 #1/#7）共存，不删步骤。
**变异**：本条为人工步骤，无自动变异；若实现让 #4 卡死或 #6 刷屏重试 → 实机判 FAIL，记入 §七。
