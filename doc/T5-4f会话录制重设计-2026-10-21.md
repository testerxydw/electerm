# T5-4f 会话录制重设计（2026-10-21）

状态：**待拍板**。草图：`doc/草图-会话录制重设计-2026-10-21.html`

## 0. 背景

T5-4e 跳转已验证通过。用户反馈：cast 文件满屏转义符，且希望输入也录制、内容可配置。按同类软件重新设计。

## 1. 根因：为什么 cast 里全是转义符（固有形态，非 bug）

cast 是 asciinema v2 格式 = **终端字节流的时间戳重放**，里面记录的就是终端协议本身：

| 内容 | 例子 | 来源 |
|---|---|---|
| 颜色/光标序列 | `\u001b[32m` `\u001b[2J` | 终端输出固有 |
| shell integration | `\u001b]633;E;...\u0007` | electerm 注入的 OSC 633（每条命令都会出现，噪声最大头） |
| 逐 chunk 碎片 | `[2.294,"o","h"]` | 输出按到达分片，一行被拆多条 |

asciinema 本身录出来同样如此——**设计上它不是"给人直接读的"，是给播放器渲染的**（`asciinema play xxx.cast` / 上传 asciinema.org 在线回放，看到的是还原后的终端画面）。真正让观感恶化的是 OSC 633 注入序列。

## 2. 同类软件参照

| 软件 | 产物 | 输入录制 | 可读性 |
|---|---|---|---|
| asciinema | .cast 重放 | `--stdin` 可选（i 事件） | 播放器渲染，源文件含转义 |
| script (util-linux) | typescript 纯文本 | 默认录输入+输出 | 含转义，`col -bp` 清理后可读 |
| TermRecord | 自包含 HTML | 否 | 渲染后 HTML，无可读源文件 |

结论：**"回放格式（cast）"与"可读格式（log）"是两个需求**，同类软件都是分开的，本设计对齐这一点。

## 2.5 与既有终端日志的重叠（2026-10-21 补充结论）

**是的，重复了，而且是"同名两套"更糟的形态。**

上游早已有"录制"功能（`term-log.jsx` + `session-base.js` 的 SessionLog）：

| 维度 | 既有 term-log（上游） | T5-4 cast 录制（本次新增） |
|---|---|---|
| 入口 | 右键菜单 `onRecord`/`onStopRecord` | 终端顶栏按钮 |
| 菜单/按钮文案 | `e('record')` / `e('stopRecord')` | **同一组 key** |
| 产物 | `.log` 纯文本（headless xterm 逐行渲染） | `.cast` asciinema v2 字节流 |
| 落盘 | 用户 saveDialog 选路径 | 自动 `~/Downloads/electerm-rec-*.cast` |
| 时间戳 | 可选行首 `[HH:MM:SS]` | 每事件相对秒 |
| 剥离转义 | **天然无转义**（VT 渲染后取文本行） | 原样字节流（含 ANSI/OSC 633） |
| 可回放 | 否（丢颜色/光标） | 是 |
| 实现层 | 主进程 SessionLog（`session-base.js:119`） | 渲染层 SessionRecorder |

关键事实：
- 两者在 UI 上**同名**，用户右键看到"录制"、顶栏也看到"录制"，行为却完全不同 → 真实可用性问题。
- 本设计原 3.2 第 2 条"纯文本 log 格式 + ansi-filter 纯函数"**就是 term-log 的完整重造**，属于平行实现，必须砍掉。
- 反过来，可读归档需求**已被 term-log 满足**（VT 渲染天然无转义，还带时间戳选项），零新代码即可复用。

### 去重方案（三选一，待拍板）

**方案 A（推荐）：一个入口 + 两种产物，文本产物复用既有通道**
- 顶栏按钮与右键菜单项统一调 `store.toggleSessionRecord`，右键菜单旧的 `onRecord` 直连改为同一开关（同一状态源 `store.recState`）。
- 设置 `recordFormat`：
  - `cast`（默认）：自动落 `~/Downloads/electerm-rec-*.cast`，零弹窗
  - `log`：弹 saveDialog，走既有 `startTerminalLogFile`（主进程 SessionLog），不新增落盘实现
  - `both`：两条线同时开/停
- 不新增 ansi-filter、不新增 `.log` 写入器。
- 风险：`both` 需要在 `toggleSessionRecord` 里编排两条线（cast 按 tabId、log 按 pid），停录通知需去重成一条。

**方案 B：保留两套，只改文案区分（风险最低）**
- 右键菜单项改文案为"保存终端日志/停止日志"（不再叫"录制"），顶栏专注"录制回放"。
- 同样砍掉新 log 格式与 ansi-filter，设置项只留 cast 相关的三项。
- 缺点：功能层面仍有两条并行链路，只是不再同名。

**方案 C：cast 吸收 term-log（删旧功能）**
- 不建议：删上游能力，文本可读性反而要靠播放器/导出补，破坏面大。

## 3. 设计方案（按方案 A 展开；选 B 则删掉 3.2 的 log 分支）

### 3.1 设置区块（设置页 → 终端，新增"会话录制"组）

```
录制格式      [ ● cast 回放文件   ○ 终端文本日志   ○ 两者都生成 ]   (radio)
录制内容      [ ■ 仅输出(默认)   □ 输出+键盘输入 ]                   (checkbox, 含警告)
剥离 shell 集成序列 [ 开 ]   (仅 cast 格式生效, 默认开)
密码提示自动避录    [ 开 ]   (检测到 password 提示即暂停捕获, 默认开)
```

- `recordFormat`: `cast`(默认) / `log` / `both` —— **`log` 分支直接复用 term-log，不新增实现**
- `recordInput`: `false`(默认)
- `recordStripOsc`: `true`(默认)
- `recordAvoidPassword`: `true`(默认)
- 均走 config 持久化（default-setting.js + 渲染层同步定义——恢复会话同款双处定义教训）

### 3.2 两种格式

1. **cast 回放**（本次唯一需要写代码的格式）：
   - 剥离 OSC 633;A/C/D/E/P 与 OSC 0/2 标题序列（recordStripOsc）
   - 保留 SGR 颜色——回放需要
   - 事件聚合：~80ms 微批合并 chunk，行数降一个量级（P1）
2. **终端文本日志**（**复用既有，零新实现**）：
   - 走 `startTerminalLogFile(pid, filePath, addTimeStampToTermLog)`，产物天然无转义
   - 保存路径沿用既有 saveDialog（`openLogSaveDialog`），默认名沿用 `logName + '.log'`
   - 不新增 ansi-filter 纯函数、不新增 `.log` 写入器、不新增 `electerm-rec-*.log` 命名

### 3.3 输入录制（recordInput）

- cast：`[t,"i","keys"]` 事件（asciinema --stdin 同款）
- log（既有 term-log）：不录输入——主进程 SessionLog 只取渲染后的输出行，保持既有行为
- **隐私边界**：开启时首次 toast 警告"键盘输入将被记录"；密码避录（3.4）默认兜底

### 3.4 密码自动避录（recordAvoidPassword）

- 复用 attach-addon-custom 已有 `_passwordPromptDetected` / `_onEchoCheckTimeout` 钩子：
  检测到密码提示 → recorder.pause()；回车/Ctrl+C 或 200ms 无回显确认 → resume()
- 纯输出模式下也生效（sudo 提示期间输出不录）

### 3.5 终端顶栏录制按钮增强

顶栏已有录制开关（T5-4d，`renderRecordIcon`：PlayCircleFilled/StopOutlined）。本次在**同一位置**扩展：

- 录制中：开关旁新增**暂停/继续按钮**（PauseCircleFilled ⇄ PlayCircleFilled，同 `sess-icon` 形态，仅录制中渲染）
- 暂停态：录制开关图标保持 StopOutlined（仍在录），暂停按钮变 PlayCircleFilled；REC 状态浮层文案切"已暂停 MM:SS"（浮层保持纯状态指示，不加按钮）
- 右键菜单同步加"暂停/继续录制"
- 暂停期间输入输出均不入文件

## 4. 边界与风险

- recordInput 开启后，`↑` 历史导航、Ctrl+R 搜索按键也会录进 i 事件（与 asciinema 行为一致），文档注明
- log 过滤器对 TUI 应用（vim/htop）输出会得到乱序纯文本——文档注明 log 适合命令行会话归档，不适合 TUI
- 密码避录依赖既有探测（新增 prompts 覆盖有限），警告文案不承诺 100%
- 兼容：旧 cast 行为不变（recordFormat 默认 cast）
