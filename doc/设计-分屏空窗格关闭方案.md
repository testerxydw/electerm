# 设计方案：分屏空窗格关闭能力（仅设计，暂不实施）

> 状态：**待用户确认** · 日期：2026-10-14 · 分支：master
> 需求原文：「关于拆分布局，如果一个布局的所有 tab 都被关闭或一个布局无 tab 时，提供关闭按钮关闭该布局？」
> 前置调研：已完成全链路只读调研（数据结构 / 状态流转 / 渲染入口），结论见 §二
> 关联：本方案**不改动**任何代码，仅输出设计供评审

---

## 一、需求澄清

需求包含**两种情形**，但本质相同（都是"某个窗格没有 tab"）：

| 情形 | 描述 | 示例 |
| --- | --- | --- |
| **A. 关空了** | 某窗格内所有 tab 被逐个关闭 → 该窗格变空 | 分屏 c2，右格关掉最后一个 tab |
| **B. 本就没有** | 切换到多窗格布局后，某些窗格从未分配过 tab | 直接切到 c2x2，只有左上格有 tab |

**诉求**：为空窗格提供按钮，点击后**关闭该窗格**（让其余窗格重新占据空间）。

## 二、现状调研（证据均来自当前代码）

### 2.1 数据结构：布局是「固定枚举」，不是任意窗格树

| 概念 | 实现 | 位置 |
| --- | --- | --- |
| 布局标识 | `store.layout`（字符串 key） | `src/client/store/init-state.js:51,129` |
| 合法布局与窗格数 | `splitConfig = { c1:{children:1}, c2:{children:2}, c3, r2, r3, c2x2:{children:4}, c1r2, r1c2 }` | `src/client/common/constants.js:417-450` |
| **窗格归属** | `tab.batch`（0 基序号）—— `store.tabs` 是**扁平数组**，靠 `batch` 归入窗格 | `src/client/components/layout/layout.jsx:129-176` |
| 每窗格活动 tab | `store.activeTabId0/1/2` | `src/client/store/init-state.js:133-135` |
| 焦点窗格 | `store.currentLayoutBatch` | 同上 `:132` |
| 新 tab 目标窗格 | **瞬时全局** `window.openTabBatch`（消费后删除） | `src/client/store/tab.js:431` |

> ⚠️ 易混淆点：`tab.pane`（`paneMap`: ssh/sftp/terminal/fileManager）是**窗格内部的视图切换**，与分屏无关（`constants.js:118-123`）。分屏只看 `tab.batch`。

### 2.2 状态流转

```
setLayout(key)            ← 唯一切换入口（tab.js:621-669）
  ├─ 持久化 ls.setItem('layout', key)
  ├─ 若新布局窗格更少 → 把越界 tab.batch 收拢到最后一格（tab.js:641-657）
  └─ 若 1格→多格 且 autoDistributeTabsWhenLayoutChange → distributeTabs()

splitTab(direction)       ← 原地拆分（tab.js:550-571，经 splitLayoutMap 找目标布局）
cloneToNextLayout()       ← 克隆到下一布局（tab.js:518-546）
moveTabToPane(tabId, b)   ← 跨窗格搬运（tab.js:574-586）

delTab(id) → removeTabs() → fixCurrentTabIds()   ← 关 tab
  └─ fixCurrentTabIds **只修 activeTabId，从不动 layout / 窗格数**（tab.js:318-363）
```

**关键结论**：关掉某窗格全部 tab 后，`store.layout` 不变、窗格数量不变。

### 2.3 渲染入口与空窗格现状

```
Layout (layout.jsx)
 └─ Layouts (layouts.jsx:16-60)
      └─ new Array(splitConfig[layout].children).map(i => LayoutItem(.layout-item v{i+1}))   ← 无条件渲染每一格
           └─ TabsWrap (tabs/index.jsx:573-586)
                └─ tabs 为空 → renderTabs() + renderNoSession() → NoSession (no-session.jsx:11-61)
```

- 空窗格**不会**残留纯空白，而是显示 `NoSession` 占位块（`.no-sessions`，含新建/书签/AI/QuickConnect/历史）；
- `SessionsWrap`（`session/sessions.jsx:104-120`）只在 **`store.tabs` 整体为空**时返回 `null`，与"某格为空"无关；
- 分隔手柄 `.layout-handle` 的 `handleMousedown` 是**空函数**（`layout.jsx:30-32`），且**全仓库无 `.layout-handle` 样式** → 目前分隔线既不可拖拽也无视觉。

### 2.4 现有能力盘点

| 能力 | 是否存在 |
| --- | --- |
| 关闭单个 tab / 其他 / 右侧 | ✅（`delTab` / `closeOtherTabs` / `closeTabsRight`） |
| 切换布局（含合并到更少窗格） | ✅ 但只能**整体降级**（`setLayout` 把越界 batch 收拢到最后一格） |
| **关闭某一个空窗格** | ❌ **不存在**（全仓库搜 `closeLayout`/`closePane`/`removePane`/`closeSplit` 零命中） |
| 拖拽分隔条<br>调整窗格比例 | ❌ 未实现（手柄为空函数、无样式） |

## 三、核心难点：固定布局枚举 vs "任意格关闭"

因为布局是**8 种固定形态**（`splitConfig`），"关掉某一格"后剩余窗格常常**无法映射到既有形态**：

| 原布局 | 关掉 | 剩余 | 有无直接对应布局 | 处理方式 |
| --- | --- | --- | --- | --- |
| `c2`（左右） | 任一格 | 1 | ✅ `c1` | 直接降级 |
| `c3`（三列） | 中间格 | 2 | ⚠️ 无"缺中间的 2 列" | **重排为 `c2`**（两侧格合并占满） |
| `c2x2`（2×2） | 任一格 | 3 | ❌ **无 L 形布局** | 重排为 `c3` 或 `r3`（线性化） |
| `c2x2` | 两格 | 2 | ✅ `c2` / `r2` | 降级 |
| `r2`（上下） | 任一格 | 1 | ✅ `c1` | 直接降级 |
| `c1r2` / `r1c2`（一大多小） | 小格 | 2/1 | ⚠️ 形态损失 | 降级为 `c2`/`r2`/`c1` |

**因此必须回答一个产品问题**：关闭空格后，剩余窗格是
- **(甲) 线性化重排**（简单、不新增布局：K=3 一律 `c3`/`r3`）—— 但 `c2x2` 关一格会看到 2×2 变三列，**视觉跳变大**；
- **(乙) 保持形状**（需新增"缺角"布局，如 `c2x2` 缺一格 → 新布局 `c2x2m1`，需写 `layout-alg`/`session-size-alg` 配置）—— 视觉平滑但工作量与回归面大。

> 建议：**MVP 走（甲）**，并在按钮上做**二次确认 + 提示目标布局**（如"关闭后变为三列布局"），把跳变变成"用户预期内的动作"。L 形布局列为后续可选（§六）。

## 四、方案设计

### 4.1 功能定义

1. 当**窗格为空**（该 `batch` 在 `store.tabs` 中无 tab）且**当前布局窗格数 > 1** 时，该窗格的 `NoSession` 占位块上显示「**关闭此窗格**」按钮；
2. 点击 → 关闭该窗格：剩余窗格按序紧凑重排，并降级到与之匹配的布局；
3. **不做自动关闭**（避免"关一个 tab 导致分屏结构变化"的意外感）；是否提供自动模式见 §4.6 配置开关。

### 4.2 布局降级映射规则

设：`K` = 剩余（有 tab 的）窗格数；`原布局` 的方向倾向 = 以 `r` 开头 → 行优先，否则列优先。

| K | 原布局含 `r`？ | 目标布局 |
| --- | --- | --- |
| 0 | — | `c1`（全空：退化为单窗格） |
| 1 | — | `c1` |
| 2 | 否 | `c2` |
| 2 | 是 | `r2` |
| 3 | 否 | `c3` |
| 3 | 是 | `r3` |
| 4 | — | `c2x2` |

**窗格紧凑重排**：把"仍有 tab 的窗格"按原 `batch` 升序收集为 `keep[]`，再把每个 `keep[j]` 上的 tab 依次改写到 `batch = j`（`j = 0..K-1`），**保持相对顺序**。

### 4.3 交互设计

| 项 | 设计 |
| --- | --- |
| 按钮位置 | 空窗格的 `NoSession` 占位块（`.no-sessions`）内，与"新建"按钮同组，视觉为 **text 按钮**（次要操作，不用 primary） |
| 文案 | 「关闭此窗格」（i18n：语言包为外部依赖，按 R2 已建立的 `db-i18n.js` 本地词条回落机制处理） |
| 图标 | `CloseOutlined` |
| 二次确认 | 用 `Popconfirm`：`关闭后剩余窗格将重排为「三列布局」，是否继续？` —— 明确告知目标布局，消除"跳变"惊吓 |
| 显示条件 | `store.layout !== 'c1'`（单窗格时无意义，不显示） |
| 键盘可达 | antd `Button`/`Popconfirm` 天然支持 Tab/Enter；符合全局 `:focus-visible` 描边环规范 |

### 4.4 实现落点（需新增，无现成钩子）

| # | 改动 | 文件 | 说明 |
| --- | --- | --- | --- |
| 1 | 新增 store 方法 `closePane(batchIndex)` | `src/client/store/tab.js` | 核心算法，见下方伪代码 |
| 2 | 传递「是否空窗格」与回调 | `src/client/components/layout/layout.jsx:129-176`（`renderSessions` 里已有 `tabsBatch[i]`，可判定空） → `tabs/index.jsx:573-586` → `no-session.jsx` | 只透传 prop，不改布局算法 |
| 3 | 按钮 + Popconfirm | `src/client/components/tabs/no-session.jsx` | 纯 UI |
| 4 | 文案词条 | `src/client/components/bookmark-form/common/db-i18n.js` 同款机制（或新建通用 `local-i18n.js`） | 语言包是外部依赖，无法就新增 key |

**`closePane(batchIndex)` 伪代码**：

```js
Store.prototype.closePane = function (batchIndex) {
  const { store } = window
  const { tabs, layout } = store
  const total = splitConfig[layout].children
  if (total <= 1) return                       // c1：无可关闭
  const has = tabs.some(t => Number(t.batch) === batchIndex)
  if (has) return                              // 防御：只允许关闭空窗格

  // 1) 收集仍有 tab 的窗格（按序）并紧凑重排
  const keep = []
  for (let b = 0; b < total; b++) {
    if (b === batchIndex) continue
    if (tabs.some(t => Number(t.batch) === b)) keep.push(b)
  }
  const K = keep.length
  keep.forEach((oldBatch, j) => {
    tabs.forEach(t => { if (Number(t.batch) === oldBatch) t.batch = j })
  })

  // 2) 选目标布局（§4.2 表格）
  const target = pickLayoutFor(K, layout)

  // 3) 重置每窗格 activeTabId（旧的高位索引要清空）
  for (let i = 0; i < 3; i++) store[`activeTabId${i}`] = ''
  tabs.forEach(t => {
    const b = Number(t.batch)
    if (!store[`activeTabId${b}`]) store[`activeTabId${b}`] = t.id
  })
  store.currentLayoutBatch = Math.min(store.currentLayoutBatch, Math.max(0, K - 1))

  // 4) 应用目标布局（redistribute=false：batch 已自行重排，禁止再自动分配）
  store.setLayout(target, false)
}
```

> **必须在 `setLayout` 之前完成 batch 重写**：因为 `setLayout` 内部对"窗格变少"会把**越界 batch 收拢到最后一格**（`tab.js:641-657`），若先调用会破坏我们的有序重排。重排后所有 `batch < K ≤ 目标 children`，该收拢逻辑自然不触发。

### 4.5 边界与异常

| 情形 | 处理 |
| --- | --- |
| 当前是 `c1` | 不显示按钮 |
| 被点击的窗格其实有 tab（状态竞态） | `closePane` 内 `has` 防御直接 return |
| 关到只剩 1 格 | 目标 `c1`；`activeTabId1/2` 清空；`currentLayoutBatch = 0` |
| 关到 0 格（全部空） | 目标 `c1`，等价于"回到单窗格"；此时 `store.tabs` 可能为空 → 走既有 `NoSession` 全屏占位 |
| `c2x2` 关一格 | K=3 → 重排为 `c3`/`r3`（**视觉跳变**，已由 Popconfirm 预告） |
| 与 `window.openTabBatch` 交互 | 无冲突（该变量仅影响新建 tab 落点） |
| 持久化 | `setLayout` 已负责 `ls.setItem('layout', key)`，无需额外处理 |
| 工作区（workspace） | 若工作区保存了布局，需确认是否也要同步（见 §七 D3） |

### 4.6 配置开关（可选）

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `enableCloseEmptyPane` | `true` | 是否显示「关闭此窗格」按钮 |
| `autoCloseEmptyPaneWhenLastTabClosed`<br>（**默认关**，建议不作为 MVP） | `false` | 关掉某窗格最后一个 tab 时自动关闭该窗格 |

> 自动模式的风险：用户"只想关 tab"，结果分屏结构被改变 → 建议**默认不启用**，或仅在"该窗格从未有过 tab"（情形 B）时自动收起。

| 方案 | 内容 | 优点 | 缺点 | 建议 |

## 六、后续可选增强（本次不做）

1. **可拖拽分隔条**：`.layout-handle` 已有 `onMouseDown` 占位（空函数）与 `handleStyles` 几何数据（`layout-alg.js`），补上拖拽 + 样式即可；需同时持久化各窗格比例。
2. **L 形（缺角）布局**：支撑 `c2x2` 关一格后的平滑过渡。
3. **窗格最大化/临时隐藏**：双击分隔条把某窗格临时占满（不改变 `tabs.batch`，仅改渲染比例），比"关闭窗格"更轻、更可逆。

## 九、一句话总结

现有分屏是「8 种固定布局 + `tab.batch` 归属」的结构，**空窗格目前会保留并显示 `NoSession` 占位块，且没有任何关闭入口**；由于布局形态有限，"关掉任意一格"需要一次**布局降级 + 窗格紧凑重排**。本方案建议：**在空窗格的占位块上提供「关闭此窗格」按钮（带 Popconfirm 预告目标布局），由新增的 `store.closePane(batchIndex)` 完成重排与降级**，默认不引入自动关闭；"保持形状（L 形布局）"与"可拖拽分隔条"作为后续独立事项。
