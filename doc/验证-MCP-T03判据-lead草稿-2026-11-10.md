## 一、导出与基线（M10 的 T03 部分）

### T03-01 具名导出落地
**通过标准**：`agent.js` 出现 `export function buildAgentSystemPrompt`（零行为变更）；golden spec
运行时**实际走了导出路径**（spec 需加一条自证断言：记录本轮用的是哪条路径，导出存在时必须是
export 路径——否则「导出存在但 spec 仍回落抽取」会掩盖导出签名被改坏的情况）。
**变异**：把导出改回私有 → spec 的路径自证断言红。

### T03-02 M10 硬门（hasExternal=false）
**通过标准**：未配置任何 server 时，run 开始处 `runTools.length === 36`（F1），且 system prompt
与现基线**逐字符相等**（1824 / `19da66c3…`）。注意：若 T03 按 F7 把签名改为
`buildAgentSystemPrompt(config, hasExternal)`，则 `hasExternal=false` 必须逐字节复现现基线。
**变异**：任意往 prompt 追加一个字符 → 红（golden spec 现成）。

### T03-03 hasExternal=true 新基线冻结
**通过标准**：T03 落地同一提交里，冻结「有外部工具」时的 prompt 新基线（长度 + sha256 + 附录
全文），双路径与 T03-01 同规。基线文本必须含 S4 的**不可信边界声明**（设计 `:43`）。
**变异**：删掉边界声明那一段 → 红。

## 二、别名与合并（M5 的 agent 面）

### T03-04 runTools 中的别名契约
**通过标准**：注入 1 个假 server（2 个工具，其一名字含非法字符/超长/重复）后，run 的
`runTools` 里外部项的名称逐条满足 §2.5 规则（`mcp__<7位id>__<清洗名>`、小写、不折叠 `_`、
64 上限走短哈希、同 server 撞名 `_2` 按原始名字典序），且每条违反都产生 warn。
**变异**：把清洗改成「折叠连续 `_`」→ 两个不同工具变同名 → `T03-04` 的去重断言红。

### T03-05 内置优先（M5 核心）
**通过标准**：外部 server 提供 `db_insert_sql`（内置同名）与 `DB_INSERT_SQL`（大小写变体）→
两者都不覆盖内置：内置实现行为不变、外部项被跳过、warn 各一条（含 alias）；`runTools` 里
内置 `db_insert_sql` 的 `function` 定义与无外部时**逐字符相同**。
**变异**：删掉内置优先分支（builtin.has 检查）→ 外部覆盖内置 → 红两条。

### T03-06 run 级冻结
**通过标准**：run 开始时 `runTools` 冻结为「内置 36 + 外部 N」快照；run 进行中保存设置
（syncConfig 增删 server）**不得**改变本次 run 的工具集，也不得让 provider 收到与已发
tool_calls 矛盾的工具列表。测试层：假 client + 手动触发 syncConfig。
**变异**：把 getTools 调用移进循环体 → 第二轮出现新工具 → 红断言「两轮 runTools 相同」。

## 三、上下文与调用路由（M4/M8 的 agent 面）

### T03-07 toolsTokens 随外部工具增长
**通过标准**：`publishContext` 的 `toolsTokens`：无外部 = 基线值；注入 100 个外部工具后
显著增长且与工具描述总字节数单调相关。已有断言粒度可用「增长 > 0 + 上限生效」。
**变异**：合并时漏掉 `openaiTools` 拼接 → 不增长 → 红。

### T03-08 调用路由与零网络校验
**通过标准**：`executeToolCall('mcp__xxx__echo', …)` 走 `mcpClientCallTool`；
`validateArgs` 失败返回 `{error:{code:'invalid_tool_arguments'}}` 且 **tools/call 往返为 0**
（T02 已有此断言，agent 面复用）；8KiB 降级 schema 放行一切入参（M4-④，必须显式钉住）。
**变异**：路由分支漏掉外部别名 → 走内置 case 落空 → 红。

### T03-09 M8 循环不 hang
**通过标准**：外部工具永不返回（`--hang`）→ agent 循环在 `timeoutMs+1s` 内拿到结构化错误
作为 tool 结果继续下一轮；主流程总耗时有上界（与 M8 同口径）；错误文案含 server 名。
**变异**：错误直接 throw 出 executeToolCall → run 崩或 hang → 红。

### T03-10 stale 缓存语义
**通过标准**：60s 内第二次 `mcpClientGetTools()` 不发真实 tools/list（请求计数器不变）；
`force`（Refresh/Restart）绕过缓存。T02 已有 force 断言，agent 面补「run 内多次调用只拉一次」。
**变异**：缓存判断写反 → 计数器增长 → 红。

## 四、边界与上限

### T03-11 不可信边界包装
**通过标准**：外部 tool 结果一律包进 `<untrusted-tool-result server="<name>">…</untrusted-tool-result>`
（包装在 T03，消毒在 T04）；无外部 server 时包装函数**一次都不执行**（M10 第 7 条）；
server `name` 含 `<>` 的在配置校验已被拒（`config-validate.js:148`），包装层不做二次转义
（那是 T04 SEC-1 的事，别提前做一半）。
**变异**：包装函数对内置结果也生效 → 破 M10 → 红。

### T03-12 两层上限各司其职
**通过标准**：假 client 提供 200 个外部工具 → `runTools` 外部部分 **≤ 100**（注册层
`schema-slim.LIMITS`，import 常量）且截断元数据（perServer/global）暴露给 UI；协议层
5 页/200 只体现在 `toolsTruncated`，不影响本断言。**两条上限都 import 常量，禁止字面量**。
**变异**：把 LIMITS.global 从 100 改 20 → 断言跟随常量变红变绿（证明没写死 100）。

### T03-13 历史回放降级
**通过标准**：历史消息里存在引用**已消失别名**的 tool_calls（server 被删/工具被删/改名）
→ 回放时替换为占位 tool 结果（如 `tool no longer available: <alias>`），provider 不收到
未声明的工具名、不 400、agent 不崩。
**变异**：原样透传 → 假 provider 断言「收到未声明工具名」→ 红。
