### 1. T5-1 FTP onData 节流（后端，无 UI，无需草图）

#### 1.1 现状核实
- src/app/server/ftp-transfer.js L41-47：`onData = (total, chunk) => { this.ws?.s({ id: 'transfer:data:' + this.id, data: total }) }`，每次 handleProgress（basic-ftp 每 chunk 回调，高频）都直接发 ws 消息。
- 对照 src/app/server/transfer.js L45-50（SFTP 版）：已有 `_.throttle((data) => {...}, 3000)` 节流先例。
- onEnd / onError 消息不受影响，最终进度不会丢失（throttle 的 trailing 调用保证末值上报）。

#### 1.2 实现设计
- 仅改 src/app/server/ftp-transfer.js：
  - 顶部 `const _ = require('../lib/lodash.js')`（与 transfer.js 同源依赖）。
  - 将 onData 的 ws 上报包为 `_.throttle(..., 3000)`，与 transfer.js L45-50 模式一致；`pausing` 判断保留在 throttle 之前（handleProgress 已有 return）。
- 多 Transfer 实例各自独立 throttle 实例，无共享状态。

#### 1.3 风险与验证
- 风险：极低——纯发送频率收敛，消息协议不变。
- 单测：新增 spec，mock ws（`s` 计数器），短时间高频调 handleProgress 断言 3s 窗口内发送次数 ≤ 2（leading+trailing），等待窗口后断言最终 total 可达。
- 验证：`npx standard` + `npm run test-unit-ci`；真机 FTP 传输观察 devtools ws 消息频率。

### 2. T5-2 状态栏数据管线（三段）

#### 2.0 现状核实
- **展示载体（2026-10-20 用户确认调整）：终端顶栏 session-control.jsx**（.terminal-control，高 var(--session-bar-h)，与 JS termControlHeight 互为镜像——底栏已拥挤：AI/传输/监控/命令历史/批量输入/快速命令带等，不再往底栏加）。
  - 顶栏左区 renderConnInfo：状态点 + host + 状态胶囊 + 类型徽标（注释明确"远端 shell 需数据管线，暂只显示类型"——T5-2a 正好补上这根管线）。
  - 顶栏右区 .term-controls：查找条 / 字号 / 分屏 / keepalive / 广播 / wrap 等 sess-icon 灯态图标组——**显隐开关由公共组件自带，终端页零逻辑**。
- **ssh2 算法来源（已验证 node_modules/@electerm/ssh2 源码）**：Client 在握手完成时 emit `'handshake'` 事件（lib/client.js L366），参数 negotiated 结构为：
  `{ kex, serverHostKey, cs: { cipher, mac, compress, lang }, sc: { cipher, mac, compress, lang } }`（lib/protocol/kex.js L156-171）。事件先于 `ready` 触发，必须在 doSshConnect 的 Promise 块内挂监听（conn 事件挂接点 session-ssh.js L794-880）。
- 上报通道先例：session-ssh.js L667-673 `this.ws?.s({ update, action: 'ssh-tunnel-result', tabId })`，复用同模式新增 action。
- zsh 版本：session-local 起本地 pty shell，可一次 child_process.exec `zsh --version`（超时 1s，失败静默）。
- 显隐开关配置（复用"主进程与渲染层同步定义"教训）：default-setting.js 与渲染层配置同时新增 `sessionBarInfoVisible: true`，偏好持久化 config。

#### 2.1 T5-2a ssh2·算法段
- 后端 session-ssh.js：doSshConnect 内挂 `conn.on('handshake', ...)`，提取 `{ kex, serverHostKey, cs.cipher, sc.cipher }`，`ws.s({ update: {...}, action: 'ssh-handshake-info', tabId: this.initOptions.srcTabId })`。
- 前端：socket 分发处将信息写入 `store.sshAlgoMap[tabId]`（store/common.js 或 init-state.js 初始化）；tab 关闭时清理（挂 tab 移除钩子）。
- 展示：公共组件 session-bar-status.jsx 内部消费 sshAlgoMap（组件契约见 2.6），SSH tab 显示 `ssh2 · curve25519-sha256 · aes256-ctr`；展示串精简（去掉 `@openssh.com` 后缀）在组件内做。
- 风险：中——需真机验证 hop 链/代理场景 handshake 挂接不重复（once 语义，rekey 二次 handshake 以首次为准）。

#### 2.2 T5-2b ↑↓ 速率段（纯前端计数，零 IPC）
- 与审计"主进程 onData 计数+500ms 节流上报 IPC"的差异说明：终端数据最终经 ws 下发至前端 socket，**在前端 socket 层计数等价且零 IPC 开销**，故改用纯前端方案（审计原意是"不可每包 IPC"，本方案直接消除 IPC）。
- 实现：前端 socket onmessage 仅统计终端 data 类型字节数（↓），socket.send 计发送字节数（↑）；500ms 节流窗口计算 KB/s 写 `store.trafficMap[tabId]`，公共组件渲染 `↑ 12.3 KB/s ↓ 456 B/s`。tab 关闭清理；无流量时该段隐藏。
- 实现前需确认：前端 socket 封装类位置与消息 action 格式（本轮未读 socket 封装文件）。
- 风险：低——纯展示层，不触碰数据流本身。

#### 2.3 T5-2c zsh 版本段
- session-local.js：shell 就绪后一次 exec `zsh --version`（超时 1s、失败静默、仅本地终端），`ws.s({ action: 'shell-info', update: { zshVersion }, tabId })`。
- 展示：公共组件消费 shellInfoMap，本地 zsh tab 显示 `zsh 5.9`。
- 风险：低——一次性 exec，不在 PATH 时静默失败不显示。

#### 2.5 页面需求矩阵（一次设计好，确认后分步落地；用户确认 2026-10-20）

逐页面盘点"会话信息三段"的适用性，一次定清边界，避免实施中途返工：

| 页面 / tab 类型 | ssh2·算法段 | zsh 版本段 | ↑↓ 速率段 | 本次落地 | 依据 |
|---|---|---|---|---|---|
| 终端页 · SSH tab | ✔（kex + cipher） | ✘（远端 shell 版本需逐机探测，成本高价值低） | ✔ | ✔ | handshake 管线现成 |
| 终端页 · 本地 tab | ✘（无 ssh） | ✔（本地一次 exec） | ✔ | ✔ | |
| 终端页 · telnet / serial tab | ✘ | ✘ | ✔ | ✔ | 无算法/版本数据源，仅流量 |
| 数据库页（.db-head 独立顶栏，32px 同高；SessionControl 对 db tab 已关闭） | ✘（MySQL/Redis/PG 非 ssh2 协议，无 handshake 数据；走 ssh 隧道时隧道算法≠连接算法，显示反而误导） | ✘ | ✘ 暂不接 | ✘ | db 数据走 dbClientOp 通道，非终端 socket；组件已复用化，未来有需求一行调用 |

- **本次 MVP 范围 = 终端页三类 tab（SSH / local / telnet·serial）**，公共组件 + 公共计数模块的设计保证后续任何页面接入都是"一行调用 + 一条数据管线"，无组件改动。
- 未来扩展路径（不在本次）：数据库页速率（挂 dbClientOp 通道计数）、桌面页速率（挂串流 ws 计数）——各自只需新增计数管线并传组件 prop 开启。

#### 2.6 架构原则：小功能实现一次，其他页面只调用（用户确认 2026-10-20）

各小功能拆分独立、全项目仅一处实现，页面侧零重复：

| 小功能 | 实现一次的位置 | 调用方 |
|---|---|---|
| ssh2 算法上报 | session-ssh.js（后端，action: 'ssh-handshake-info'） | 任意 SSH session 自动生效 |
| zsh 版本探测 | session-local.js（后端，action: 'shell-info'） | 本地 shell 自动生效 |
| ↑↓ 速率计数 | 独立公共模块 src/client/common/session-traffic.js（socket 字节计数 + 500ms 窗口 + store 写入） | socket 封装挂接一次，全部 session 类型生效 |
| 顶栏展示组件 | **src/client/common/session-bar-status.jsx**（与 session-bar-actions.jsx / db-engine-mark.jsx 同目录同模式：内部做类型判断 + 开关消费 + 条件显隐） | 终端页 session-control.jsx 一行调用；数据库页 db-session.jsx 等需要时同样一行调用 |
| 显隐开关 | config.sessionBarInfoVisible 一处定义（default-setting.js + 渲染层同步） | 组件内消费；开关图标在组件内自带（含切换逻辑） |

- 组件契约：`<SessionBarStatus tab={tab} />`，由组件内部决定该 tab 显示哪些段（SSH→算法段、本地 zsh→版本段、有流量→速率段），调用方不传业务逻辑，只传 tab。
- 数据 store（sshAlgoMap / trafficMap / shellInfoMap）写入集中在 traffic 模块与 socket 分发一处，页面不直接写。
- 风险：中——需真机验证 hop 链/代理场景 handshake 挂接不重复（once 语义，rekey 二次 handshake 以首次为准）。

### 4. T5-4 ⌘R 会话录制

#### 4.1 现状核实
- 快捷键层：term-init.js L95 `term.attachCustomKeyEventHandler(this.handleKeyboardEvent)` → shortcut-handler.js `shortcutExtend` 匹配 `conf.shortcut.split(',').includes(r)` 后调用 `this[conf.func + 'Shortcut'](event)`。
- 默认表 shortcuts-defaults.js：条目格式 `{ name: 'type_func', shortcut, shortcutMac }`；**meta+r 当前空闲**（meta+l 是 clear、meta+f 是 search）；`alt+r` 已被 app_reloadCurrentTab 占用。
- 关键边界：handleKeyboardEvent L211-215 在 alternate buffer（TUI/vim）时直接 `return true` 交给 xterm——录制开关在 TUI 下自然失效，属可接受行为（不额外加拦截）。
- 冲突提示：Ctrl+R 是 shell 反向历史搜索（readline），**Win/Linux 默认不绑定**（shortcut 为空字符串），仅 Mac 默认 meta+r（meta 前缀不会传给 shell）。

#### 4.2 实现设计（拆 3 个提交）

**T5-4a 快捷键注册**
- shortcuts-defaults.js 新增 `{ name: 'terminal_toggleSessionRecord', shortcut: '', shortcutMac: 'meta+r' }`。
- terminal mixins 新增 `toggleSessionRecordShortcut(ev)`：`ev.preventDefault()` + `window.store.toggleSessionRecord(this.props.tab.id)`；设置页快捷键列表自动出现（buildConfig 驱动，无需改设置页）。

**T5-4b 录制引擎（纯前端缓冲 + 主进程批量写）**
- 数据源：与 T5-2b 同源——前端 socket 收到的终端输出（渲染层收到即捕获，不碰 xterm 内部）。
- 格式：asciinema v2 JSONL：首行 `{ version: 2, width, height, timestamp }`，行 `{ [sec, nsec], event: 'o', data }`。**默认仅记录输出 'o'，不记录键盘输入 'i'**（隐私边界，草图标注）。
- 缓冲与落盘：内存攒 buffer，500ms 或 256KB 触发 flush，经 `window.pre.runGlobalAsync('appendRecFile', path, content)` 调主进程 ipc.js 注册的 fs.appendFile（幂等 append）。
- 文件路径：默认 `~/Downloads/electerm-rec-YYYYMMDD-HHmmss.cast` 直写（不做另存对话框，避免模态打断；"另存为"留待后续）。开始/停止均 toast 提示路径。
- 生命周期：store `recState = { [tabId]: { path, startTime } }`；tab 关闭自动停录并最终 flush。

**T5-4c REC 指示 UI**
- 终端右上角 absolute 浮层：`● REC 00:12`（红点用现有 danger 色派生 token，动效 var(--dur-2)）；点击=停止。
- footer 不加新按钮（避免底栏再膨胀）；样式不新增布局（浮层不动 flex），遵守 styl 三关守护测试。

#### 4.3 风险与验证
- 风险：中高——高频流缓冲（复用节流经验）；socket 消息格式需实现时确认；长会话内存上限由 256KB flush 阈值兜底。
- 单测：asciinema v2 行格式化与时间戳单调性纯函数（放 common 便于测试）；flush 阈值逻辑；快捷键映射存在性 + 反向验证（Win 默认为空）。
- 验证：真机录制 → asciinema play / cat 校验格式；⌘R 开关、tab 关闭停录、TUI 下不误触。

## 2. T5-4f 会话录制与终端日志统一设计（2026-10-21 · v3）

> 原文档：`T5-4f会话录制重设计-2026-10-21.md`（2026-10-21）

### 0. 背景

T5-4e 文件定位已修好。用户反馈三点：

1. cast 文件满屏转义符，希望输入也能录、内容可配置；
2. 录制与既有「终端日志」重复 → 统一入口；
3. 日志存储目录也要统一，并能在终端日志页「打开日志目录」（文字按钮 / 文档图标）。

本版按拍板方向：**一个入口 = 右侧「终端日志」页；一个目录 = 所有会话日志与录制文件同处**。

### 1. 根因：cast 里为什么全是转义符（固有形态，非 bug）

cast 是 asciinema v2 格式 = 终端字节流的时间戳重放，记录的就是终端协议本身：

| 内容 | 例子 | 来源 |
|---|---|---|
| 颜色/光标序列 | `\u001b[32m` `\u001b[2J` | 终端输出固有 |
| shell integration | `\u001b]633;E;...\u0007` | electerm 注入的 OSC 633（噪声最大头） |
| 逐 chunk 碎片 | `[2.294,"o","h"]` | 输出按到达分片，一行被拆多条 |

asciinema 官方录出来同样如此——不是给人直读的，是给播放器渲染的。可读归档由纯文本日志承担。

### 2. 同类软件参照

| 软件 | 产物 | 输入录制 | 可读性 |
|---|---|---|---|
| asciinema | .cast 重放 | `--stdin` 可选（i 事件） | 播放器渲染，源文件含转义 |
| script (util-linux) | typescript 纯文本 | 默认录输入+输出 | 含转义，`col -bp` 清理后可读 |
| TermRecord | 自包含 HTML | 否 | 渲染后 HTML，无可读源文件 |

### 3. 现状盘点：两套录制 + 两个目录

| 维度 | 既有 term-log（上游） | T5-4 cast 录制 |
|---|---|---|
| 入口 | 右键 `onRecord/onStopRecord`；右侧「终端日志」页 `saveTerminalLogToFile` 开关 | 顶栏按钮 + `⌘R` |
| 文案 | `e('record')` / `e('stopRecord')` | **同一组 key** |
| 产物 | `.log` 纯文本（headless xterm 逐行渲染） | `.cast` asciinema v2 字节流 |
| **目录** | `config.sessionLogPath`，空则 `appData/electerm/session_logs` | **`app.getPath('downloads')`** |
| 时间戳 | 可选行首 `[HH:MM:SS]` | 每事件相对秒 |
| 转义 | 天然没有 | 原始字节流 |
| 可回放 | 否 | 是 |
| 实现层 | 主进程 `SessionLog`（`session-base.js:119`） | 渲染层 `SessionRecorder` + 主进程 `ipc.js:238` |

结论：

- UI 同名不同物 → 统一到「终端日志」页；
- 目录分居 Downloads / 配置目录 → 统一到一个目录；
- 上一版的「新增纯文本 log + ansi-filter」= 重造 term-log，**已删除**。

### 5. 边界与风险

- **目录变更**：cast 从 Downloads 迁到配置目录，属行为变更；需在变更说明注明旧文件不迁移。
- `openSessionLogDir` 用 `shell.openPath`（Linux 走 xdg-open），失败仅日志不弹错。
- 页面靠 `refs.get('term-' + pid)` 读状态 + 100ms 轮询兜底；cast 状态直接读 store，不叠加轮询。
- 顶栏录制控制仅在有终端实例的页渲染（`inTerminalTab && hasShellSession`）。
- 右键 `onRecord` 改为打开面板会改变既有交互（原本直接弹保存框）；文本日志区仍提供开关，能力不丢。
- 两条链路同时开时停录通知重名（都叫 `stopRecord`），需合并为一条。
- OSC 剥离默认开，调试 shell integration 时需临时关。
- 兼容：`recordInput=false` 默认，cast 事件格式向后兼容。
